# 开发接手与变更规范

本文档是本项目的开发总入口，面向首次接手的开发者和 AI。它解决两个问题：

1. 在没有历史对话的情况下，快速建立对当前架构、运行模式和安全边界的正确认识。
2. 修改需求时识别完整影响面，避免只改页面、只改接口或只覆盖一种运行方式。

具体业务规则仍以对应的功能文档和代码为准；若代码、测试与文档不一致，不能自行选择
最方便的一项作为事实，应先核实行为并在同一变更中消除不一致。

本文记录的是“当前架构下容易遗漏的影响面”，不是禁止架构演进的永久模板。若更好的
设计改变了模块边界、联动方式或验证手段，应在实现中完成迁移，并同步更新本文；检查
清单用于促使开发者做出明确判断，不要求没有依据地修改每一个列出的文件。

## 1. 接手阅读顺序

按以下顺序阅读，不要直接从某个页面组件开始：

1. 根目录 `README.md` 与[文档中心](../README.md)：产品能力、运行方式和文档导航。
2. 本文档：架构边界、影响面矩阵和完成定义。
3. [架构设计](架构设计.md)：核心客户端、模块关系和数据流。
4. [功能实现与变更索引](功能实现与变更索引.md)：目标功能的实现入口、特殊情况、影响面和验证入口。
5. 与任务有关的 `docs/功能/*.md`：只核对用户可见行为、操作边界和当前说明。
6. 涉及界面时，同时阅读[前端开发](前端开发.md)和
   [前端设计规范](前端设计规范.md)；新增或重排页面还要核对
   [移动端能力矩阵](移动端能力矩阵.md)。
7. 涉及存储、认证或发行时，分别阅读[数据存储](数据存储.md)、
   [缓存与数据一致性](缓存与数据一致性.md)、
   [WebVPN 校外访问](../功能/WebVPN校外访问.md)和
   [发行与 CI/CD](发行与CI.md)。
8. 最后阅读目标代码、相邻实现和测试；文档不能代替代码核查。

## 2. 当前系统边界

### 2.1 运行模式

| 模式 | 入口 | 数据目录 | 网络与退出 |
|---|---|---|---|
| `development` | `start_all.py` / Uvicorn | 仓库 `data/` | 默认本机；允许本地开发 CORS |
| `desktop` | `launchers/desktop.py` | `%LOCALAPPDATA%\NEU-JWXT-Toolkit\data` | 仅本机；单实例；托盘恢复页面；支持“退出程序” |
| `server` | `launchers/server.py` + systemd | `/var/lib/neu-jwxt-toolkit` | 仅监听回环地址；由 Caddy/Nginx 反代；无远程关机按钮 |
| `mobile` | Android 本地版 + `launchers/mobile.py` | Android 应用内部目录 | 随机回环端口；所有 API 强制本次进程令牌；原生通知 |

`NEU_JWXT_DATA_DIR` 始终优先。生产模式前后端同源，不能为了调试重新开放任意 CORS。
`desktop` 专属关机接口不得出现在其他模式的可用交互中。`mobile` 不提供 SMTP 和远程恢复链接；
Android 客户端壳不是运行 profile，它连接正常的 `server` 模式。

### 2.2 请求和数据链路

```text
React 页面
  → frontend/src/services/api.js
  → backend/app/routers（HTTP、鉴权、请求响应边界）
  → backend/app/schemas（Pydantic 数据契约）
  → backend/core（教务请求、解析、业务规则）
  → backend/core/cache（可重建资源、revision、后台协调）
  → backend/core/storage（用户状态、文档、会话、配置及旧格式迁移）
  → 教务系统 / WebVPN
```

共享对象在 `backend/app/dependencies.py` 的 `ApplicationServices` 集中组装并统一
启动/关闭。Router 通过公开依赖 getter 获取服务，不导入下划线全局对象；新增共享状态
时不得临时创建另一套认证客户端、存储、缓存协调器或追踪器。

### 2.3 认证是同一个业务会话

- 校内直连和 WebVPN 是 `NEUAuthClient` 的不同访问方式，不是两套业务实现。
- 二维码、账号密码、短信二次认证和 Cookie 恢复必须延续正确的 `requests.Session`。
- 外部请求必须通过认证客户端的 `get/post/request`，以保留 URL 转换、Cookie、
  超时和登录恢复行为。
- 不得把真实学号、密码、Cookie、恢复令牌或二维码内容写入日志、异常详情和测试夹具。
- JWXK 与 CXCY 的服务线路独立配置，默认跟随教务；创院列表、后台缓存抓取和证书包必须
  通过同一个固定线路的服务客户端。服务级认证错误不得触发全局退出，代理链接先按登记
  源站规范化再做路径白名单校验。前台定向恢复复用 `ServiceConnection`，不要复制登录状态机。

### 2.4 两层访问保护

Linux `server` 模式先验证网站访问密码，再进入 NEU 登录。网站密码使用 scrypt
加盐哈希；成功后使用 HMAC 签名的 `HttpOnly` Cookie。除健康检查、访问登录接口和
经过设计的 `/api/auth-recovery/<签名令牌>/...` 一次性恢复接口外，所有 `/api` 都必须经过访问网关。

新增所谓“公开接口”必须先完成威胁分析，不能只为修复 401 就加入公开路径。离线 API
也包含个人数据，在服务器模式下必须受网站密码保护。

### 2.5 缓存是共享基础设施

- `cache.db` 是可重建缓存唯一真相源；旧 CSV/JSON 仅在兼容周期内惰性导入，不再双写。
- 成绩页、GPA 和成绩追踪共享 `scores` revision；培养计划记录其依赖 revision。
- 科研目录是可重建缓存，收藏是用户权威状态；两者生命周期不能混用。
- 页面、追踪、登录预热和手动刷新复用同一 coordinator job，禁止各自实现 freshness、
  mtime、后台线程或文件缓存。
- 所有远端调用共享 `AuthSessionManager` 的身份边界；认证、退出、写操作和会创建/刷新子会话
  的服务操作使用独占互斥，已确认身份的纯只读请求可使用有界并发槽和隔离 Session 快照。
  缓存读取不触发远端认证。
- 离线模式只读 Registry 明确允许的资源，不创建 job、不恢复认证、不执行写操作。

新增或修改数据源前必须阅读[缓存与数据一致性](缓存与数据一致性.md)并回答其中的资源
登记九问。

## 3. 修改前的需求影响分析

开始编码前，用下面的问题形成一份简短的内部检查清单。任何一项“不涉及”都应当是
核查后的结论，而不是因为没有看到相关文件。

- 用户的核心任务是什么？桌面端和手机端的目标是否不同？
- 数据来自哪个教务接口？直连和 WebVPN 是否都经过统一客户端？
- 2024 级及以前、2025 级及以后是否存在字段名或规则差异？
- 这是展示规则、业务规则、缓存规则还是远端写操作？
- 后端核心、Schema、Router、依赖组装、前端 API、页面、路由、导航分别是否涉及？
- 首次无数据、缓存数据、远端成功、远端失败、登录过期分别显示什么？
- 离线模式应当开放、只读开放还是隐藏？
- 成绩、培养计划、GPA 模拟和成绩追踪之间是否需要同步？
- `development / desktop / server` 是否行为一致？是否存在模式专属能力？
- Linux 网站密码、可信反代、Cookie、限流、日志脱敏是否受影响？
- 320px 手机、触屏点击、键盘操作和桌面悬停是否都有可用入口？
- 需要哪些单元测试、集成测试、浏览器验收和文档更新？
- 是否影响冻结程序、安装脚本、反代示例、版本或 GitHub Actions？

### 3.1 先确认功能说明书与开发索引中的四类事实

开始修改前，目标功能说明书和功能实现索引应共同回答以下四个问题。说明书记录当前产品行为，
实现索引记录开发接手所需的实现事实；
不是聊天过程或个人工作记录：

1. **当前实现链路**：页面入口、前端服务、router/schema、core、缓存/任务和外部接口分别在哪里；
2. **当前行为与容易遗漏的特殊情况**：用户已经依赖的交互、数据边界、判定优先级、失败和空数据语义，
   以及容易在局部修复时被忽略的例外；
3. **修改影响面**：本层变化会联动哪些页面、运行模式、缓存、认证、通知和移动端能力；
4. **更新与验证入口**：需要同步哪些文档，应该运行哪些测试和页面检查。

如果功能实现索引缺少其中一项，不要凭文件名猜影响范围。先对照代码和测试补足当前事实，
再继续实现需求。新增或修正行为时，把实现事实写回开发索引；用户可见变化再同步到功能说明书。

### 4.1 按层判断的补充规则

影响矩阵用于决定“至少检查什么”，不是只改一个文件的许可。具体判断按以下顺序进行：

1. 先确认用户可见入口和最终数据集；
2. 再沿请求链检查数据契约和业务判定；
3. 最后检查共享状态、缓存、认证、后台任务、通知、离线和移动端边界。

常见联动如下：

| 起点 | 必须继续检查 |
|---|---|
| GPA/成绩筛选或统计 | 成绩页、GPA 模拟、绩点策略、待输入/隐藏、追踪快照与通知、桌面表格和移动卡片 |
| 课表筛选或布局 | 个人/班级/教师/教室四种模式、共享时间模型、冲突检测、首屏缓存、手机布局和课表文档 |
| 选课记录或状态判定 | 目录、已选结果、手动写操作、自动任务、归档、通知和 JWXK 模式语义 |
| 登录、Cookie 或恢复 | `NEUAuthClient`、`AuthSessionManager`、所有业务调用方、WebVPN/验证码流程、离线降级和认证测试 |
| 缓存或后台刷新 | CacheRegistry、revision、失效、账号切换、离线读、页面旧数据保留和后台去重 |
| 共享按钮或响应式布局 | 所有使用该模式的页面、加载/禁用/错误状态、320px/375px/430px/768px 验收和移动端矩阵 |

## 5. 完整功能的实现顺序

### 5.1 新增教务功能

1. 获取最小必要的请求和响应样例，删除学号、姓名、Cookie、手机号和令牌。
2. 在 `backend/core` 实现 URL、请求和解析；保留未知字段的兼容策略，不能只适配一个
   账号的非空响应。
3. 定义内部模型和错误语义，区分“无资格/无数据”和“接口失败/解析失败”。
4. 在 `backend/app/schemas` 定义稳定的 HTTP 契约。
5. 在 router 中做鉴权、输入校验和响应映射，在 `backend/app/main.py` 注册。
6. 在 `frontend/src/services/api.js` 增加唯一前端调用入口。
7. 添加页面、路由和导航；若是写操作，加入状态预检、二次确认和提交后刷新。
8. 决定缓存、离线、追踪和其他功能的联动，不能默认互不相关。
9. 为核心解析、路由保护和关键异常增加测试。
10. 更新 README 功能列表和独立功能文档。

### 5.2 修改展示或筛选

展示层修复也要检查数据契约。筛选后的统计必须使用与当前可见结果相同的数据集；没有
筛选时不能用视觉标记暗示筛选已生效。Ant Design 的 `selectedKeys` 是“过滤值数组”，
复合范围应编码成一个稳定值，不能把 `[min, max]` 当成两个独立过滤值。

移动端不以“桌面表格能横向滚动”为完成标准。要先确定首屏答案，再决定使用卡片、
摘要列表、抽屉或详情页。手机端默认内容可以更聚焦，但合法能力必须与桌面等价；不能
把管理、配置、导入导出或写操作仅留在电脑端。

### 5.3 修改缓存或后台任务

可重建资源必须登记到 CacheRegistry 并复用 CacheStore/CacheCoordinator；分类、Schema、
revision、canonicalization、时效、离线、依赖、写后失效、账号切换、迁移和发行排除
必须一次说明完整。用户文档、权威状态、可靠队列、安全状态和日志不得注册为缓存。

调用同步 HTTP 客户端、读写较大文件或执行耗时解析的 FastAPI 路由不得写成直接阻塞
事件循环的 `async def`；使用普通 `def` 交给线程池，或显式在线程池执行。当前单账号
运行时共享一个认证身份和主 Session。认证恢复、退出、远端写操作及会创建/刷新子会话的
服务操作必须通过 `AuthSessionManager` 独占边界；已确认身份的纯只读请求可以进入有界并发
读取窗口，并使用隔离的 Session 快照，不能直接并发操作主 Cookie Jar。本地缓存接口不经过
该锁，也不得触发远端会话检查。后台刷新还必须短时
去重，避免路由切换或多个标签页把同一刷新排队执行多次。

所有远端写操作必须在 `MUTATION_POLICIES` 声明 `automatic_retry=False` 和成功后的
invalidations。路由只能在官方成功码确认后执行失效；失败、超时或业务拒绝不能改动
本地缓存，也不能由后台任务重放。

## 6. 安全基线

- API 输入通过 Pydantic 或等价白名单校验；限制密码、Cookie、文本和列表大小。
- 不使用用户输入拼接 Shell、路径、Python 表达式、SQL 或 HTML。
- SPA fallback 只能返回固定 `index.html`；静态文件使用框架 containment 或明确白名单，
  解析后的路径必须仍位于构建目录内。编码点段、反斜杠和符号链接逃逸必须有回归测试。
- 外部 URL 必须是代码定义的受控端点；重定向、恢复链接和代理头按可信边界处理。
- Cookie 至少使用 `HttpOnly` 和 `SameSite=Lax`；可信 HTTPS 反代下使用 `Secure`。
- 访问密码只保存盐和哈希，Cookie 签名密钥至少 32 字节，不返回到前端。
- 认证失败限流必须使用不可由客户端任意伪造的来源；只信任配置中的反向代理。
- 日志不得出现密码、Cookie、SMTP 授权码、二维码/恢复令牌或完整敏感 URL。
- 服务端个人数据接口，包括离线接口，不能加入公开 API 列表。
- Windows 仅监听本机；Linux 默认也只监听回环地址，由用户配置 HTTPS 反代。
- 写操作默认应比读操作更保守：资格校验、明确按钮文案、防重复提交和确认反馈齐全。

## 7. 分层验证与执行顺序

测试用例和完整门禁不减少，但不要在每次微调后重复“专项 → 全量 → 构建 → 全量”。
按风险分层验证：

- 迭代中：前端使用 `npm run test:changed`；后端运行受影响的测试文件和必要的关联测试。
  定位到明确文件时可用 `npm run test:related -- src/pages/TimetablePage.js`。
- 仅 Markdown 文档修改：核对链接和文档与代码的一致性，无需重跑应用测试和生产构建。
- 最终交付：页面局部变更做相关测试、必要的浏览器验收和一次生产构建/预算检查；
  认证、缓存、共享组件、API、存储、任务、依赖或发行变更执行完整关联回归。
  无法确定影响范围时使用全量，不以增量结果代替全量通过的声明。
- 同一轮工作中，已通过且其输入、依赖及环境未再变化的验证不重复执行；后续修改影响了
  哪一层，就重跑该层。不要为省时间复用来源不明或旧源码生成的构建。
- CI 始终运行全量门禁；增量入口只用于本地迭代，不替换 CI。

完整门禁顺序如下（Windows 使用项目 `.venv/Scripts/python.exe`）：

```bash
# 后端业务测试
python -m pytest backend/tests

# 导入和语法检查
python -m compileall -q backend launchers

# 前端；依赖或锁文件变更、干净环境使用 npm ci
```

## 8. 文档同步规则

| 修改内容 | 同步文档 |
|---|---|
| 用户可见能力或入口 | `README.md` + `docs/功能/对应功能.md`；功能文档只补充用户操作和边界 |
| API、字段、业务规则 | 对应功能文档；功能实现与变更索引；必要时架构设计 |
| 页面模式、组件或移动策略 | 前端开发 + 前端设计规范 |
| 数据文件、刷新或权限 | 数据存储 + 缓存与数据一致性 |
| 登录、WebVPN、恢复流程 | WebVPN 校外访问 |
| 运行模式、安装、反代 | 快速开始 + 对应部署文档 |
| CI、发行物、版本流程 | 发行与 CI/CD |

功能实现索引应保持以下几类当前信息；功能说明书不需要复制这些章节：

- 当前实现链路：列出关键入口和唯一事实来源；
- 当前行为与容易遗漏的特殊情况：列出边界、优先级、失败/空数据、重复操作语义和容易被忽略的例外；
- 修改影响面：列出需要继续检查的关联能力；
- 更新与验证入口：列出需要同步的文档、测试文件和页面验收。

### 8.1 功能实现索引的推荐结构

新增或大幅修改功能实现索引时，按以下顺序组织内容；用户功能说明书不使用这一结构：

```text
# 功能名称（开发说明）

功能简介（用户目标与边界）

## 当前实现链路
页面入口、前端服务、schema/router、core、缓存/任务、外部接口和共享模块

## 当前行为与容易遗漏的特殊情况
当前交互、数据来源、判定优先级、失败/空数据、重复操作、离线边界和容易被忽略的例外

## 修改影响面
修改本功能各层时必须继续检查的页面、服务、运行模式和关联功能

## 更新与验证入口
应同步的文档、自动测试、浏览器验收和移动端检查

## 相关用户说明
链接到 `docs/功能/` 下的用户说明书
```

“当前实现链路”写关键入口和唯一事实来源，不罗列每个普通文件；“当前行为与容易遗漏的特殊情况”
写会影响用户结果或后续修改判断的行为、边界和例外，不写聊天记录；“修改影响面”写跨层联动；“更新与验证入口”
写下一次修改可以直接使用的路径和测试入口。若某一节不适用，应明确写“不涉及及原因”，不要留下空标题。

功能实现索引不记录聊天过程、个人工作记录或未实现愿望，但应写明当前实现事实和容易遗漏的特殊处理。
这些内容是修改时的核对依据，不是不可修改的永久规则；需求、接口或设计变化时，应同步调整代码、
测试、功能说明和影响面。
文档中的示例必须能对应当前代码，尤其不能保留已知会崩溃的旧实现。引用文件时使用仓库
相对路径；涉及真实教务响应时只写匿名化字段和规则，不粘贴个人完整响应。

## 10. 已知例外与技术债

以下是当前代码中的历史例外，不应作为新代码范例：

- `backend/app/dependencies.py` 为兼容既有测试和逐步迁移仍保留部分下划线全局别名；
  新代码必须使用 `ApplicationServices` 或公开 getter，迁移过的 Router 不得重新引用
  私有别名。
- 部分早期功能文档包含概念性响应样例。修改解析器前必须对照当前 dataclass、
  Pydantic 模型和匿名化响应，不能仅按文档示例猜字段。
- 全局认证客户端和缓存按“单 NEU 账号、本人多设备”设计，不支持多租户。不得在没有
  隔离认证、存储和后台任务的情况下增加多用户入口。
- 测试以匿名化夹具和模拟响应为主，不代表真实教务端到端验证。涉及学校接口变化时，
  交付说明必须明确真实账号验证是否完成。

发现新的文档与代码偏差时，应在本节记录并尽量在同一变更中修复，不能静默绕过。
