# 前端开发规范

本文档规范前端页面的数据、交互与状态实现。开始修改前还必须阅读
[开发接手与变更规范](开发接手与变更规范.md)；视觉令牌、布局、响应式与可访问性要求
见[前端设计规范](前端设计规范.md)。三份规范应同时遵循。

## 1. 先选择页面模式

不能把所有功能机械套成桌面表格。根据移动端核心任务选择：

| 数据与任务 | 桌面端 | 手机端 |
|---|---|---|
| 多字段比较、排序、筛选 | 表格 | 摘要卡片 + 快捷视图 + 完整筛选/详情 |
| 层级和完成进度 | 树/分组列表 | 核心摘要 + 类别抽屉 + 任务列表 |
| 少量配置 | 分区表单 | 单列分区表单 |
| 单条记录操作 | 表格操作列/详情 | 卡片主操作或底部操作区 |

参考实现不是单一页面：

- 成绩筛选、列设置和筛选后统计：`frontend/src/pages/ScoresPage.js`
- 培养计划层级、搜索和移动视图：`frontend/src/pages/AcademicReportPage.js`
- 配置开关与保存：`frontend/src/pages/GradeTrackingPage.js`
- 写操作、资格状态与确认：`frontend/src/pages/ResearchTrainingPage.js`
- 移动端条目和详情：`frontend/src/pages/EvaluationPage.js`
- 共享移动筛选、详情和操作栏：`frontend/src/components/mobile/MobileUX.js`
- 可扩展工具总览与嵌套工作区：“导出下载”及其四节活动子功能

手机端和桌面端必须复用同一份数据、筛选状态、业务校验和操作函数。允许默认视图和
组件结构不同，不允许复制一套移动业务逻辑，也不允许用 `display: none` 隐藏能力来
完成响应式适配。各页面的入口对照与验收要求见
[移动端能力矩阵](移动端能力矩阵.md)。

## 2. 数据状态

数据页至少区分：

- 初次加载；
- 已加载但为空；
- 本地缓存；
- 远端最新数据；
- 刷新中（保留旧数据，避免整页闪白）；
- 登录失效；
- 请求/解析失败；
- 离线只读；
- 提交中和提交结果。

`allData` 表示完整源数据，`displayData` 表示当前筛选/快捷视图后的结果。统计、分页和空
状态必须明确使用哪一份数据；筛选后的统计通常应基于 `displayData`。

组件卸载时取消仍在进行的可取消请求。刷新和提交期间禁用重复操作，但不要清空已有
结果。离线模式必须调用离线 API，刷新按钮应禁用并明确写“只读离线数据”。

## 3. 表格、筛选和排序

一般数据表只为有用户价值的列提供筛选或排序。课程数据的四个核心表格——成绩、培养
计划、GPA 模拟、GPA 模拟的培养计划导入——采用更严格的一致契约：除选择框和操作列
外，每个业务数据列都同时提供排序和筛选。文本枚举可使用 Ant Design `filters`；自由
文本使用搜索输入；数值使用范围筛选，布尔和状态字段使用完整枚举。

学期必须按学校的学年语义比较，不能直接比较显示字符串：`-1`/秋季是一个学年的第一
学期，`-2`/春季是第二学期。默认显示从新到旧，例如
`2025-2026春季 > 2025-2026秋季 > 2024-2025春季 > 2024-2025秋季`；同一学年的自然
时间升序则为秋季在春季之前。页面数据源使用新到旧比较器提供隐式基础顺序，初次进入
时不得设置 `defaultSortOrder` 或显示排序箭头；只有用户主动操作表头后才进入显式排序。
表格 sorter 使用自然时间比较器，筛选选项直接使用新到旧比较器。统一复用
`frontend/src/utils/termSort.js`，
禁止页面自行按字符串、接口返回顺序或反复乘 `-1` 推断方向。无法识别或未安排的学期
排在默认列表末尾。

### 3.1 数值范围的数据契约

Ant Design 将 `selectedKeys` 的每个元素当作一个独立过滤值。范围必须编码成一个值，
不能使用 `[min, max]`，否则 `onFilter` 会分别收到数字并可能产生
`TypeError: value is not iterable`。

```javascript
const encodeRange = ({ min, max }) =>
  JSON.stringify({ min: min ?? null, max: max ?? null });

const decodeRange = (value) => {
  try {
    return JSON.parse(value || '{}');
  } catch {
    return {};
  }
};

// selectedKeys 永远是空数组或只含一个编码范围的数组
setSelectedKeys(hasAnyBoundary ? [encodeRange({ min, max })] : []);

column.onFilter = (filterValue, record) => {
  const { min, max } = decodeRange(filterValue);
  const value = Number(record.credit);
  if (!Number.isFinite(value)) return false;
  if (min !== null && min !== undefined && value < Number(min)) return false;
  if (max !== null && max !== undefined && value > Number(max)) return false;
  return true;
};
```

范围的应用、只填最小值、只填最大值、两者都填、重置和多个筛选组合都必须测试。

### 3.2 筛选状态与派生统计

筛选状态应来自表格回调中的 `filters`，不能用 `displayData.length !== allData.length`
推断，因为合法筛选可能仍命中全部记录。筛选清除时必须同步清理与筛选相关的提示、
下划线、徽标和固定浮层。

成绩平均绩点直接使用当前结果中每门课程的系统绩点：

```text
Σ(课程绩点 × 课程学分) / Σ课程学分
```

不要把绩点转换为百分制成绩后再平均。零学分和无有效绩点课程不进入分母，界面应说明
当前筛选口径。

## 4. 列设置与本地偏好

- 只有字段较多的桌面表格需要列设置；手机任务卡片不照搬列设置。
- 使用 `frontend/src/utils/settings.js`，每个页面使用独立且稳定的 key。
- 加载旧配置时与新默认列合并，新增列不能因旧 localStorage 永久消失。
- “恢复默认”必须同时更新 React 状态和 localStorage。
- 不在 localStorage 存储密码、Cookie、恢复令牌或个人业务数据。

## 5. 刷新、写操作与反馈

- 刷新按钮区分“本地数据”“已是最新”“刷新中”和“只读离线数据”。
- 刷新失败保留旧数据，并给出可操作的错误信息。
- 写操作提交前校验资格与必要字段；提交中禁用重复点击；成功后刷新相关状态。
- 危险或不可逆操作二次确认。自动评教的安全模式等业务保护不能因 UI 重构绕过。
- 不用空白页面表示加载或错误，不在成功前乐观显示远端写入已完成。

本地优先页面应同时保留“当前显示版本”和“后台同步版本”。后台同步写入新缓存后，不
应直接替换用户正在筛选或阅读的列表；先根据 revision 提示刷新，用户确认后再应用。
同一 revision 在一次页面会话中被选择“稍后”后不得重复弹窗。远端同步失败继续显示
旧缓存，并以非阻断状态说明数据尚未核验。

只要显示更新确认弹窗，就必须同时展示用户可理解的变化摘要。摘要优先直接比较
`resource.data` 与 `resource.availableData`，从而覆盖后台 job、跨页 revision event 等
所有更新来源；不能只依赖当前请求的临时 job diff。成绩摘要包含新增、移除、修改课程和
总 GPA，培养计划摘要包含学分汇总、课程状态与类别结构，科研训练摘要包含批次、课题、
资格和确认状态。首次加载、离页后的直接采用等真正静默更新不弹摘要。

成绩、培养计划和科研训练进入页面时必须先调用各自的账号隔离缓存接口；缓存命中不得
等待教务会话健康检查。只有当前账号无缓存时，首屏才允许等待远端获取。后台检查需要
短时间去重或复用正在进行的请求，组件卸载时清理尚未开始的定时任务。不要在一次刷新
流程中重复拉取同一份成绩，也不要并发调用共享认证 Session。

成绩分项是明确的单科按需资源，不随页面或总表刷新全量加载。桌面和手机都以成绩数字为
入口：先读取该课程缓存并立即打开详情抽屉，在线时再提交同课程 single-flight job；离线
只读缓存。动态分项不得硬编码为平时/期中/期末，快速切换课程时必须用请求代次防止旧响应
覆盖当前抽屉。

“导出下载”使用模块注册表生成总览卡片和子功能导航。注册项包含稳定 ID、标题、简介、
图标、路由、离线能力和可用状态；新增导出工具不应再复制总览布局或增加顶级侧栏菜单。
四节活动每次进入先显示中文时间选择卡，默认当前学年 8 月 31 日至次年 8 月 30 日，再
按模式加载，日期输入固定为 `YYYY-MM-DD`。学年下拉可以预生成当前起始年前 4 年至后 1 年
的历史快捷项，但默认值只能由当天日期计算，不能因快捷项较早而改变。自动模式使用
ResourceProvider 的 cache-first/SWR、更新提示和手动 refresh；首次无缓存时必须保持加载态
直到 refresh 返回可显示结果或明确失败，不能把 `available: false` 的 cache-only 响应当作
空数据结束 loading。首次尚无可显示数据时，固定加载动画应先于筛选和统计出现在当前
视口；暂不渲染会把动画挤到首屏以下的工作区控件。已有缓存的后台更新则继续显示旧数据，
不使用全页加载态遮盖。
按需模式直接调用远端 API，只保存在组件内存，并用请求代次/取消机制防止旧响应覆盖新
结果或写入缓存。用户确认按需模式时，应先调用后端精确删除当前账号四节活动缓存；删除
成功后才保存模式偏好并开始直连读取。删除失败时保留自动模式、显示可重试错误，不得
静默继续或仅隐藏 ResourceProvider 数据。模式偏好使用统一 settings 工具保存，但不保存
活动数据。列表的“日期范围内、全部、时间未知、有证书、有奖”是并列快捷视图：后四者跨
全部记录筛选，而统计和证书打包始终由日期范围驱动；“有证书”按明确证书入口判断，“有奖”
按获奖字段包含“奖”判断。证书打包始终由后端重新抓取，不提交页面列表或证书 URL。离线仅在存在
兼容活动缓存时允许只读进入，且禁用后台更新、按需模式和证书打包。

四节活动在小于 768px 时不直接堆叠桌面筛选卡。默认工作区只保留等宽的移动筛选入口、
证书打包入口和可换行的当前筛选摘要；学年、日期、分区、搜索和完整五项查看范围统一放入
复用的底部 `MobileFilterDrawer`，修改先写草稿，点击“应用”后一次提交，“重置”恢复当前
学年、默认日期、全部分区、空搜索和“日期范围内”。抽屉正文独立滚动，底部操作保持可见。
桌面端继续使用原完整筛选卡，不因移动分支减少入口或改变筛选语义。

## 6. 响应式与交互

- 以 320px 为最小支持宽度；手机核心信息不得依赖横向滚动或悬停。
- 手机端与桌面端保持业务能力等价；低频字段和操作必须在详情、筛选或“更多操作”中
  两次操作内可达。“请到电脑端管理”不是可接受的移动适配。
- 同级的 2-3 个移动按钮应使用稳定的等宽网格或主次比例；操作更多时按用户任务合并为
  有名称的菜单，不能依赖 `flex-wrap` 随机换行。
- 折叠必须有明确的信息层级理由。短资格条件、关键统计和当前状态应直接显示为紧凑
  摘要，不得为了看起来“省空间”增加一次无意义点击。
- 工具栏在手机端保留当前任务的主操作，其他合法操作放入统一面板；桌面和手机共享
  筛选、排序、分页及提交状态。
- 长表单或写操作使用接近全屏的抽屉/弹窗，正文独立滚动，标题、关闭入口和提交按钮
  保持可见；底部操作栏适配 `safe-area-inset-bottom` 和动态视口。
- 短筛选和少量选项不得套用接近全屏的固定高度。复用 `MobileFilterDrawer`，由内容决定
  实际高度，并以动态可见视口为最大值；内容溢出时仅滚动正文。带输入框的弹层需要响应
  `visualViewport` 变化并在键盘弹出后保持聚焦字段与底部操作可达。
- 桌面横向列表改成手机纵向条目时，要显式复核子项的 `flex`、`height`、`min-height`
  和外边距。桌面端的 `flex: 1` 不能直接保留在纵向可滚动容器中，否则会产生异常长条目。
- 桌面 Tooltip 中的必要信息必须有点击/聚焦入口。
- 快捷视图或筛选改变时重置分页；空结果说明当前条件，而不是显示通用错误。
- 课程名、教师名、资格说明等长文本使用换行和弹性布局，不能把按钮挤出卡片。
- 浮动控件不得遮挡主操作、列表状态或手机安全区。
- 具体视口和无障碍验收清单见[前端设计规范](前端设计规范.md)。

## 7. 新增或修改页面检查清单

- [ ] 已在 `frontend/src/services/api.js` 复用或增加统一 API 调用，没有在组件中散落 URL。
- [ ] 路由、导航、页面标题和离线可用性已经同步。
- [ ] 加载、空、缓存、刷新、错误、禁用和提交状态完整。
- [ ] 派生统计明确基于完整数据还是当前筛选数据。
- [ ] 筛选应用、组合、清空与分页复位均正常。
- [ ] 桌面表格和手机任务视图分别按用户目的设计。
- [ ] 已按[移动端能力矩阵](移动端能力矩阵.md)核对桌面能力到手机入口，没有桌面专属
      的合法筛选、详情、导入、导出、保存或写操作。
- [ ] 320px、375px、430px、768px 和桌面宽度没有横向溢出或操作遮挡。
- [ ] 短筛选弹层按内容收起，长列表弹层受视口约束且正文可滚动；虚拟键盘弹出后提交区
      仍保持可见。
- [ ] 2-3 个同级按钮没有孤立换行；4 个以上操作已经按任务分组，且两次操作内可达。
- [ ] 触屏、鼠标和键盘都有可用入口，不依赖颜色表达唯一状态。
- [ ] 生产构建通过，关键流程已做浏览器验收。
- [ ] 按[开发接手与变更规范](开发接手与变更规范.md)检查后端、缓存、认证和文档联动。

# 前端设置存储

## 概述

前端设置存储工具位于 `frontend/src/utils/settings.js`，用于将用户界面偏好设置保存到浏览器的 `localStorage`，实现设置的持久化。

## 功能特性

- ✅ **自动保存** - 设置变更后自动保存到本地
- ✅ **自动恢复** - 页面启动时自动加载上次设置
- ✅ **智能合并** - 新版本增加列时，保留用户偏好同时显示新列
- ✅ **一键重置** - 提供恢复默认设置功能
- ✅ **通用接口** - 统一的 API 方便添加新的设置项

## 使用方法

### 1. 导入设置工具

```javascript
import { columnSettings, saveSetting, loadSetting } from '../utils/settings';
```

### 2. 列设置（已实现）

成绩页面的列显示设置已自动支持本地保存：

```javascript
// 初始化时加载保存的列配置
const [columnConfig, setColumnConfig] = useState(() => 
  columnSettings.load(getDefaultColumns())
);

// 切换列时自动保存
const toggleColumn = (key) => {
  setColumnConfig(prev => {
    const newConfig = prev.map(col => 
      col.key === key ? { ...col, visible: !col.visible } : col
    );
    columnSettings.save(newConfig);  // 自动保存
    return newConfig;
  });
};

// 重置为默认
const resetColumnConfig = () => {
  const defaultConfig = getDefaultColumns();
  setColumnConfig(defaultConfig);
  columnSettings.reset();  // 清除本地保存
};
```

### 3. 添加新的设置项

参考以下模式添加其他设置：

```javascript
// 1. 在 SettingKeys 中添加键名
export const SettingKeys = {
  COLUMN_CONFIG: 'columnConfig',
  PAGE_SIZE: 'pageSize',        // 新增：分页大小
  THEME: 'theme',               // 新增：主题
  // ...
};

// 2. 创建专门的工具函数（可选）
export const pageSizeSettings = {
  KEY: SettingKeys.PAGE_SIZE,
  
  save: (size) => saveSetting(pageSizeSettings.KEY, size),
  
  load: (defaultSize = 10) => 
    loadSetting(pageSizeSettings.KEY, defaultSize),
  
  reset: () => removeSetting(pageSizeSettings.KEY)
};

// 3. 在组件中使用
const [pageSize, setPageSize] = useState(() => pageSizeSettings.load(10));

const handlePageSizeChange = (size) => {
  setPageSize(size);
  pageSizeSettings.save(size);
};
```

## API 参考

### 基础函数

| 函数 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `saveSetting(key, value)` | key: string, value: any | void | 保存设置项 |
| `loadSetting(key, defaultValue)` | key: string, default: any | any | 加载设置项 |
| `removeSetting(key)` | key: string | void | 删除设置项 |
| `clearAllSettings()` | - | void | 清空所有设置 |

### 列设置专用

| 函数 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `columnSettings.save(columns, key?)` | columns: Array, key?: string | void | 保存列配置（key 可选，默认 `'columnConfig'`） |
| `columnSettings.load(defaultColumns, key?)` | defaultColumns: Array, key?: string | Array | 加载并合并列配置 |
| `columnSettings.reset(key?)` | key?: string | void | 恢复默认列配置 |

## 存储格式

设置项存储在浏览器的 `localStorage` 中，键名格式为：

```
neu_toolbox:<key>
```

例如：
- `neu_toolbox:columnConfig` - 列配置
- `neu_toolbox:pageSize` - 分页大小

## 注意事项

1. **存储限制** - localStorage 通常有 5MB 限制，不要存储大量数据
2. **隐私安全** - 不要存储敏感信息（密码等）
3. **版本兼容** - 列设置会自动合并，但如果数据结构大变可能需要重置
4. **隐私模式** - 部分浏览器的隐私/无痕模式下 localStorage 不可用

## 未来扩展建议

以下设置项可以考虑添加本地保存：

## 共享资源与页面数据

成绩、培养计划和科研训练不得在页面里自行维护另一套“先请求缓存、再请求远端”的
effect。统一使用 `frontend/src/resources/ResourceStore.js`：

```javascript
const resource = useCachedResource('scores');
// resource.data              当前页面固定显示的版本
// resource.availableData     后台已提交的最新版本
// resource.updateAvailable   两个 revision 是否不同
// resource.refresh()         手动强制检查，复用后端 single-flight
// resource.applyAvailable()  用户确认后切换显示版本
// resource.applyData(data)   精确应用弹窗实际展示的版本，避免多 revision 竞态
```

规则：

- App 路由之上只挂一个 `ResourceProvider`，以账号/离线状态作为 generation 边界。
- 内存已有数据时切页零等待；浏览器刷新只调用 cache-only typed API。
- 在线 cache miss 或 stale 才提交后台 job；离线模式绝不调用 refresh。
- focus/visibility 恢复时重新读本地缓存；miss 或 stale 才请求协调器，失败由后端 60 秒
  退避防抖。
- 无 job 的 `throttled` 与 job 的 `failed/cancelled` 都是失败结果：必须结束 loading、
  保留旧数据并显示重试反馈；手动刷新不得随后把旧缓存提示成“刷新成功”。
- 每 15 秒轮询的是本地 revision event，不是教务系统；首次轮询只建立 cursor。
- 首次无旧数据的 job 完成后自动显示；已有 displayed revision 时必须提示用户应用新版。
- 更新提示必须展示当前版本与可用版本的变化摘要；只有没有 displayed revision 的静默
  首载可以不显示。
- “稍后”只固定本次页面显示，新缓存仍安全提交；离页后销毁 Modal/timer，重新进入直接
  使用 available 版本。
- 不使用全局同名 AbortController 取消其他消费者；StrictMode、多组件和多标签最终由
  后端 single-flight 保证。
- 应用培养计划新版时尽量保留搜索、分类、展开、分页和滚动；GPA 模拟编辑态不得被真实
  数据静默覆盖，而要走 revision 三方协调。

新持久资源必须先在后端 Registry 登记，并同步更新
[缓存与数据一致性](缓存与数据一致性.md)；前端 definitions 只是对应 typed reader，
不能成为第二份策略真相。
