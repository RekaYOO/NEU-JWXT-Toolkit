# 前端开发

前端使用 React 18、React Router 6 和 Ant Design 5。视觉与响应式规则见
[前端设计规范](前端设计规范.md)，完整修改流程见
[开发接手与变更规范](开发接手与变更规范.md)。

## 页面和路由

顶级功能登记在 `frontend/src/features/featureRegistry.js`，包括稳定 ID、路径、名称、图标和
离线能力。`App.js` 只负责实际组件、认证/离线 guard 和嵌套路由；`MainLayout.js` 从注册表生成
导航和页名。

新增页面时至少处理：

1. 注册功能或把它作为已有功能的子路由。
2. 明确在线、离线和 server 网站访问层的可用性。
3. 添加 loading、empty、error、stale 和 submitting 状态。
4. 在 320、375、430、768、1024 和 1440px 检查核心流程。
5. 更新[移动端能力矩阵](移动端能力矩阵.md)和功能文档。

不应为每个工具都增加顶级导航；例如证明打印和四节活动属于“导出下载”子功能。

## 数据状态

数据页不能用一个 `loading` 覆盖所有情况。至少区分：

- 首次没有数据，正在读取本地或远端；
- 已有本地数据，后台刷新中；
- 数据过期但仍可展示；
- 远端失败，保留旧数据；
- 空结果；
- 写操作提交中或结果待核验。

共享可重建资源使用 `frontend/src/resources/ResourceStore.js`。页面订阅资源快照、revision、
刷新任务和事件，不把同一缓存再复制到组件 localStorage。个人课表和头像使用
`BrowserTimetableStore` 的账号隔离 IndexedDB 镜像，仍由 ResourceProvider 统一协调；其他业务
资源只读取服务器缓存。后台更新只更新数据，不应在用户没有
改变筛选时重排列表、关闭展开项或把滚动位置拉回顶部。

## 筛选、排序和统计

- 保留一份原始数据；筛选、排序、分页和统计使用 `useMemo` 派生。
- 统计必须使用与当前列表相同的筛选结果。
- 数值范围使用统一解析和边界语义；空值不是 0。
- 搜索触发方式按业务决定。远端大目录通常在回车/点击后查询，不在每次按键时请求。
- 后台标签变化默认不重排已加载列表；用户改变搜索、筛选、范围或分页后才重新排序。
- 官方代码与中文标签分离，提交代码、展示名称。

桌面表格列筛选与手机筛选抽屉必须写入同一筛选状态，不维护两套规则。

## 列设置和浏览器偏好

页面偏好使用 `frontend/src/utils/settings.js` 封装，不直接散落调用 localStorage。键名应稳定、
带页面语义，并为无效旧值提供安全默认。列设置保存显示列和顺序；新增默认列不得覆盖已有用户
选择。

账号级业务数据不能放 localStorage，包括课程方案、收藏、自动任务和归档。这些数据由后端按
账号持久化。

## 读取和刷新

推荐页面流程：

1. 订阅本地快照并立即渲染。
2. 根据 freshness 决定是否提交后台刷新。
3. 轮询 job 或监听 cache event，拿到新 revision 后替换快照。
4. 保留当前筛选、展开、焦点和滚动上下文。
5. 显示最近数据时间，而不是只显示旋转图标。

手动刷新可以提高本次请求优先级，但不应绕开 single-flight、认证互斥或风控退避。

应用壳使用 `GET /api/client/bootstrap` 获取本地运行环境、认证快照、事件游标以及课表/头像
服务器缓存，避免首屏分别请求多组状态接口。该接口不访问学校系统；若后端版本尚未提供它，
前端自动回退原有 `/api/status`、课表和头像 cache-only 接口。后续本地状态通过账号级
`ClientUpdateScheduler` 调用 `/api/client/updates`，合并缓存事件和认证挑战轮询。

同一账号的多个标签页优先通过 `BroadcastChannel` 和 localStorage 短租约只保留一个轮询主
标签，其他标签消费主标签广播的服务器确认结果；浏览器不支持时保持独立轮询兼容。调度器只
合并相同只读请求，自动任务页面仍以 1 秒刷新可见进度，短信认证倒计时和用户主动刷新也不降频。

## 写操作

按钮点击后立即锁定相同操作，提交前给出业务影响和具体对象。官方明确成功时先更新受影响的
最小前端状态，再异步刷新相关资源；不要让用户等待完整目录重载才看到成功。

响应不明确时显示“待核验”，不得在前端自动重发。两步操作（例如撤回后重投）每一步都必须
以官方确认状态为前提，并允许中途停止。

### JWXK 双模式

选课工作台的抢选 `02` 与权重 `04` 共享同一页面骨架、目录、方案、结果、课表和任务卡。
`frontend/src/utils/jwxkModes.js` 是前端模式语义的唯一来源，集中定义人数口径、当前结果
feed、允许的任务类型和空状态。页面不得再用 `devoted_weight`、按钮文案或字段是否存在来
猜测模式。

- `02` 读取当前 `selected`，展示意愿值、已选人数、自动抢课和空位换课。
- `04` 读取当前 `volunteered`，展示投权值、已投注人数、模型和策略投权。
- 两种模式的 `0/0`、明确批次/学期不匹配及错误 feed 均只读并置底。
- 结果操作入口优先服从后端 `operation_allowed` 和 `operation_block_reason`，前端规则只作
  旧后端兼容兜底。
- `ALL`、`ROUND`、`ALLKC` 只用于目录；创建任务或发起写操作前必须确认真实
  `teaching_class_type`。
- 三类自动任务共享启动、暂停、取消、立即检查、执行阶段、最近/下次检查和操作历史布局；
  模式专属字段作为插槽出现，不复制第二套任务卡。
- 抢选高意愿候选处于数据未知、登录恢复、请求退避或提交待核验时，前端必须明确显示
  “不降级”原因，不能提供绕过状态机直接尝试低意愿课程的操作。

## 桌面与手机

桌面和手机使用同一份数据、派生结果、校验和 handler。根据任务改变布局：

| 场景 | 桌面 | 手机 |
|---|---|---|
| 多字段比较 | 表格 | 摘要卡 + 详情 |
| 复杂筛选 | 工具栏/列筛选 | 有活动条件数的筛选抽屉 |
| 层级 | 树 + 列表 | 类别抽屉 + 列表 |
| 批量操作 | 表格选择 | 条目选择 + 底部操作栏 |
| 详情 | 抽屉/Modal | 全宽抽屉或自适应 Modal |

不能靠 `display: none` 删除手机端合法能力。触屏目标、键盘焦点、ARIA 名称、减少动态效果和
错误文本都要可用。共享移动组件位于 `frontend/src/components/mobile/`。

字段较多且同时包含结果列表的筛选 Modal 必须受 `100dvh` 动态视口约束：标题和 footer 固定在
弹窗框架内，中间 body 独立纵向滚动；320px、窄高度横屏和虚拟键盘出现时，关闭、清空与应用
操作仍须可达。不能用整页滚动或截断结果区来掩盖弹窗过高。

课表是响应式共享的特例：桌面普通课表、手机七日缩略视图和选课紧凑课表必须复用同一个
`TimetableGrid`，节次偏移、课程跨度、重叠课程和点击详情复用同一组模型，通过展示策略调整
字段、字号、行高及重叠布局；桌面与手机缩略视图使用同一课程簇。桌面以悬浮切换展开项，
手机缩略视图以首次点击展开、再次点击进入详情。手机按日课程
卡片是另一种任务布局，不复制七日网格算法。校区节次时间由
`frontend/src/utils/timetableSections.js` 统一补全，页面组件不得自行维护作息常量。

课表展示最终只维护两个结构：`MobileTimetable` 的按日卡片，以及 `TimetableGrid` 的七日网格。
`MobileCompactWeekTimetable` 只能作为参数包装器调用共享网格，不能拥有第二套节次定位 JSX 或
CSS。重叠课程必须使用同一规范化课次和 `groupDayCourses` 课程簇；不同设备只改变字段密度、
展开手势和字号，不得重新解析时间文本或改变冲突结论。

`resolveTimetableSections` 返回仅供展示的 `ResolvedTimetableSection`，输入保持不可变。时间按
官方节次字段、可验证的课程字段、版本化内置校区作息逐级补全，未知校区不得套用默认值。
“全部校区”需要保留不同的时间 variant，并把相同时刻的校区合并。手机缩略模式每节都显示
开始时间和“第 X 节”；地点取消行数截断，由 `mobileCompactSectionHeights` 按 320px 宽度、
课程跨度、展开项内容和折叠标题增加必要行高。选课紧凑模式不因地点增长，因为该模式只显示名称和状态。
全部校区的 variant 应优先由当前渲染课程的可识别校区生成，只有课程没有校区信息时才回退
页面上下文的校区目录；查询课表不得复用个人课表的 `sections_by_campus`。时间轴宽度与节次最低
高度根据实际不同时间 variant 数量调整。多个时间使用固定的“短校区标签 / 开始时间”两列
居中对齐，节次放在时间组下方，不能靠左上角堆字或压缩星期列容纳多校区标签。

学期课表为第 12 节和移动浏览器安全区保留的滚动尾部必须放在主课表、未安排节次和集中实践
之后；不得把永久 `padding-bottom` 加在主课表组件内部，否则会把附加课程推离主课表。

班级、教师和教室课表在手机端复用个人课表的悬浮设置组件与 `mobileCompactWeekView` 偏好，
但查询对象是悬浮窗首要信息，且不显示“打开时默认课表”。查询模式选择对象、换日、换周和
刷新不得执行个人课表的首次自动聚焦；课程数量变化时只临时稳定滚动空间，不保留永久占位。
查询对象尚未选择时不能显示“正在识别教学周”这类虚假进行状态；刷新入口应刷新对象目录，
对象选定并取得上下文后才刷新课表。官方筛选值与展示标签分离，例如楼层 `3.0` 继续作为请求值，
界面统一显示为 `3`。

修改该链路时至少覆盖：四校区 12 节作息、官方/课程时间覆盖、未知校区、全部校区 variant、
同一时段手机堆叠的两阶段点击、长地点行高、课程详情点击、周视图滑动换周和学期视图禁用换周手势。

## 样式

全局令牌定义在 `frontend/src/App.css`，Ant Design theme 在 `App.js`。页面 CSS 使用语义类名
和全局变量，不复制品牌色。业务状态颜色固定：成功、警告、危险、信息不能因页面不同改变含义。

页面应优先复用 Ant Design 和已有业务组件。只有跨页面确有相同状态、交互和可访问性要求时才
抽共享组件，避免为了消除少量 JSX 形成难懂抽象。

## 测试和构建

```bash
cd frontend
npm ci
npm test
npm run build
npm run test:performance
```

测试优先覆盖用户可见行为：筛选与统计同步、缓存先显、写操作防重复、失败保留旧数据、账号
切换、移动端入口和路由 guard。纯格式化函数放在 `utils/` 并做确定性单元测试。

生产构建必须使用同源 API；CI 会检查 bundle 中没有固定的
`http://localhost:8000` baseURL。项目有意保留一个 CRA 主包，不使用路由代码分割；新增依赖和
页面代码必须通过 `test:performance` 的 gzip/Brotli 预算。`npm run build` 会生成 `.gz`、`.br`
预压缩变体，并从运行构建中移除 `.map`。正式 Release 在 CI 中先私下保存与版本对应的 source
map artifact，再剥离进入 Windows/Linux 发行载荷的副本；源码运行和发行程序均不会公开 map。
