# 日志系统文档

## 概述

`backend.core.log` 模块提供完整的日志记录和管理功能，支持分级分类存储、自动轮转、API 查看等功能。

## 功能特性

- ✅ **分级日志** - DEBUG/INFO/WARNING/ERROR/CRITICAL
- ✅ **分类存储** - system/access/error/login/sync
- ✅ **自动轮转** - 按天和单文件大小轮转，自动清理过期日志
- ✅ **访问日志** - 记录所有 HTTP 请求、可信来源 IP、代理节点、User-Agent、会话账号和响应结果
- ✅ **认证审计** - 单独记录网站访问密码、教务登录、二维码、短信、自动恢复和登出事件
- ✅ **错误关联** - 访问、认证和异常日志使用同一个 `request_id`
- ✅ **日志查看** - 通过 Web 界面查看、搜索、下载

## 项目结构

```
backend/core/log/
├── __init__.py          # 导出 get_logger, LogConfig, LogCategory, AccessLogger 等
├── logger.py            # 核心日志功能（含 StructuredLogger）
├── access_logger.py     # 访问日志中间件（FastAPILogMiddleware）
└── manager.py           # 日志管理器（LogManager）
```

## 日志存储

日志文件存储在 `data/logs/` 目录下：

```
data/logs/
├── system_2024-03-17.log   # 系统日志
├── access_2024-03-17.log   # 访问日志
├── error_2024-03-17.log    # 错误日志
├── login_2024-03-17.log    # 登录日志
└── sync_2024-03-17.log     # 同步日志
```

## 使用方法

### 1. 基础日志记录

```python
from backend.core.log import get_logger, LogCategory

# 获取系统日志记录器
logger = get_logger("my_module", LogCategory.SYSTEM)

# 记录日志
logger.debug("调试信息")
logger.info("一般信息")
logger.warning("警告信息")
logger.error("错误信息")
```

### 2. 结构化日志

```python
from backend.core.log.logger import StructuredLogger
from backend.core.log import LogCategory

logger = StructuredLogger("my_module", LogCategory.SYNC)

# 添加上下文
logger.with_context(user_id="20220001", action="sync_scores")

# 记录带上下文的日志
logger.info("开始同步成绩")
logger.error("同步失败", error_code=500)
```

### 3. 访问日志中间件

FastAPI 已自动集成：

```python
from backend.core.log import LogConfig
from backend.core.log.access_logger import FastAPILogMiddleware

# 添加中间件
app.add_middleware(FastAPILogMiddleware, config=LogConfig())
```

所有 API 请求会自动记录：
```
2026-07-31 10:20:00 [INFO] neu.access.access: HTTP {"event":"http_access","request_id":"...","method":"GET","path":"/api/scores/cache","status_code":200,"client_ip":"198.51.100.20","peer_ip":"127.0.0.1","user_agent":"...","user_id":"20250001","gateway_state":"authenticated","access_session_id":"..."}
```

访问字段含义：

| 字段 | 含义 |
|------|------|
| `client_ip` | 按可信代理配置解析出的原始访问 IP；只有直连节点位于 `trusted_proxies` 时才采信转发头 |
| `peer_ip` | 与应用建立 TCP 连接的节点，服务器部署时通常是 Caddy/Nginx 的回环地址 |
| `user_id` | 请求完成时内存中已认证的 NEU 账号；为空表示尚未登录教务系统 |
| `access_session_id` | 网站访问密码成功后签发的随机会话标识，用于串联同一浏览器会话，不是 Cookie 本身 |
| `gateway_state` | `not_required`、`anonymous` 或 `authenticated` |
| `response_size_bytes` | 实际发送的响应正文大小 |

日志中不记录查询字符串、请求体、密码、Cookie、短信验证码、二维码内容、恢复令牌或登录流程 ID。成绩追踪恢复路径中的令牌会统一替换为 `<redacted>`。

### 4. 认证安全事件

`login_YYYY-MM-DD.log` 记录网站访问密码、NEU 直连/WebVPN 登录、二维码、短信、自动恢复、教务登出和成绩追踪一次性恢复登录。每条事件包含结果、来源 IP、代理节点、User-Agent、`request_id`、网站访问会话 ID，以及可确定时的 NEU 学号。

网站访问密码是单一共享密码，本身不能证明访问者的现实身份；在 NEU 登录成功前，只能通过 IP、User-Agent 和随机访问会话 ID 进行关联。

### 5. 稳定性错误

业务路由把非预期故障写入 `error_YYYY-MM-DD.log`，字段包含错误编号、组件、异常类型、HTTP 状态、来源 IP、会话账号和不含异常消息/局部变量的安全调用位置。客户端只收到同一个错误编号，不直接收到可能包含文件路径、票据 URL 或上游响应的原始异常文本。普通系统日志在请求期间也会自动追加 `request_id`、来源 IP 和会话账号。

### 6. 日志管理器

```python
from backend.core.log.manager import LogManager
from backend.core.log import LogCategory

manager = LogManager()

# 获取日志文件列表
files = manager.get_log_files(category=LogCategory.SYSTEM, days=7)

# 读取日志内容
entries = manager.read_log(
    LogCategory.SYSTEM,
    "2024-03-17",
    level="ERROR",
    search="timeout",
    limit=100
)

# 查看日志末尾
entries = manager.tail_log(LogCategory.ACCESS, "2024-03-17", lines=50)

# 搜索日志
results = manager.search_logs("error", LogCategory.ERROR, days=7)

# 清理旧日志
deleted = manager.clear_old_logs(keep_days=30)
```

## 日志分类说明

| 分类 | 用途 | 示例 |
|------|------|------|
| `system` | 系统运行日志 | 服务启动、配置加载 |
| `access` | API 访问日志 | HTTP 请求记录 |
| `error` | 错误日志 | 异常堆栈 |
| `login` | 登录相关 | 登录成功/失败 |
| `sync` | 数据同步 | 成绩同步记录 |

## Web 界面

日志查看页面：开发模式为 `http://localhost:3000/logs`；默认单端口模式为 `http://localhost:8000/logs`。

功能：
- 按分类/日期/级别筛选日志
- 按预设消息类型筛选（HTTP 请求、访问密码验证、NEU 登录、WebVPN、会话恢复、应用异常等）
- 列表只显示类型和短摘要；点击一行/一张卡片查看完整字段、请求上下文和原始消息
- 实时查看最新日志（tail）
- 关键词搜索
- 下载日志文件
- 清理旧日志

## API 接口

### 获取统计摘要
```bash
GET /api/logs/summary?days=7
```

### 获取日志文件列表
```bash
GET /api/logs/files?category=system&days=7
```

### 获取日志内容
```bash
GET /api/logs/content?category=system&date=2024-03-17&level=ERROR&limit=100
```

`entries` 中除时间、级别、日志器和原始 `message` 外，还包含展示字段：

| 字段 | 说明 |
|---|---|
| `event_type` | 稳定的预设事件标识，例如 `http_access`、`neu_login`、`application_error` |
| `event_title` | 面向用户显示的中文事件名称 |
| `summary` | 列表使用的短摘要，不替代原始消息 |
| `details` | 从结构化消息中提取的安全详情字段；未知旧日志为空对象 |
| `structured` | 是否命中结构化事件匹配 |

匹配由后端完成，前端不依赖日志字符串自行解析。无法识别的旧格式会显示为“系统记录”或
对应分类的普通记录，原始内容仍可在详情中查看，因此升级不需要迁移历史日志文件。

### 查看日志末尾
```bash
GET /api/logs/tail?category=access&date=2024-03-17&lines=100
```

### 搜索日志
```bash
GET /api/logs/search?keyword=error&days=7
```

### 下载日志文件
```bash
GET /api/logs/download/system/2024-03-17
```

### 清理旧日志
```bash
DELETE /api/logs/cleanup?keep_days=30
```

## 配置

```python
from backend.core.log import LogConfig, LogLevel

config = LogConfig(
    log_dir="data/logs",           # 日志目录
    level=LogLevel.INFO,            # 日志级别
    max_bytes=10*1024*1024,        # 单个文件最大 10MB
    backup_count=7,                 # 每天最多保留 7 个大小轮转分片
    retention_days=30,              # 自动删除 30 天前的日志
    format_type="text",            # text 或 json
    console_output=True,            # 同时输出到控制台
)
```

## 最佳实践

1. **选择合适的分类** - 便于后续查找和过滤
2. **使用适当的级别** - DEBUG 用于调试，ERROR 用于需要关注的错误
3. **添加上下文信息** - 使用 StructuredLogger 记录关键上下文
4. **定期清理** - 设置合理的保留策略，避免磁盘占满
5. **关注错误日志** - 定期检查 error 分类的日志
6. **保护日志访问** - IP、User-Agent 和学号属于敏感审计数据，服务器日志 API 必须继续受网站访问密码保护
7. **正确配置代理** - `trusted_proxies` 只填写应用直接信任的反向代理 IP，不要填写任意公网地址
