# 日志系统

日志模块位于 `backend/core/log/`，用于运行诊断、HTTP 访问审计、认证安全事件和可关联的
应用错误。日志页面是系统设置的一个标签，不是独立顶级功能。

## 分类和位置

| 分类 | 文件前缀 | 内容 |
|---|---|---|
| 系统 | `system_` | 服务生命周期、业务状态和普通诊断 |
| 访问 | `access_` | HTTP 方法、路径、状态、耗时和访问上下文 |
| 错误 | `error_` | ERROR 以上事件和应用异常 |
| 登录 | `login_` | 网站访问层、NEU 登录、二维码、短信、恢复和登出 |
| 同步 | `sync_` | 明确登记为同步类的后台工作 |

文件位于运行数据目录的 `logs/`：开发模式为 `<仓库>/data/logs`，Windows 发行版为
`%LOCALAPPDATA%\NEU-JWXT-Toolkit\data\logs`，Linux 服务为
`/var/lib/neu-jwxt-toolkit/logs`。

默认级别为 INFO，单文件上限 10 MiB、每类每日最多 7 个轮转分片、保留 30 天。文件名为
`<category>_YYYY-MM-DD.log`，分片使用数字后缀。访问日志只写分类文件，不重复输出到
stdout/journald，避免大量目录扫描造成控制台背压。

## 关联字段

`FastAPILogMiddleware` 为每个请求建立异步安全上下文：

- `request_id`：跨访问、系统、认证和错误日志关联一次请求；
- `client_ip`：根据受信反向代理规则得到的客户端地址；
- `peer_ip`：直接连接应用的地址；
- `session_user`：当前登录账号（存在时）；
- `access_session_id`：Linux 网站访问层会话（存在时）；
- User-Agent、方法、路径、状态码和耗时。

普通系统/错误文本会追加最小关联上下文。访问与认证事件使用结构化 JSON 消息；日志页面通过
`backend/core/log/presentation.py` 把已知事件转为用户可读标题、摘要和字段。

## 记录日志

业务模块通过分类 logger 写入：

```python
from backend.core.log import LogCategory, get_logger

logger = get_logger("course-selection", LogCategory.SYSTEM)
logger.info("catalog refresh completed rows=%s", row_count)
```

认证事件使用 `log_security_event()`，未预期应用错误使用 `log_application_error()`。后者返回
短错误编号供 API 响应引用，并把异常类型和有限堆栈保存到错误日志；客户端不接收完整堆栈。

日志应描述阶段、对象类型、耗时和结果，不能记录：

- 密码、短信验证码、Cookie、CAS ticket、Authorization、`secretVal`；
- SMTP 授权码；
- 完整个人业务响应或自由文本评价；
- 可用于重放远端写操作的请求体。

课程、教学班或任务标识确有诊断价值时使用最小必要字段，账号只使用上下文中的当前身份。

## 页面和 API

系统设置中的日志页支持分类、日期、级别、关键词、分页、尾部查看、下载和按保留天数清理。
Linux server 模式下所有接口仍受网站访问密码保护。

| 接口 | 用途 |
|---|---|
| `GET /api/logs/summary` | 最近 1–30 天分类和文件大小摘要 |
| `GET /api/logs/files` | 文件列表 |
| `GET /api/logs/content` | 指定分类/日期的分页内容 |
| `GET /api/logs/tail` | 最新 1–500 条 |
| `GET /api/logs/search` | 跨日期关键词搜索 |
| `GET /api/logs/download/{category}/{date}` | 下载合并后的当日日志 |
| `DELETE /api/logs/cleanup` | 删除超过保留天数的文件 |

路由对分类、日期、分页和清理天数做边界校验，不接受任意文件路径。下载会合并同一天的轮转
分片。

## 排障方式

1. 从用户界面的错误编号或时间开始。
2. 在访问日志找到对应 `request_id` 和 HTTP 状态。
3. 使用同一 `request_id` 关联系统、登录和错误日志。
4. 区分认证恢复、官方业务拒绝、请求过快、本地解析和写操作待核验。
5. 分享日志前进行脱敏；不要把整个日志目录上传到公开 issue。

后台长任务应记录阶段和累计耗时，避免用“失败”掩盖具体失败点。请求过快属于业务退避状态，
不应触发连续登录重建。

## 实现和测试

- `logger.py`：分类 logger、格式化、按日与大小轮转。
- `context.py`：请求上下文。
- `access_logger.py`：ASGI 访问和未处理异常审计。
- `security_logger.py`：认证事件和安全错误编号。
- `manager.py`：读取、搜索、下载和清理。
- `presentation.py`：结构化事件的用户展示。
- `backend/app/routers/logs.py`：受约束的 HTTP 接口。

修改日志字段时同时检查隐私、Linux 反代地址、轮转分片顺序和页面兼容。相关测试分布在
认证、运行模式和日志路由测试中；生产日志不得作为测试夹具提交。
