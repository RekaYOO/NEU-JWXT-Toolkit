# 本地数据存储

旧进程级邮件、追踪和恢复配置通过 `import-legacy --shared-settings-owner ACCOUNT` 单独接续。
维护命令要求显式归属、先预览后按摘要应用；文档和邮件加密记录使用同一事务，冲突全回滚。
追踪保持关闭，不接续旧会话、旧恢复令牌和邮件队列。详见[旧版资料导入](../部署/旧版资料导入.md)。

## 旧版文档接续

`toolbox import-legacy` 先预览来源归属、目标差异与摘要，再按摘要将支持的权威文档原子写入。
实现及限制见[旧版资料导入](../部署/旧版资料导入.md)。相同内容不重复创建，新版墓碑不复活，
原始文件不修改；导入不启动任务、不恢复学校会话，已过期日程标记保留。
支持 GPA、绩点偏好、科研收藏、选课方案、显式学期日程及课程历史归档；其他旧资料仍须继续接续。
归档使用独立 64 MiB 文档上限，避免完整目录被普通文档 4 MiB 限制截断；事务总量最多 128 MiB。
旧集合文件按账号逐记录转换，新归档标识按轮次生成；保留历史课程来源、课次、人数与归档状态，
清除扫描进度且不续跑旧扫描任务。目录查询仍区分真实轮次课程与 ALLKC 发现范围。

## Go 新版加密备份

维护入口为 `toolbox backup/restore --data ... --file ...`，实现位于 `internal/store/backup.go`
和 `cmd/toolbox/backup.go`，操作说明见[Go备份与恢复](../部署/Go备份与恢复.md)。
SQLite `VACUUM INTO` 取得一致快照，将数据库、vault 密钥及 SHA-256 清单作为 ZIP 流
交给 `filippo.io/age` 标准口令加密，不复制活动 WAL，不自行实现加密协议。
输出使用独占硬链接发布，拒绝覆盖既有文件。

恢复在私有临时目录认证、限额解包和校验，仅接受三个固定普通文件。完整性、外键及全部
密文凭据验证后按当前 schema 打开临时数据，原子撤销会话/恢复上下文、暂停任务/追踪、
取消待发邮件；保留未知写入记录和删除墓碑。最后独占创建新目标目录，以进行中标记防止
中断后启动不完整数据。部署模式、站点密码、准入和资料保留，不触发学校访问。

验证入口：`internal/store/backup_test.go`、`cmd/toolbox/backup_test.go`，覆盖双账号往返、
密钥配对、错误密码、截断、目录穿越、未知文件、删除记录、未知操作和恢复暂停语义。
旧 Python 数据转换仍需独立实现，不以新版备份替代。

Go成绩追踪配置保存在grade-tracking/config文档，账号generation和revision保护；专用接口仅更新
间隔和时段，通用文档入口禁止改删。state保存脱敏检查结果及时间，snapshot保存剔除详情引用的语义
成绩快照；成功检查批量CAS提交两者，失败只更新state。后台执行仍在迁移。

Go重构分支的`toolbox.db`现为Schema 10；`evaluation_attempts`以账号与
学期/任务/课程摘要为键保存提交状态、尝试次数和更新时间，不保存评分正文或评分原因。
发送前原子登记pending；pending/unknown/confirmed不得再次发送，明确rejected/not_sent可重试。
账号撤权后旧generation不能开始或更改提交记录；重启不清理未知记录，不恢复批量发送。
该表不是可重建缓存，清理缓存不能删除它。Schema 4升级保留原有数据并新增此表。

## Go重构分支缓存边界

festival-activities为default/Schema 1/30分钟资源。自动模式保留活动元数据与已核准的私密证书引用，
API始终移除详情和证书URL；按需读取不提交任务、不写缓存。切换按需时，Resources.Delete等待
同账号在途工作后事务删除指定键，并标记旧job不可运行或复用，禁止完成任务冷却期返回已删除结果。
数据库删除核对账号generation和启用状态；其他账号、其他变体及其他资源不受影响。

research-training使用default变体、Schema 1、5分钟TTL；批次、资格、完整目录和已确认课题
全部读取成功后提交，分页总数变化或批次切换不能提交混合快照。research-favorites是账号权威
文档，按批次/课题联合摘要保存展示快照和收藏时间；通用文档API不能改删。缓存提交后按账号锁
读取最新缓存更新收藏快照，CAS和generation阻止删除或撤权之后复活，跨批次及下架收藏标为过期。
取消收藏写入删除版本；清理目录缓存不得删除收藏。旧JSON收藏现由 `import-legacy` 按账号和批次导入，参见本页“旧版文档接续”。

research-operations保存最近科研报名操作，按课题摘要存批次、动作、pending/unknown/confirmed/
rejected/not_sent和尝试次数，不保存联系方式或申请理由。发送前CAS写入pending；响应丢失
只读核验，撤权后拒绝写入迟到结果并保留pending证据。重启不清理未确认记录；通用文档接口禁止改删。

experiment-courses使用default变体、Schema 1和5分钟TTL，按账号保存当前学期课程与独立官方
选课结果；共享刷新只有两者都成功才提交。课程和结果稳定排序后计算revision，变化摘要记录
课程增删改和selected_results_changed。班次保持实时查询、不单独持久化；冲突基线仅读取
personal-timetable/term:<同学期>，陈旧或结构缺失不作为硬性阻止依据。

experiment-operations为账号权威操作文档，按学期/任务/项目摘要保存最近一次选退意图、班次、
状态和尝试次数。发送前CAS写入pending，结果不明保留unknown；重试先读学校结果，不能重发
未确认的操作。verify只读核验，confirmed后允许学校端人工变更引起新的明确操作。
通用文档PUT/DELETE禁止改动此命名空间；成功操作仅失效目标学期课表，失效后绕过已完成job的复用期。

独立JWXK任务候选使用secrets的campus-service-jwxk用途，AES-GCM绑定账号和用途，正文含
账号、generation和网关Cookie，不保存学校密码。重启只有账号启用且密文代次仍匹配时才能恢复，
无需把恢复链接访客变成普通浏览器用户；首次业务调用前验证子服务。主登录与此密文分开，
用户选择忘记登录时同时删除两者，普通退出通过代次撤销防止旧密文复活。

Schema 10增加auth_recovery_contexts，绑定账号/generation、primary或jwxk目标、业务来源/范围、
配置epoch、创建和固定到期时间。只存随机上下文ID与签名token哈希；发送阶段可通过本机密钥和
域分离HMAC重建token，不需要把完整链接写入outbox。账号撤权、停用、配置epoch变化、到期与
终态均拒绝读取和重建。相同有效上下文复用且不续期，并发消费只允许一次；每账号最多64个活动
上下文，达到上限拒绝新建，不淘汰有效链接。新建时清理该账号过期、旧代次/配置及终态上下文。
token专用HTTP流程与发送时链接组装已接通。通知队列只保存recovery_id，发送时核对账号、
generation、业务来源、配置epoch和固定期限，再在内存组装URL。主会话新登录或对应子服务
恢复后撤销同目标其余活动链接。成功消费发生在会话发布前，后续发布失败也不重新激活该token。

Schema 9增加site_auth_sessions，保存分用途令牌哈希、绑定的凭据版本和到期时间，令牌明文只在
HttpOnly Cookie中。site_settings的credential-access/admin保存独立盐和scrypt密码哈希。
密码替换删除对应用途会话；管理员凭据不能读取学校账号密文。撤销账号代次与暂停运行中自动任务
在同一事务完成，文档revision同步递增，pending_selection/pending_drop等未知提交证据不清除。

Go入口使用独立数据目录中的`toolbox.db`。可重建资源与事件分别位于`cache_entries`和
`cache_events`，用户方案、账号会话与凭据分别存表；缓存清理不得删除整个数据库或`vault.key`。
缓存提交在事务内验证账号generation，退出前启动的任务不能覆盖退出后的数据。失败只记录错误，
保留已有快照；相同语义revision更新检查时间和学校引用，不改变数据更新时间。事件差异与缓存
同事务提交，重启后仍可读取。数据库schema 4为已有事件表增加changes字段，不删除已有资料。
本机只读离线可读取最近缓存账号，远程离线必须使用当前访问会话。旧Python数据迁移尚未接通。

## Go重构分支的用户数据

Go入口当前默认使用`data/go/toolbox.db`，`NEU_JWXT_DATA_DIR`仍优先。账号文档与旧版缓存分离，
以账号、命名空间、文档键构成复合主键；revision用于保存冲突，删除保留墓碑。新旧数据不会自动混合。
学校Cookie与用户明确记住的凭据使用AES-GCM加密，附加认证数据绑定账号与用途；浏览器会话只保存
随机令牌的SHA-256。停用或停止账号递增generation，旧Cookie不能通过恢复账号而重新生效。
备份和恢复必须同时包含SQLite数据库与同目录`vault.key`；遗失密钥时不能新建密钥冒充恢复成功。
旧版资料导入仍待接通，当前不会改写旧数据。实现和验证入口见[Go迁移](Go迁移.md)。

本文说明持久化数据的分类、位置、权限、清理和升级边界。可重建缓存的算法与并发规范见
[缓存与数据一致性](缓存与数据一致性.md)。

## 1. 数据目录

| 模式 | 默认目录 |
|---|---|
| `development` | 仓库 `data/` |
| `desktop` | `%LOCALAPPDATA%\NEU-JWXT-Toolkit\data` |
| `server` | `/var/lib/neu-jwxt-toolkit` |
| `mobile` | Android 应用内部 `filesDir` 下的数据目录，由本地启动器设置 |

`NEU_JWXT_DATA_DIR` 始终优先。业务代码只能从 runtime/共享 Storage 获取可写目录，不能
写冻结资源目录或自行依赖 cwd。Linux 目录权限为 `0700`，敏感文件和 `cache.db` 为
`0600`。

Android 本地版使用相同的 Storage、CacheStore、CacheCoordinator 和账号隔离规则，仅替换
数据根目录及通知出口。SQLite、会话、凭据和用户文档不得写入 Android `cacheDir`，该目录
仅用于可丢弃的下载中转文件。课程大纲的正文不持久化，但进入页面仍按共享逻辑自动请求
第一页；不能把“不缓存”解释为“仅手动刷新”。原生网络桥不承担业务缓存和认证恢复。

| 用户归档 | `course_selection_catalog_history.json` 中的账号级选课轮次快照 | 否；仅用户手动删除 |

不能仅因为数据是 JSON 就把它注册为缓存。收藏、GPA 方案、追踪配置、系统邮件 outbox、恢复状态、凭据、
Cookie、网站密码和日志永远不能由缓存淘汰策略删除。

## 3. SQLite 缓存

`cache.db` 是运行时可重建缓存唯一真相源。它采用 WAL、busy timeout、每线程短连接和
短事务；网络请求期间不持有数据库事务。主键是
`(account_id, resource, variant)`，保存 payload、Schema、revision、`saved_at`、
`last_checked_at`、`last_attempt_at`、错误类型及依赖 revision。

课程大纲仅保存 `course-outline-metadata` 最小元数据，不保存正文。Schema 2 保留旧条目供显示，
由在线消费者重新核验旧版本或过期数据；失败不覆盖旧值，不需要删除 `cache.db` 或其他个人数据。

单科分项成绩使用 `score-details` 资源和由 `course_code + term` 哈希得到的 variant。远端
WID 只作为后端查询引用保存在私密缓存，不进入浏览器、日志、邮件或测试夹具；空详情不得
清除以前成功保存的分项。总成绩成功刷新或登录恢复后，后端只为缺失或失配的 variant 排队
补全；前端详情页只读缓存。

四节活动仅在“自动读取并存储”模式下写入 `cache.db`，保存规范化活动元数据、已抓取
详情、解析警告和后端受控证书引用；公开响应始终剔除引用。“每次使用按需读取”模式只在
当前请求/页面内存中持有结果，不读写该缓存。模式偏好属于非敏感浏览器设置，不包含活动
数据。证书打包每次重新抓取；图片和 ZIP 只存在于请求期间的内存或受控临时流，响应结束
即清理。真实 cxcy 页面响应、Cookie 和 CAS 票据不得持久化为业务数据。

证书引用只允许四个分区旧目录或共享
`/static/uploads/res/certificate/{受限ID}/{单层图片文件}`；共享目录拒绝额外路径层级和
非 PNG/JPEG/WebP 文件，查询部分只允许可丢弃的临时时间戳类参数。canonicalization 移除
这些参数，避免同一证书因缓存戳变化制造 revision；公开 API 仍不返回该引用。

用户确认改为“每次使用按需读取”时，应用必须通过后端精确删除当前认证账号的
`festival-activities/default` 缓存。该动作不等同于“清除全部数据”：不得删除当前账号的
成绩、培养计划等资源，不得影响其他账号，也不得扩大到其他 variant。删除失败必须反馈
给用户并保持原模式；只有删除成功后才能保存按需偏好和开始当次读取。重新选择自动模式
后由正常刷新流程重新创建缓存。

业务代码只能通过 `CacheStore`/`CacheCoordinator`/typed adapter 读写缓存：

- 不直接执行缓存 SQL；
- 不用文件 mtime 判断 freshness；
- 不从页面、追踪或 router 写 `scores.csv`；
- 不对同一资源建立另一个 JSON 缓存或定时器。

旧文件首次可信访问时幂等导入。必须先校验账号和旧 Schema，再规范化、计算统一
revision、在 identity guard 内提交，随后标记待远端检查。迁移失败可以继续兼容读取旧
文件并写脱敏诊断，但不能生成半条 SQLite 数据。旧文件不再双写。

## 4. 权威用户数据

### 当日日程与调休

课表日程使用独立账号/学期文档保存 `revision`、`events` 和 `moves`；`moves` 表示从源日期复制
官方课程到目标日期的关系，不表示删除或移动源日课程。时间使用 `HH:mm`，日期使用无时区的日历日期；
后端未来日期校验按东八区进行，不依赖服务端操作系统时区。课程本身不复制写入文档，显示时从官方
课表投影，不混入官方缓存或选课数据。字段、条目数量、重复 ID、重复目标及时间范围均由 Schema 校验。

存储通过共享 Storage 的 runtime 数据根目录定位；进程内互斥锁内校验 revision，临时文件、fsync、
权限限制后原子替换。版本不符返回 409，不能覆盖旧文档。损坏文档不能当成空数据自动覆盖。
四种运行方式使用相同 API；APP 客户端跟随服务端账号数据，不创建另一套浏览器权威存储。
不注册 CacheRegistry，不随刷新/清缓存淘汰，发行目录检查明确排除 `timetable_agendas`。

文档内部 `_semester` 记录从当前账号 fresh、Schema 兼容的官方课表中确认的完整学期起止日期，
不接受前端提交；完整意味着从第 1 周起连续、每周周日至周六，无缺周及日期矛盾。元数据更新不增加
用户内容 revision，日期延长可更新，日期缩短不能提前清理。没有完整日期的旧文档保留，等待可信数据补齐。

结束日期过去后停止展示和编辑，内容暂留。日程 API 仅观察已有 CacheCoordinator/Registry 数据，
不发远端请求、不提交 job；只有 fresh 学期索引明确指向已开始且完整日期覆盖今天的新学期，才清理
当前账号中确认早于新学期的旧日程。清理通过同一互斥/原子写入，将 events/moves 清空、revision 增加一次
并保存 `_retired` 标记；保留的只是无日程内容的版本及生命周期元数据，避免旧窗口重新创建已清理数据。
损坏文件不重置，其他账号、未来学期和未知生命周期文档不动。预览学期、缓存 TTL 和清缓存都不是删除条件。
可重建缓存库读取失败时跳过本次生命周期确认，仍可读取独立日程文档，不把缓存故障传播为日程数据丢失。

### 绩点计算策略

`gpa_preferences/<account-sha256>.json` 是按账号隔离的权威配置，不是缓存。`mode` 只接受
`through_2024`、`from_2025` 或 `null`；`null` 按学号前四位自动选择。写入采用同目录临时文件、
fsync、权限限制和原子替换。成绩页、离线读取、模拟器与成绩追踪共用该值，清缓存不应删除。
该目录不得进入发行包、日志或版本控制。

### GPA 模拟

GPA 方案按账号哈希目录隔离，文件名使用 basename 限制，临时文件写入、fsync 后
`os.replace`。2.0 保存成绩/培养计划基线 revision 和基础真实成绩，用于三方协调。
旧 1.0 文件只有可信 `exported_by` 与当前账号一致时才复制导入，原文件不修改；没有
owner 的文件不能跨账号放行。

### 科研收藏

收藏以 `(account, batch_id, topic_id)` 隔离，保存最小课题归档。目录缓存更新后用最新
非敏感课题字段刷新收藏归档；换批次后收藏保留并标记过期，取消收藏才删除。导师联系
方式、申请/退回理由不写入目录缓存或收藏。

### 选课轮次课程归档

JWXK 课程目录实时读取，但用户浏览过的教学班会按账号与轮次合并进
`course_selection_catalog_history.json`。归档只保存规范化课程、教学班、时间、容量、匿名人数、
官方可选性和脱敏原因；禁止保存 `secretVal`、Authorization、Cookie、学号响应行或完整远端响应。

该文件是用户要求长期保留的历史资料，不注册进 CacheRegistry，也不按 freshness 淘汰。轮次结束前
进入轮次后，后台按该轮次真实课程类型扫描全部分页；可见页面无需等待扫描完成。轮次结束前
10 分钟内，后台对已确认可选且已归档的课程重新读取一次人数；结束后标记为历史备份。程序未在
结束窗口运行时保留最后一次可信数据并标明未完成最终刷新。归档按账号隔离，只能由用户在选课页面
逐轮次删除。

### 选课自动任务

`course_selection_tasks.json` 保存用户明确创建并启动的方案组、候选优先级、目标门数、运行意图、
轮询模式和最小提交核验标记。实时策略投权任务还保存年级人数、课程意愿、最近模型建议、
最近计算/调整时间，以及退选和重投两阶段的待核验状态。它不是缓存，程序重启后不能按 freshness 淘汰；仅当
`desired_state=running` 时恢复执行，并且必须先读取官方已选结果核验。每次远端写请求前原子保存
`inflight_mutation`，若进程或登录在写入期间中断，重启后只能核验官方结果，不能盲目重放。

任务文件禁止保存 `secretVal`、Authorization、Cookie、账号密码或完整远端响应。登录恢复继续
使用共享 `AuthSessionManager + NEUAuthClient`；账号不匹配时任务保持等待，不能在另一账号下执行。

策略模型使用的年级人数按“账号 + 学期”保存在普通配置中的
`course_selection_weight_grade_sizes`，属于用户策略配置而非远端缓存；切换账号或学期不会复用。

### 成绩追踪

- `grade_tracking_config.json` 只保存 enabled 意图、检查间隔和每日时段，不再保存 SMTP 或
  重新登录地址。
- snapshot/state 必须记录 `account_id`，切换账号时清空旧账号个人快照和 revision 去重状态，
  但保留通用检查配置及 enabled 意图。
- `last_notified_revision` 持久保证同一成绩 revision 最多通知一次；邮件投递状态不写回恢复 Flow。

### 系统邮件与远程认证恢复

- `system_mail_config.json` 保存全系统唯一 SMTP 通道；API 永不回传 `smtp_password`，只返回
  `smtp_password_configured`。成绩追踪与自动选课使用不同 source 和去重键，但共享发送线程。
- `system_mail_outbox.json` 是可靠重试队列，只保存普通邮件正文，或恢复邮件的上下文 ID 与模板。
  恢复 URL 中的明文 token 在真正发送前动态生成，不写入 outbox。
- `auth_recovery_config.json` 保存 `public_base_url` 和 `link_ttl_hours`（默认 3，范围 1–168 小时）；
  `auth_recovery_state.json` 保存账号、业务来源、`primary|jwxk` 目标、上下文 ID、token 哈希、
  创建时间、固定截止时间 `expires_at`、去重键和状态。旧链接按原创建时间加 3 小时补齐截止时间，
  不因升级或重启续期。终态记录最多保留最近 30 天，且总历史有界；未到期上下文不会因历史清理被删除。
- `auth_recovery_secret.key` 是恢复 URL 的 HMAC 密钥。二维码、图形验证码、短信验证码、Cookie、
  完整表单和候选 Session 只存在于进程内存，不得出现在任何上述文件中。
- 升级时从 `grade_tracking_config.json` 幂等迁移 SMTP 与 `site_url`，从旧
  `grade_tracking_outbox.json` 保留普通成绩/选课邮件并丢弃旧恢复路径邮件；旧文件不再作为运行时
  发送队列。旧恢复链接不兼容。

### 凭据和会话

`credentials.json` 当前仍是用户明确选择“记住登录”后的本地凭据，属于高敏感数据；
`session.json` 保存 CAS/WebVPN 会话。它们不能进入 API 响应、日志、测试夹具或发行包。

## 5. logout、清理和升级

主动退出 NEU 登录时先在统一远端锁内清 Cookie、提升 identity epoch、清活动 client
和凭据，再做本地清理，避免退出间隙被后台恢复。

`clear_data=true`：

- 删除当前账号 SQLite 缓存及事件；
- 删除当前账号科研收藏；
- 删除追踪个人 snapshot/state、系统邮件 outbox 和认证恢复上下文；
- 删除旧缓存、头像、Cookie 和凭据；
- 保留 GPA 用户文档、追踪检查配置、系统 SMTP 配置、远程恢复站点地址、恢复 URL 签名密钥、日志和 `cache.db` 基础设施文件。
- 保留选课轮次课程归档；它属于用户主动保留的资料，只能在对应页面手动删除。

`clear_data=false` 退出会话、暂停追踪并立即使现有恢复上下文/链接失效，但保留系统邮件配置、
outbox 中的普通业务通知和缓存；同账号下次登录可继续使用缓存，切换账号时追踪个人状态必须重新建立。

Windows 安装升级保留 `%LOCALAPPDATA%`；Linux `install.sh --upgrade` 只替换 `/opt`
并保留 `/etc`、`/var/lib`，健康失败回滚程序但不回滚数据。Release 包不得包含
`cache.db`/WAL/SHM、旧缓存、个人文档、日志、配置、凭据、会话或真实响应。
`course_selection_catalog_history.json` 同样不得进入发行包。

## 6. 浏览器本地数据

`localStorage` 仅保存列显示、分页等非敏感偏好，以及用户主动保存的 GPA 浏览器副本。
键统一使用 `neu_toolbox:` 前缀。禁止保存密码、Cookie、SMTP 授权码、恢复令牌或教务
完整响应。ResourceProvider 的内存数据是 UI 快照，不是持久化真相。

个人课表和头像是允许的浏览器业务快照：`frontend/src/resources/BrowserTimetableStore.js`
使用版本化 IndexedDB 保存在线身份确认后的当前/下一学期规范化课表、学期索引和单个头像
BLOB。它按账号命名空间隔离，最多保留两个学期；不保存选课叠加、临时预览、冲突结果、班级/
教师/教室结果或任何认证材料。浏览器镜像只能由服务器确认的课表/头像响应写入，不能回写
`cache.db`，也不改变显式离线模式的能力范围。用户可在设置中分别清除课表或头像镜像。

前端内置的多校区 12 节作息是随静态资源发布的版本化显示常量，不是用户数据或缓存记录。
解析时生成的节次时间只存在于 React 派生状态，不写入 IndexedDB，也不修改已保存的官方课表
快照；因此清除本机课表缓存与更新内置作息互不依赖。

# Go目录查询快照补充

重构分支使用SQLite `documents` 的 `jwxk-catalog-queries` 命名空间保存已成功的目录查询。
文档键由轮次和完整规范化查询条件的SHA-256组成，包含范围、分页、过滤、时段、排序和在线式条件，
不包含账号凭据；账号由外层文档主键隔离。只保存经投影的课程响应，不保存学校操作密钥。
快照属于用户保留资料，不注册普通过期缓存，不由缓存清理淘汰。写入采用账号generation与文档revision，
删除保留墓碑，旧刷新不能复活已删记录。通用文档写入接口禁止上传伪造快照，允许带revision删除。
此阶段是精确查询快照，不等同于完整轮次归档；全量合并与历史管理仍在迁移。

`jwxk-rounds`保存账号轮次展示元数据，由成功的官方状态读取写入；方案读取复用它填补学期、
选课类型和菜单。状态、账号资格等动态授权信息不作为本地放行依据，读取始终返回unknown状态和
can_enter=false。通用文档接口禁止客户端写入伪造快照，允许带版本删除；墓碑不由后台状态刷新复活。

`selection-attempts`保存手动投选操作摘要，键为操作类型、轮次和课程代码的SHA-256，账号由文档主键隔离。
保存state、attempt和文档revision；退课另存课程代码、轮次、教学班和学期，用于未知状态恢复及阻止提前重选，
不保存操作密钥或请求表单。发送前pending，结果为confirmed、unknown、
rejected或not_sent。pending/unknown/confirmed阻止重放，明确rejected/not_sent可重试；官方结果可将未知记录
核验为confirmed。客户端通用文档接口不得修改或删除该命名空间，进程重启不解除待核验限制。
确认退课后才重置已确认的同课程选课记录，确认重选后才重置已确认的同教学班退课记录；未知记录不能据此自动清除。

## Go轮次归档补充

`jwxk-archives`按账号与轮次哈希标识持久保存已查询的课程并集、来源和轮次展示元数据。
它是用户历史资料，不受缓存TTL淘汰。通用接口禁止上传官方资料；专用历史接口支持读取与删除。
删除保存墓碑，查询合并使用请求前版本校验，已删除轮次不会被后续后台查询复活。
已选/资格同步采用同一账号串行槽与文档CAS，部分已选来源失败不清除旧状态。
首次全量扫描完成前保持`catalog_complete=false`；后续扫描失败保留此前完整资料及明确失败状态。
扫描进度、最近完成时间和失败重试时间随归档持久保存；运行任务不写cache条目，登录后按资料恢复扫描。
当前仍受单文档4MiB存储上限约束，超限明确失败。

权重年级人数保存在settings命名空间的`weight-grade-<term>`文档，账号隔离、CAS保存；旧360值
读取时改为5000。目录课程的market_scan_id与归档completed_scan_id/完成教学班数共同限定模型
使用的最新完整扫描样本；未在该次扫描出现的历史课程仍可查看，但不能充当当前市场或候选。

`weight-applications`按账号与轮次保存手动投权执行清单：规范化目标哈希、学期、官方预算规则、
撤回/重投阶段及每门确认状态。发送前清单已持久化，具体学校写操作继续由selection-attempts账本保护。
清单不保存操作密钥，通用文档接口不能改删。存在未知写操作时不得替换或结束清单；专用结束接口只改
本地阶段，不回退学校操作。配置读取可离线返回未完成原方案，关闭页面、重开接口不丢失进度。
清单项withdraw_only记录“仅撤回原志愿”的零分配目标；它只用于清单执行，不会向学校发送零权重投放。
旧清单缺少该字段时按false读取。恢复接口返回此标记，确认窗口与完成核验保持相同语义。

`jwxk-automation-settings`保存账号/轮次自动化时间与通知偏好，默认值只在读取时补齐，未配置时
不创建文档。PUT保存前严格校验，使用generation与CAS；通用文档PUT禁用，避免绕过间隔和字段约束。
归档名称、学期、模式与SMTP状态属于响应展示数据，不写入该配置，也不接受客户端上传。

`jwxk-automation-tasks`按账号与task_id保存任务草稿、目标、绑定组、状态与执行证据。取消或替换的记录
标记cancelled并从公开列表隐藏，不直接删除未核验操作信息；通用文档接口禁止改删任务。
`SaveBatchForSession`把多文档变更放在同一个SQLite事务中，检查每项revision及账号generation，任一失败
全部回滚。批次最多256项、单项4MiB、合计32MiB，禁止同一命名空间/键重复。任务替换、方案与绑定任务
联动、任务与归档时间同步均使用该事务，避免中断后半更新。

普通抢选任务执行前保存last_attempt_at/next_attempt_at，发送前保存pending_selection与pending_group。
进度使用revision和generation检查，不能以旧会话覆盖方案同步结果；远端结果仍以selection-attempts账本为准。
任务文档只保留规范化课程引用、状态及最近80条结果，不保存secretVal。重启后先核验保留的意图，
未知结果不得重新提交；账号退出取消后台工作，撤销generation也会阻止后续持久化和写入准备。
空位换课另外保存pending_drop/pending_drop_group和swap_results内drop_states/inflight_mutation，
每门退课确认后立即更新；已有低层账本的意图仅核验，无账本的意图重新检查最新空位后才允许执行。
策略任务保存weight_scan_job、weight_application与weight_status中的last_strategy_at/active_window和
已完成最终窗口标记。扫描任务句柄跨进程失效时重新获取完整市场；执行清单跨进程保留，不重新计算
覆盖未完成意图。下一周期仅在完整官方结果已确认原志愿不存在时重置confirmed提交记录，未知记录不重置。

邮件配置整体保存在secrets表的mail-config用途内，沿用AES-GCM及账号/用途关联数据，包含SMTP密码。
保存使用SaveSecretForSession检查enabled与generation；读取API只返回非秘密字段与密码是否存在。
配置按账号隔离，通用文档接口不能访问secrets表。旧全局JSON配置导入仍待迁移，不自动猜测多用户归属。

数据库schema 6新增mail_outbox，按账号/generation/source/dedupe_key唯一约束；包含正文、状态、失败次数、

队列标记cancelled。该表与通用documents分离，不能通过文档API改写发送状态或伪造队列。
