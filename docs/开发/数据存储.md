# 本地数据存储

本文说明持久化数据的分类、位置、权限、清理和升级边界。可重建缓存的算法与并发规范见
[缓存与数据一致性](缓存与数据一致性.md)。

## 1. 数据目录

| 模式 | 默认目录 |
|---|---|
| `development` | 仓库 `data/` |
| `desktop` | `%LOCALAPPDATA%\NEU-JWXT-Toolkit\data` |
| `server` | `/var/lib/neu-jwxt-toolkit` |

`NEU_JWXT_DATA_DIR` 始终优先。业务代码只能从 runtime/共享 Storage 获取可写目录，不能
写冻结资源目录或自行依赖 cwd。Linux 目录权限为 `0700`，敏感文件和 `cache.db` 为
`0600`。

## 2. 数据分类

| 分类 | 当前数据 | 是否可淘汰/重建 |
|---|---|---|
| 可重建缓存 | `cache.db` 中的成绩、单科分项成绩、培养计划、科研训练、四节活动元数据、头像 | 是 |
| 用户状态 | `research_training_favorites.json` | 否 |
| 用户文档 | `成绩/gpa_simulations/<account-hash>/*.json` | 否 |
| 可靠队列 | `grade_tracking_outbox.json` | 否 |
| 追踪状态 | tracking config/state/snapshot | 否 |
| 安全状态 | `session.json`、`credentials.json`、server config | 否 |
| 日志 | `logs/` | 按日志保留策略 |
| 旧缓存 | `scores.csv`、`scores_meta.json`、`academic_report.json`、`research_training_cache.json`、`avatar.png/meta` | 一个兼容周期只读迁移 |

不能仅因为数据是 JSON 就把它注册为缓存。收藏、GPA 方案、追踪配置/outbox、凭据、
Cookie、网站密码和日志永远不能由缓存淘汰策略删除。

## 3. SQLite 缓存

`cache.db` 是运行时可重建缓存唯一真相源。它采用 WAL、busy timeout、每线程短连接和
短事务；网络请求期间不持有数据库事务。主键是
`(account_id, resource, variant)`，保存 payload、Schema、revision、`saved_at`、
`last_checked_at`、`last_attempt_at`、错误类型及依赖 revision。

单科分项成绩使用 `score-details` 资源和由 `course_code + term` 哈希得到的 variant。远端
WID 只作为后端查询引用保存在私密缓存，不进入浏览器、日志、邮件或测试夹具；空详情不得
清除以前成功保存的分项。

四节活动仅在“自动读取并存储”模式下写入 `cache.db`，保存规范化活动元数据、已抓取
详情、解析警告和后端受控证书引用；公开响应始终剔除引用。“每次使用按需读取”模式只在
当前请求/页面内存中持有结果，不读写该缓存。模式偏好属于非敏感浏览器设置，不包含活动
数据。证书打包每次重新抓取；图片和 ZIP 只存在于请求期间的内存或受控临时流，响应结束
即清理。真实 cxcy 页面响应、Cookie 和 CAS 票据不得持久化为业务数据。

证书引用只允许四个分区旧目录或共享
`/static/uploads/res/certificate/{受限ID}/{单层图片文件}`；共享目录拒绝额外路径层级和
非 PNG/JPEG/WebP 文件，查询部分只允许可丢弃的临时时间戳类参数。canonicalization 移除
这些参数，避免同一证书因缓存戳变化制造 revision；公开 API 仍不返回该引用。

用户确认改为“每次使用按需读取”时，应用必须通过后端精确删除当前认证账号的
`festival-activities/default` 缓存。该动作不等同于“清除全部数据”：不得删除当前账号的
成绩、培养计划等资源，不得影响其他账号，也不得扩大到其他 variant。删除失败必须反馈
给用户并保持原模式；只有删除成功后才能保存按需偏好和开始当次读取。重新选择自动模式
后由正常刷新流程重新创建缓存。

业务代码只能通过 `CacheStore`/`CacheCoordinator`/typed adapter 读写缓存：

- 不直接执行缓存 SQL；
- 不用文件 mtime 判断 freshness；
- 不从页面、追踪或 router 写 `scores.csv`；
- 不对同一资源建立另一个 JSON 缓存或定时器。

旧文件首次可信访问时幂等导入。必须先校验账号和旧 Schema，再规范化、计算统一
revision、在 identity guard 内提交，随后标记待远端检查。迁移失败可以继续兼容读取旧
文件并写脱敏诊断，但不能生成半条 SQLite 数据。旧文件不再双写。

## 4. 权威用户数据

### GPA 模拟

GPA 方案按账号哈希目录隔离，文件名使用 basename 限制，临时文件写入、fsync 后
`os.replace`。2.0 保存成绩/培养计划基线 revision 和基础真实成绩，用于三方协调。
旧 1.0 文件只有可信 `exported_by` 与当前账号一致时才复制导入，原文件不修改；没有
owner 的文件不能跨账号放行。

### 科研收藏

收藏以 `(account, batch_id, topic_id)` 隔离，保存最小课题归档。目录缓存更新后用最新
非敏感课题字段刷新收藏归档；换批次后收藏保留并标记过期，取消收藏才删除。导师联系
方式、申请/退回理由不写入目录缓存或收藏。

### 成绩追踪

- config 保存检查时段、SMTP 和 enabled 意图；API 永不回传 SMTP 密码。
- snapshot/state 必须记录 `account_id`，切换账号时清空旧账号个人快照、outbox 和
  revision 去重状态，但保留通用配置及 enabled 意图。
- outbox 是可靠重试状态，不能注册为缓存；`last_notified_revision` 持久保证同一成绩
  revision 最多通知一次。

### 凭据和会话

`credentials.json` 当前仍是用户明确选择“记住登录”后的本地凭据，属于高敏感数据；
`session.json` 保存 CAS/WebVPN 会话。它们不能进入 API 响应、日志、测试夹具或发行包。

## 5. logout、清理和升级

主动退出 NEU 登录时先在统一远端锁内清 Cookie、提升 identity epoch、清活动 client
和凭据，再做本地清理，避免退出间隙被后台恢复。

`clear_data=true`：

- 删除当前账号 SQLite 缓存及事件；
- 删除当前账号科研收藏；
- 删除追踪个人 snapshot/state/outbox；
- 删除旧缓存、头像、Cookie、凭据和恢复状态；
- 保留 GPA 用户文档、追踪配置、日志和 `cache.db` 基础设施文件。

`clear_data=false` 只退出会话并暂停追踪；同账号下次登录可继续使用缓存，切换账号时
追踪个人状态必须重新建立。

Windows 安装升级保留 `%LOCALAPPDATA%`；Linux `install.sh --upgrade` 只替换 `/opt`
并保留 `/etc`、`/var/lib`，健康失败回滚程序但不回滚数据。Release 包不得包含
`cache.db`/WAL/SHM、旧缓存、个人文档、日志、配置、凭据、会话或真实响应。

## 6. 浏览器本地数据

`localStorage` 仅保存列显示、分页等非敏感偏好，以及用户主动保存的 GPA 浏览器副本。
键统一使用 `neu_toolbox:` 前缀。禁止保存密码、Cookie、SMTP 授权码、恢复令牌或教务
完整响应。ResourceProvider 的内存数据是 UI 快照，不是持久化真相。

## 7. 变更检查

- [ ] 先按六类数据确定归属，未把权威状态误当缓存。
- [ ] 账号 scope、Schema、revision、canonicalization、时效和离线策略已登记。
- [ ] 依赖 revision 与 mutation invalidation 已声明。
- [ ] 切号、logout、clear_data 不会串号或被旧 job 回写。
- [ ] 写入原子、权限正确，日志不含 payload/秘密。
- [ ] 旧格式迁移幂等且不修改原用户文档。
- [ ] Windows/Linux 升级保留，发行构建明确排除。
- [ ] 测试覆盖并发、崩溃、账号隔离、迁移、清理和离线。
