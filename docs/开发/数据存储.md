# 本地数据存储

本文描述当前持久化边界。修改前先阅读
[开发接手与变更规范](开发接手与变更规范.md)，尤其是缓存联动、离线和发行排除要求。

## 1. 数据目录

数据目录由 `backend/core/runtime/config.py` 统一决定：

| 运行模式 | 默认目录 |
|---|---|
| `development` | 启动工作目录下的 `data/` |
| `desktop` | `%LOCALAPPDATA%\NEU-JWXT-Toolkit\data` |
| `server` | `/var/lib/neu-jwxt-toolkit` |

`NEU_JWXT_DATA_DIR` 在全部模式下优先。业务代码不得自行用 `cwd`、仓库根目录或冻结
资源目录拼接可写路径，应使用共享 `Storage` 的 `config.data_dir`。

Linux 数据目录为服务用户 `0700`，写出的敏感文件为 `0600`。Windows 依赖当前用户
本地应用数据目录的账户隔离。

## 2. 主要文件

| 文件/目录 | 内容 | 敏感性 |
|---|---|---|
| `scores.csv` | 全部成绩及教务原始字段 | 个人学业数据 |
| `scores_meta.json` | 获取时间、账号、总绩点和来源 | 个人标识 |
| `academic_report.json` | 培养计划、类别和课程状态 | 个人学业数据 |
| `session.json` | CAS/WebVPN Cookie 会话 | 高敏感 |
| `credentials.json` | 选择“记住密码”后的学号和密码 | 高敏感，当前为明文 |
| `avatar.*` / 头像元数据 | 用户头像缓存 | 个人数据 |
| `grade_tracking_config.json` | 检查时段、SMTP 和站点地址 | 含 SMTP 授权码 |
| `grade_tracking_snapshot.json` | 最近成绩快照 | 个人学业数据 |
| `grade_tracking_state.json` | 运行状态和检查时间 | 一般敏感 |
| `grade_tracking_outbox.json` | 等待重试的邮件 | 可能含成绩内容 |
| `成绩/` | GPA 模拟方案 | 个人规划数据 |
| `logs/` | 应用与访问日志 | 必须脱敏 |

文件名以当前实现为准。新增文件时必须加入本表，并检查清理、升级保留、权限、离线和
发行排除。

## 3. 核心类与当前 API

### 3.1 `Storage`

实现：`backend/core/storage/storage.py`

| 方法 | 用途 |
|---|---|
| `save_scores(scores, filename=None, metadata=None)` | 保存 UTF-8 BOM CSV，并可写元数据 |
| `load_scores(filename=None)` | 加载成绩；无文件返回空列表 |
| `load_scores_with_meta(filename=None)` | 返回 `scores / meta / filepath` |
| `export_scores_by_term(term_scores, base_filename="scores")` | 按学期导出 |
| `save_config / load_config` | 通用 JSON 配置 |
| `save_json / load_json` | 指定文件 JSON |
| `save_credentials / load_credentials / clear_credentials` | 记住登录凭据 |
| `save_avatar / load_avatar / clear_avatar` | 头像缓存 |
| `get_last_update_time` | 文件更新时间 |
| `list_files / get_storage_info` | 数据目录信息 |
| `clear_all_data(preserve_config=True)` | 清理业务数据，可保留配置 |

不要在新代码中调用文档历史版本里的 `save_session`、`load_session`、`clear_all`；当前
Session 持久化由认证客户端使用 `session.json` 管理。

成绩 CSV 的 `CSV_FIELDS` 是兼容契约。新增字段时：

1. 追加或有意识地迁移字段，不随意重排/删除；
2. 加载旧 CSV 时为缺失字段提供默认值；
3. 同步 `CourseScore`、在线/离线 Schema、前端和测试；
4. 确认 `raw_data` 不包含不必要的个人或认证信息。

### 3.2 `AcademicStorage`

实现：`backend/core/storage/integration.py`

- `get_scores_smart(auth, force_refresh=False)`：按缓存时效选择本地或远端；远端失败且
  本地存在时返回本地数据和错误信息。
- `refresh_scores(auth)`：强制远端刷新并写共享 `scores.csv`。
- `compare_with_remote(auth)`：比较新增、删除和成绩/绩点变化。

成绩缓存默认时效由代码中的 `CACHE_EXPIRY_HOURS` 定义。修改时效属于用户行为变化，
需要同步成绩功能文档和测试。

### 3.3 `AcademicReportStorage`

培养计划缓存使用 `academic_report.json`，包含：

```json
{
  "schema_version": 2,
  "username": "匿名账号标识",
  "saved_at": "ISO 时间",
  "report": {}
}
```

- `save_report / load_report`：保存或加载版本化缓存。
- `get_report_smart(auth, force_refresh=False)`：无缓存、Schema 版本不匹配、账号不匹配
  或成绩文件更新时刷新；远端失败时可以回退到同账号有效缓存。
- `refresh_report(auth)`：强制刷新，返回明确成功/失败对象。

缓存必须按账号和 Schema 版本校验，不能让不同账号共用旧培养计划。

### 3.4 `AutoLoginManager`

- `try_auto_login()`：优先恢复 Cookie，再使用已保存凭据。
- `save_login(auth)`：保存当前登录信息。
- `clear_login()`：清除凭据和会话。

共享实例在 `backend/app/dependencies.py` 创建。不要在 router 中创建另一份默认存储，
否则可能使用不同运行目录。

## 4. 缓存联动

```text
在线成绩刷新 / 成绩追踪
  → scores.csv + scores_meta.json
  → 成绩页、GPA 模拟读取
  → 成绩变化时培养计划缓存需要刷新

培养计划刷新
  → academic_report.json
  → 培养计划页、GPA 模拟导入、离线培养计划读取

离线模式
  → 只读上述共享缓存
  → 不触发认证或远端请求
```

成绩追踪首次同步或检测到变化时会刷新培养计划。培养计划刷新异常应记录日志，但不能
撤销已经成功的成绩缓存或阻断成绩通知。

## 5. 清理、升级与发行

- `clear_all_data(preserve_config=True)` 会保留凭据和成绩追踪配置，但删除快照、状态、
  待发送邮件及普通业务数据；修改清理逻辑前检查用户预期。
- Windows 重新安装/升级不能删除 `%LOCALAPPDATA%` 中的数据。
- Linux `install.sh --upgrade` 只替换 `/opt` 程序，保留 `/etc` 和 `/var/lib`；失败
  回滚也不能覆盖数据。
- PyInstaller 和 Release 包不得包含仓库 `data/`、`.env`、日志、凭据、Session、
  SMTP 配置、真实响应或 GPA 方案。

## 6. 安全要求

- `credentials.json` 当前为明文密码，只在用户明确选择记住登录时写入；UI 和文档必须
  说明风险，API 不得回传密码。
- `session.json`、SMTP 授权码和恢复令牌按凭据处理，禁止打印或进入异常详情。
- JSON/CSV 写入后调用统一权限函数；不要新建绕过 `secure_file` 的敏感写入路径。
- 文件名若受用户输入影响，必须白名单化并限制在数据目录内，防止路径穿越。
- server 模式的 `/etc/neu-jwxt-toolkit/config.json` 保存网站密码盐/哈希和 Cookie
  签名密钥，属于运行配置，不位于业务数据目录，但同样使用 `0600`。
- 所有数据目录、响应抓包和本地配置均由 `.gitignore` 排除；提交前仍需检查 Git 跟踪
  状态，不能只依赖忽略规则。
