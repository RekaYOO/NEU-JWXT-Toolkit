# 本地数据存储

本文说明持久化数据的分类、位置、权限、清理和升级边界。可重建缓存的算法与并发规范见
[缓存与数据一致性](缓存与数据一致性.md)。

## 1. 数据目录

| 模式 | 默认目录 |
|---|---|
| `development` | 仓库 `data/` |
| `desktop` | `%LOCALAPPDATA%\NEU-JWXT-Toolkit\data` |
| `server` | `/var/lib/neu-jwxt-toolkit` |
| `mobile` | Android 应用内部 `filesDir` 下的数据目录，由本地启动器设置 |

`NEU_JWXT_DATA_DIR` 始终优先。业务代码只能从 runtime/共享 Storage 获取可写目录，不能
写冻结资源目录或自行依赖 cwd。Linux 目录权限为 `0700`，敏感文件和 `cache.db` 为
`0600`。

Android 本地版使用相同的 Storage、CacheStore、CacheCoordinator 和账号隔离规则，仅替换
数据根目录及通知出口。SQLite、会话、凭据和用户文档不得写入 Android `cacheDir`，该目录
仅用于可丢弃的下载中转文件。课程大纲的正文不持久化，但进入页面仍按共享逻辑自动请求
第一页；不能把“不缓存”解释为“仅手动刷新”。原生网络桥不承担业务缓存和认证恢复。

## 2. 数据分类

| 分类 | 当前数据 | 是否可淘汰/重建 |
|---|---|---|
| 可重建缓存 | `cache.db` 中的成绩、单科分项成绩、培养计划、科研训练、四节活动元数据、头像 | 是 |
| 用户状态 | `research_training_favorites.json` | 否 |
| 用户文档 | `成绩/gpa_simulations/<account-hash>/*.json` | 否 |
| 用户归档 | `course_selection_catalog_history.json` 中的账号级选课轮次快照 | 否；仅用户手动删除 |
| 自动任务 | `course_selection_tasks.json` 中账号级选课方案组、运行意图与最小核验状态 | 否；用户暂停、取消或删除 |
| 可靠队列 | `system_mail_outbox.json` | 否 |
| 追踪状态 | `grade_tracking_config.json`、`grade_tracking_state.json`、`grade_tracking_snapshot.json` | 否 |
| 通知配置 | `system_mail_config.json`、`auth_recovery_config.json` | 否 |
| 安全状态 | `session.json`、`credentials.json`、`auth_recovery_state.json`、`auth_recovery_secret.key`、server config | 否 |
| 日志 | `logs/` | 按日志保留策略 |
| 旧缓存 | `scores.csv`、`scores_meta.json`、`academic_report.json`、`research_training_cache.json`、`avatar.png/meta` | 一个兼容周期只读迁移 |

不能仅因为数据是 JSON 就把它注册为缓存。收藏、GPA 方案、追踪配置、系统邮件 outbox、恢复状态、凭据、
Cookie、网站密码和日志永远不能由缓存淘汰策略删除。

## 3. SQLite 缓存

`cache.db` 是运行时可重建缓存唯一真相源。它采用 WAL、busy timeout、每线程短连接和
短事务；网络请求期间不持有数据库事务。主键是
`(account_id, resource, variant)`，保存 payload、Schema、revision、`saved_at`、
`last_checked_at`、`last_attempt_at`、错误类型及依赖 revision。

课程大纲仅保存 `course-outline-metadata` 最小元数据，不保存正文。Schema 2 保留旧条目供显示，
由在线消费者重新核验旧版本或过期数据；失败不覆盖旧值，不需要删除 `cache.db` 或其他个人数据。

单科分项成绩使用 `score-details` 资源和由 `course_code + term` 哈希得到的 variant。远端
WID 只作为后端查询引用保存在私密缓存，不进入浏览器、日志、邮件或测试夹具；空详情不得
清除以前成功保存的分项。总成绩成功刷新或登录恢复后，后端只为缺失或失配的 variant 排队
补全；前端详情页只读缓存。

四节活动仅在“自动读取并存储”模式下写入 `cache.db`，保存规范化活动元数据、已抓取
详情、解析警告和后端受控证书引用；公开响应始终剔除引用。“每次使用按需读取”模式只在
当前请求/页面内存中持有结果，不读写该缓存。模式偏好属于非敏感浏览器设置，不包含活动
数据。证书打包每次重新抓取；图片和 ZIP 只存在于请求期间的内存或受控临时流，响应结束
即清理。真实 cxcy 页面响应、Cookie 和 CAS 票据不得持久化为业务数据。

证书引用只允许四个分区旧目录或共享
`/static/uploads/res/certificate/{受限ID}/{单层图片文件}`；共享目录拒绝额外路径层级和
非 PNG/JPEG/WebP 文件，查询部分只允许可丢弃的临时时间戳类参数。canonicalization 移除
这些参数，避免同一证书因缓存戳变化制造 revision；公开 API 仍不返回该引用。

用户确认改为“每次使用按需读取”时，应用必须通过后端精确删除当前认证账号的
`festival-activities/default` 缓存。该动作不等同于“清除全部数据”：不得删除当前账号的
成绩、培养计划等资源，不得影响其他账号，也不得扩大到其他 variant。删除失败必须反馈
给用户并保持原模式；只有删除成功后才能保存按需偏好和开始当次读取。重新选择自动模式
后由正常刷新流程重新创建缓存。

业务代码只能通过 `CacheStore`/`CacheCoordinator`/typed adapter 读写缓存：

- 不直接执行缓存 SQL；
- 不用文件 mtime 判断 freshness；
- 不从页面、追踪或 router 写 `scores.csv`；
- 不对同一资源建立另一个 JSON 缓存或定时器。

旧文件首次可信访问时幂等导入。必须先校验账号和旧 Schema，再规范化、计算统一
revision、在 identity guard 内提交，随后标记待远端检查。迁移失败可以继续兼容读取旧
文件并写脱敏诊断，但不能生成半条 SQLite 数据。旧文件不再双写。

## 4. 权威用户数据

### 绩点计算策略

`gpa_preferences/<account-sha256>.json` 是按账号隔离的权威配置，不是缓存。`mode` 只接受
`through_2024`、`from_2025` 或 `null`；`null` 按学号前四位自动选择。写入采用同目录临时文件、
fsync、权限限制和原子替换。成绩页、离线读取、模拟器与成绩追踪共用该值，清缓存不应删除。
该目录不得进入发行包、日志或版本控制。

### GPA 模拟

GPA 方案按账号哈希目录隔离，文件名使用 basename 限制，临时文件写入、fsync 后
`os.replace`。2.0 保存成绩/培养计划基线 revision 和基础真实成绩，用于三方协调。
旧 1.0 文件只有可信 `exported_by` 与当前账号一致时才复制导入，原文件不修改；没有
owner 的文件不能跨账号放行。

### 科研收藏

收藏以 `(account, batch_id, topic_id)` 隔离，保存最小课题归档。目录缓存更新后用最新
非敏感课题字段刷新收藏归档；换批次后收藏保留并标记过期，取消收藏才删除。导师联系
方式、申请/退回理由不写入目录缓存或收藏。

### 选课轮次课程归档

JWXK 课程目录实时读取，但用户浏览过的教学班会按账号与轮次合并进
`course_selection_catalog_history.json`。归档只保存规范化课程、教学班、时间、容量、匿名人数、
官方可选性和脱敏原因；禁止保存 `secretVal`、Authorization、Cookie、学号响应行或完整远端响应。

该文件是用户要求长期保留的历史资料，不注册进 CacheRegistry，也不按 freshness 淘汰。轮次结束前
进入轮次后，后台按该轮次真实课程类型扫描全部分页；可见页面无需等待扫描完成。轮次结束前
10 分钟内，后台对已确认可选且已归档的课程重新读取一次人数；结束后标记为历史备份。程序未在
结束窗口运行时保留最后一次可信数据并标明未完成最终刷新。归档按账号隔离，只能由用户在选课页面
逐轮次删除。

### 选课自动任务

`course_selection_tasks.json` 保存用户明确创建并启动的方案组、候选优先级、目标门数、运行意图、
轮询模式和最小提交核验标记。实时策略投权任务还保存年级人数、课程意愿、最近模型建议、
最近计算/调整时间，以及退选和重投两阶段的待核验状态。它不是缓存，程序重启后不能按 freshness 淘汰；仅当
`desired_state=running` 时恢复执行，并且必须先读取官方已选结果核验。每次远端写请求前原子保存
`inflight_mutation`，若进程或登录在写入期间中断，重启后只能核验官方结果，不能盲目重放。

任务文件禁止保存 `secretVal`、Authorization、Cookie、账号密码或完整远端响应。登录恢复继续
使用共享 `AuthSessionManager + NEUAuthClient`；账号不匹配时任务保持等待，不能在另一账号下执行。

策略模型使用的年级人数按“账号 + 学期”保存在普通配置中的
`course_selection_weight_grade_sizes`，属于用户策略配置而非远端缓存；切换账号或学期不会复用。

### 成绩追踪

- `grade_tracking_config.json` 只保存 enabled 意图、检查间隔和每日时段，不再保存 SMTP 或
  重新登录地址。
- snapshot/state 必须记录 `account_id`，切换账号时清空旧账号个人快照和 revision 去重状态，
  但保留通用检查配置及 enabled 意图。
- `last_notified_revision` 持久保证同一成绩 revision 最多通知一次；邮件投递状态不写回恢复 Flow。

### 系统邮件与远程认证恢复

- `system_mail_config.json` 保存全系统唯一 SMTP 通道；API 永不回传 `smtp_password`，只返回
  `smtp_password_configured`。成绩追踪与自动选课使用不同 source 和去重键，但共享发送线程。
- `system_mail_outbox.json` 是可靠重试队列，只保存普通邮件正文，或恢复邮件的上下文 ID 与模板。
  恢复 URL 中的明文 token 在真正发送前动态生成，不写入 outbox。
- `auth_recovery_config.json` 保存 `public_base_url` 和 `link_ttl_hours`（默认 3，范围 1–168 小时）；
  `auth_recovery_state.json` 保存账号、业务来源、`primary|jwxk` 目标、上下文 ID、token 哈希、
  创建时间、固定截止时间 `expires_at`、去重键和状态。旧链接按原创建时间加 3 小时补齐截止时间，
  不因升级或重启续期。终态记录最多保留最近 30 天，且总历史有界；未到期上下文不会因历史清理被删除。
- `auth_recovery_secret.key` 是恢复 URL 的 HMAC 密钥。二维码、图形验证码、短信验证码、Cookie、
  完整表单和候选 Session 只存在于进程内存，不得出现在任何上述文件中。
- 升级时从 `grade_tracking_config.json` 幂等迁移 SMTP 与 `site_url`，从旧
  `grade_tracking_outbox.json` 保留普通成绩/选课邮件并丢弃旧恢复路径邮件；旧文件不再作为运行时
  发送队列。旧恢复链接不兼容。

### 凭据和会话

`credentials.json` 当前仍是用户明确选择“记住登录”后的本地凭据，属于高敏感数据；
`session.json` 保存 CAS/WebVPN 会话。它们不能进入 API 响应、日志、测试夹具或发行包。

## 5. logout、清理和升级

主动退出 NEU 登录时先在统一远端锁内清 Cookie、提升 identity epoch、清活动 client
和凭据，再做本地清理，避免退出间隙被后台恢复。

`clear_data=true`：

- 删除当前账号 SQLite 缓存及事件；
- 删除当前账号科研收藏；
- 删除追踪个人 snapshot/state、系统邮件 outbox 和认证恢复上下文；
- 删除旧缓存、头像、Cookie 和凭据；
- 保留 GPA 用户文档、追踪检查配置、系统 SMTP 配置、远程恢复站点地址、恢复 URL 签名密钥、日志和 `cache.db` 基础设施文件。
- 保留选课轮次课程归档；它属于用户主动保留的资料，只能在对应页面手动删除。

`clear_data=false` 退出会话、暂停追踪并立即使现有恢复上下文/链接失效，但保留系统邮件配置、
outbox 中的普通业务通知和缓存；同账号下次登录可继续使用缓存，切换账号时追踪个人状态必须重新建立。

Windows 安装升级保留 `%LOCALAPPDATA%`；Linux `install.sh --upgrade` 只替换 `/opt`
并保留 `/etc`、`/var/lib`，健康失败回滚程序但不回滚数据。Release 包不得包含
`cache.db`/WAL/SHM、旧缓存、个人文档、日志、配置、凭据、会话或真实响应。
`course_selection_catalog_history.json` 同样不得进入发行包。

## 6. 浏览器本地数据

`localStorage` 仅保存列显示、分页等非敏感偏好，以及用户主动保存的 GPA 浏览器副本。
键统一使用 `neu_toolbox:` 前缀。禁止保存密码、Cookie、SMTP 授权码、恢复令牌或教务
完整响应。ResourceProvider 的内存数据是 UI 快照，不是持久化真相。

个人课表和头像是允许的浏览器业务快照：`frontend/src/resources/BrowserTimetableStore.js`
使用版本化 IndexedDB 保存在线身份确认后的当前/下一学期规范化课表、学期索引和单个头像
BLOB。它按账号命名空间隔离，最多保留两个学期；不保存选课叠加、临时预览、冲突结果、班级/
教师/教室结果或任何认证材料。浏览器镜像只能由服务器确认的课表/头像响应写入，不能回写
`cache.db`，也不改变显式离线模式的能力范围。用户可在设置中分别清除课表或头像镜像。

前端内置的多校区 12 节作息是随静态资源发布的版本化显示常量，不是用户数据或缓存记录。
解析时生成的节次时间只存在于 React 派生状态，不写入 IndexedDB，也不修改已保存的官方课表
快照；因此清除本机课表缓存与更新内置作息互不依赖。

## 7. 变更检查

- [ ] 先按六类数据确定归属，未把权威状态误当缓存。
- [ ] 账号 scope、Schema、revision、canonicalization、时效和离线策略已登记。
- [ ] 依赖 revision 与 mutation invalidation 已声明。
- [ ] 切号、logout、clear_data 不会串号或被旧 job 回写。
- [ ] 写入原子、权限正确，日志不含 payload/秘密。
- [ ] 旧格式迁移幂等且不修改原用户文档。
- [ ] Windows/Linux 升级保留，发行构建明确排除。
- [ ] 测试覆盖并发、崩溃、账号隔离、迁移、清理和离线。
