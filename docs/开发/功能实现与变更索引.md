# 功能实现与变更索引

旧版 `schedule_gpa_context` 对应 Go 的 `queuePolicyContext`。保存 GPA 规则、登录时处理已有成绩缓存、成绩刷新完成时均可触发。`missingPolicyCodes` 从成绩和缓存筛出缺少分制的课程并去重。资源调度器按账号与会话代次复用任务。`TestMissingPolicyCodesOnlyRequestsUnresolvedCoursesOnce` 覆盖课程筛选。

选课工作台向 `TimetablePage` 传入轮次学期、叠加课程和冲突结果。详情使用的 `conflictCourseScheduleMap` 和 `effectiveConflictMap` 与课表卡片共用学期判断，避免同课程号在另一学期的详情中引用本轮次安排。

成绩追踪邮件分两处验收。`TestTrackingActivationQueueDeliveryAndReenable` 检查初始通知入队、去重和消息内容。`TestMailSMTPDeliveryAndRequiredTLS` 用回环 SMTP 接收消息，按邮件客户端的方式解码中文主题、纯文本和 HTML，核对收件人及正文，并验证要求 STARTTLS 时遇到明文服务会停止投递。

`TestGPAConcurrentEditsPreserveWinningCourses` 同时提交同一账号同一版本的两份不同方案。两个请求分别返回成功和版本冲突，重新读取时核对了成功写入的课程和递增一次的版本标记。

空闲教室用例 `TestRoomScanLimitResumeAndNoRepeatedRoomFetch` 先扫描占用教室，再模拟下一间教室查询失败，最后使用原游标重试。核对失败时返回错误，重试成功后仅新增一间空闲教室。

成绩接口用例 `TestScoresPolicyAndCachedReportHTTP` 用四门课程区分两套年级规则。2025 级默认策略的绩点为 16/6，切换至旧策略后为 30/9，两种模式的学期课程总学分均为 9。

日程删除与重连由两个专项测试覆盖。`TestAgendaSurvivesReopenAndRejectsStaleWriter` 验证服务端删除后拒绝旧版本并保留空日程。`TimetablePage.query.test.js` 的 `weekly day headings` 用例验证离线期间暂停读取，重连后重新读取并显示最新日程，保存请求次数保持为一次。

历史选课导出位于 `CourseSelectionArchivePage`，数据取自当前账号的轮次详情响应。切换归档时清空旧详情及课表预览。导出保存整份归档，移动客户端交给 `saveNativeFile`。

GPA 方案读取接口返回的 `ETag` 可原样传给删除接口的 `If-Match`。旧页面发送的数字版本号继续有效。`TestGPAPlansWithSameFilenameRemainAccountScoped` 覆盖双账号同名保存、重命名隔离和使用读取版本删除，旧数字格式由 `TestGPAFilesRoundTripAtomicRenameAndConflict` 覆盖。

考试浏览器验收通过 `tools/fixtures/exam_calendar` 调用 Go 的 `ExamsCalendar` 生成模拟接口的响应。`QA_GO` 可指定 Go 程序路径，`QA_CALENDAR_OUTPUT` 可保留浏览器下载的 ICS，用于独立日历客户端验收。

`node tools/check_exams.cjs` 从 `QA_FRONTEND_BUILD` 指定的网页目录运行移动和桌面 Chrome 验收。RC26 Windows ZIP 解压网页在 375 和 1440 像素宽度通过正常学期、空学期、失败和恢复后的文件下载检查。接口使用模拟数据，下载检查比对文件名和文件内容。

考试页面 `ExamPage` 按所选学期重新加载，查询开始时清空卡片和统计，导出随考试列表清空而禁用。切换或离开页面会使旧查询失效。

考试明细协议回归：`TestExamDetailsDistinguishEmptyFromFailure` 在学期查询成功后分别模拟合法空明细、错误明细类型和学校失败码，只有合法空数组返回空列表，其余必须返回错误。与 `TestExamCalendarUTCStableIdentityAndSafeText` 一起运行可检查状态读取与 ICS 生成，不代表真实日历客户端已完成导入。

日程持久化回归 `TestAgendaSurvivesReopenAndRejectsStaleWriter`：通过日程专用接口保存一项个人日程和一条调休，在关闭并重新打开同一数据库后用合成账号重新登录，过期修订号的清空请求被拒绝（409），读回的完整响应与保存时一致。该项是 Go 应用层测试，不是发行包的进程重启测试。

`tools/check_selection_preview_detail.cjs` 还验证嵌入选课详情的大纲标签：进入、切回课程详情、再次进入，每次断言同一课程的概览和三组分段均呈现本次响应内容。RC25 Windows 包在五种宽度通过，区别于培养方案摘要的缓存回归。

选课预览包内回归入口为 `tools/check_selection_preview_detail.cjs`。模拟学期覆盖第 13 周第 7 至 8 节实验；窄屏通过嵌入课表的教学周选择条切周，桌面使用全学期视图。分别断言实验时间写入方案、对应课表项可见、未发起正式选退课请求。RC25 Windows 包在五种宽度通过。

教务证明：RC24 的生成失败分支会向浏览器抛出未处理的异步错误。工作区修复后 `tools/check_documents.cjs` 在 320/375/768/1440px 验证取消不生成、隔离 HTML 预览、失败提示和重新确认后下载，PDF 名称与传输字节与模拟响应一致。未验证真实学校文件，RC24 归档未包含修复。

`tools/check_desktop_install_ui.cjs` 在两轮安装前分别向临时 ZIP 追加一个字节，检查页面失败提示、下载任务状态和启动版本标记，再恢复正确包确认可重试。RC24 实测通过，发行归档本身未被修改。

RC24 Windows 网页安装回归：`tools/check_desktop_install_ui.cjs` 两轮先取消再确认。取消后任务仍为 `downloaded`，首次未创建版本选择标记，第二次原标记未变；确认后从原入口重启到 2.2.4，手动回退仍保留站点主题。初始版本号为模拟值，未覆盖公网下载或历史二进制升级。

Windows 发行验收 `tools/check_go_release.py <发行目录> --smoke` 需要将 Go 加入 PATH。它将已校验的 ZIP、摘要及版本交给 `TestWindowsReleaseSwitchFromArchive`；未匹配、跳过或失败均不记为通过。成功记录在 `verification.json` 的 `smoke.windows_archive_upgrade`。

候选包 24 的离线 Debian 虚拟机检查可附加 `--docker-bases <基础镜像归档>`。Docker 28.5.2 使用 overlay2 成功载入 `debian:bookworm-slim`、`node:22-bookworm-slim`、`golang:1.24-bookworm`，逐一检查平台为 linux/amd64。此后使用发行包导入的测试镜像通过容器重建与原凭据登录检查。来宾系统使用临时快照，结束后不保留已载入的镜像；缓存归档可复用。此结果不包含正式多阶段 Dockerfile 构建。

Docker 离线运行回归：`tools/check_debian_service.py` 的可选 `--docker-engine <Linux 静态工具包>` 分支在临时快照内运行 `tools/check_docker_guest.sh`。用发行归档导入测试镜像后删除并重建容器，验证命名卷中的双重准入凭据仍有效。该项只补充容器运行证据，不能替代正式 Dockerfile 与 Compose 的测试。

`tools/check_debian_service.py` 使用 Debian 12 nocloud 镜像、临时磁盘快照与只读归档，在无网卡虚拟机中通过串口运行包内 systemd 服务。分支工作流 `debian-reboot` 安装当前构建的归档，移除初始化密码，重启来宾系统并比对两次启动标识。它检查开机自启、服务健康、原站点及管理员密码、普通会话访问管理员接口的权限。[首次整机重启验收记录](https://github.com/RekaYOO/NEU-JWXT-Toolkit/actions/runs/45229370841)

统一候选包 `03a9c8c` 与上述验收版本 `8c17e1e` 的 Linux 压缩包摘要不同。逐项核对两个归档的 347 个条目后，路径、权限及每个普通文件的 SHA-256 均一致，其中包括实际运行的 `toolbox` 和 systemd 服务配置。

`debian-reboot` 还在同一来宾磁盘上分两次启动应用层测试进程。重启前为合成账号保留一次结果未知的抢课请求。重启后登录同一账号，测试只轮询持久化任务状态，由正常的后台调度器读取模拟学校的已选结果。验收要求任务成功、待核验标记清空且恢复阶段提交次数为零。[后台自动接续验收记录](https://github.com/RekaYOO/NEU-JWXT-Toolkit/actions/runs/45233281448)

科研收藏旧资料迁移：候选包 22 Windows 的 `legacy_favorite_ownership_and_privacy` 检查从双账号旧文件预览并执行指定账号的导入，直接读取新库，核对只产生一条该账号的收藏、课题编号和标题正确，快照不含联系方式、电话、邮箱、申请理由及拒绝理由。原文件字节未改变。此项扩展发行验证，不改变现有产品行为。

`tools/check_linux_guest.sh` 使用专用 `neu-toolbox` 用户与组启动候选包；检查服务进程有效 UID、数据目录和两个私有文件的所有者及模式。候选包 22 在 Alpine 下实测数据目录 `0700`、`toolbox.db` 与 `vault.key` 均为 `0600`，UID/GID 均为 10001，移除初始化密码后仍可重启并重新登录。此检查未启用 systemd 的服务隔离设置。

发行文本的换行不依赖构建主机：`tools/build_go_release.py` 显式生成 LF 版本文件、LF Linux 服务单元及 CRLF Windows 启动脚本；`tools/check_go_release.py` 对归档内容检查。候选包 22 已通过两平台归档检查；未改变业务页面或认证流程。

Linux 归档的虚拟机检查还会在同一次开机期间启动第二个进程：清除两项初始化密码环境变量后，使用原密码重新取得网站与管理员会话，并核对普通会话无法读取管理列表。数据目录位于内存文件系统，覆盖进程重启，不覆盖整机重启。

`tools/check_linux_guest.sh` 为临时 Linux 虚拟机的启动检查脚本，作为 PID 1 的 shell 脚本运行，结束时关闭虚拟机，不应在宿主机直接执行。候选包 21 已在 QEMU/Alpine 内完成服务启动、首页、匿名访问限制和 SIGTERM 检查；这与下述 systemd 工作流是两项不同的验收。

`tools/check_release_https.cjs` 在 Chrome 上检查 Windows RC24 服务端：按 Android 首次检测的约束，不带 Cookie 且不跟随重定向访问 `/api/health`，断言移动协议版本为 1。测试使用隔离数据与临时证书，不覆盖 Android 平台证书信任或原生请求。

原生客户端的 `TrustedServerTest` 通过设置界面触发真实 OkHttp 健康探测，再关闭和重开 Activity 核对地址；需要显式传入 `toolboxHttpsOrigin`，运行方式见 [Android 安装与运行](../部署/Android安装.md)。未提供地址时跳过，不能据此核销真机验收。

`.github/workflows/android-client-check.yml` 在重构分支更新前端、Android 打包配置或版本时自动运行，也支持手动运行。单元测试、lint、客户端调试包和设备测试包使用同一提交，APK 在 Actions 中保留七天。实际设备安装与 HTTPS 连接需另行验证。

Docker 部署验收入口为 `.github/workflows/go-platform-check.yml` 的 `docker-runtime`。首启及移除初始化密码后重建容器，均以新 Cookie 会话核对普通准入成功、普通会话读取管理列表被拒、管理员二次登录后可读取列表。本机仅通过该步骤的 Bash 语法检查，尚无容器执行结果；本项仅改变验证方式，不改变产品行为。

`tools/check_appearance.cjs` 在 Chrome 的 320、375、430、768、1440 像素视口对生产网页执行 Tab 导航，以 Enter 预览樱空模板、以空格取消，检查品牌色恢复且模拟账号设置版本不变。候选包 19 后新增焦点截图取样：比较两个按钮上边缘焦点轮廓与外侧背景，要求至少 3:1。320 像素下预览按钮修复前仅 1.57:1；主题设置按钮使用主题文字色绘制 3 像素焦点轮廓后五种宽度通过。该检查不能替代其他页面、任意自定义主题或 Android 软键盘验收。

Windows 跨候选构建回滚实测：`TestDesktopStartupFailureRestoresAndRelaunches` 使用 `TOOLBOX_ROLLBACK_NEW_ZIP` 指定候选包 19、`TOOLBOX_ROLLBACK_OLD_ZIP` 指定候选包 18，从各自 ZIP 取出实际可执行文件。故意缺失新版静态清单后，验证启动器重新选中 18 的同级目录、该程序健康启动且测试账号保留。根启动器取自当前源码，健康检查的版本标签为测试值，两包实际版本均为 2.2.4；这不是历史正式版本或跨数据库格式的迁移测试。

数据库还原成功后，撤销本次快照登记并清理已用的数据库和密钥副本。旧版本继续使用期间产生的数据不能被早先的快照覆盖。`TestUpgradeCheckpointSurvivesRetry` 在回滚后新增账号，再次选择同一候选版本，验证新登记的快照包含该账号；未完成还原前仍保留原登记。

候选包 18 后的源码已将数据库还原接入 Windows 本地首次启动的正常错误退出：在数据库关闭后、进程锁释放前还原未确认快照，成功才返回专用退出状态 78；根启动器核对当前选择后切回上次安装或根程序。`TestDesktopStartupFailureRestoresAndRelaunches` 用当前编译的 Windows 可执行文件模拟两个版本目录，使候选程序缺少静态清单，验证自动启动根程序、健康接口返回原版本号、测试账号仍可读取。此测试不覆盖强杀、断电或不同历史二进制版本的兼容性。下方先前阶段中“尚未接入”的记录是历史状态。

`restoreUpgradeCheckpoint` 取得数据目录锁后，核对候选版本快照、当前密钥及 SQLite 日志状态，准备并验证数据库副本后替换已关闭的数据库。已确认健康的版本不能使用此路径。`TestUpgradeCheckpointSurvivesRetry` 验证还原后升级前账号存在、快照后新增账号不存在。此步骤尚未接入启动器的失败退出分支，不能代表自动重启上一版本成功。

候选桌面版本确认升级快照之前，`upgradeStartupGate` 仅放行 `GET /api/health`；其他 HTTP 请求返回 503 且不执行对应处理器。启动器通过 `NewInactiveAPI` 注册路由而不启动选课调度或邮件发送。存在快照时，健康检查通过后先从本地库恢复账号，再确认快照，最后启动调度器并开放业务请求。确认失败时关闭服务并退出。`TestUpgradeStartupGate` 检查业务请求调用次数，`TestUpgradeCheckpointSurvivesRetry` 覆盖错误版本不恢复账号、本地恢复失败保留快照。这不代表已接通数据自动还原。

候选包 18 之后：已选中的 Windows 本地单用户版本在取得数据目录进程锁后、打开已有数据库前登记本地升级快照。启动 HTTP 服务后，回环健康接口返回 Go 后端及预期版本才确认此次升级并清理快照。`TestUpgradeCheckpointSurvivesRetry` 使用临时数据库和测试 HTTP 服务验证错误版本保留快照、正确版本清理，同一版本后续不重复创建。根程序、空库和初始化命令不创建快照。首次启动失败后的还原尚未接通。

`CreateUpgradeSnapshot` 在指定父目录创建独立的本地快照，用只读 SQLite 连接取得数据库副本，复制配套密钥并校验副本内已有密文，不运行迁移。`CheckUpgrade` 复用此步骤，但只迁移自己的临时副本并在退出时清理。`TestBackupDirectoryLeavesSourceVersionUnchanged` 验证保留快照的数据库版本仍为 1。快照含数据库和密钥，不能作为可分发的加密备份；Windows 启动器尚未将其用作首次启动失败后的自动恢复点。

候选包 18 之后：Windows 安装器切换到新目录前，将原选中的同级版本名保存在新目录旁的 `.previous` 文件。当前版本无法通过版本探测时，`launch` 优先尝试上一次选择，再回根程序。`TestWindowsReleaseSwitchFromArchive` 用当前源码启动器连续安装同一份候选包 18 ZIP，依次移除两个临时安装的可执行文件，验证两级回退的版本输出。这不验证已迁移数据库的降级兼容，也不等同于运行中崩溃后的数据恢复。

候选包 17 之后，Windows 网页安装将运行服务的实际数据目录传给候选程序 `check-upgrade`：以只读连接对 SQLite 执行 `VACUUM INTO`，在临时目录用密钥副本走新版 `store.Open`，结束后清理副本。候选程序退出成功且返回预期标记后，安装器才更新启动选择。命令行 `install-update` 可显式指定 `-check-data`。`TestReleaseDataProbeUsesCandidateExecutable` 使用实际 Windows 子进程验证可读及缺失的源库；存储层用例覆盖旧结构可迁移、冲突结构失败、源库版本不变。这不是首次启动失败后的数据回滚。

## 版本识别与跨平台更新

- 统一版本来源：根目录 `VERSION`；Android 覆盖安装顺序使用 `ANDROID_VERSION_CODE`。
- Release 资产清单：`.github/workflows/release.yml` 生成 `release-manifest.json`，并与
  `SHA256SUMS.txt` 一起发布。
- 后端检查/下载：`backend/core/runtime/updates.py` 与 `backend/app/routers/runtime.py`；
  设置页入口为 `frontend/src/components/VersionUpdateCard.js`。
- Linux 服务自动升级：数据目录 staging 后由 `packaging/linux/neu-jwxt-toolkit-updater.path`
  的 `PathExists` 触发 root-owned helper；helper 加锁并原子移走 `request.env` 后才执行，
  重启监听器可拾取未认领请求，但失败或重启不自动重复安装。最终复用 `install.sh --upgrade`
  的配置保留和健康失败回滚。
- Android 客户端/本地版：`packaging/android/shared/.../AppUpdateManager.java`，只访问官方
  GitHub、校验 SHA-256，再通过 FileProvider 拉起系统安装器。
- 客户端版系统设置同时读取手机客户端 Release 和连接服务端的 `/api/runtime/update`；两条链路
  必须由用户分别触发检查/下载，不能在进入设置页或启动客户端时自动检查或下载。服务端更新仍复用
  远端 Linux 的 staging、watcher 和回滚状态。
- 服务端任务进度和阶段历史由 `updates.py` 原子写入数据目录 `updates/update-status.json`；
  root 更新器通过 `update-result.env` 回报安装中、完成或失败及阶段原因，任务 ID 必须匹配才合并。
  `VersionUpdateCard` 在 APP 客户端与浏览器显示同一历史，提交下载不等于升级成功。后台请求超时、
  更新器未接管或安装过久应显示失败并允许用户重新手动尝试；旧任务结果不能覆盖新任务。
  下载的瞬时网络故障及包内容不完整最多自动重试三次，每次清理部分文件；校验通过才提交
  安装请求。安装、回滚或远端业务写操作不在此重试范围内。
  自动升级能力需确认 path 单元正在运行，而非仅检查单元文件存在。定向验证入口：
  `backend/tests/test_runtime_updates.py`、`frontend/src/components/VersionUpdateCard.test.js`。
- 修改版本、发行文件名或安装权限时，需要同时核对发行与 CI、Linux/Android/Windows 部署说明、
  系统设置页面、原生桥和对应测试；不应把更新下载与业务缓存预热或认证恢复混在一起。
- `VersionUpdateCard` 将版本信息按“状态、当前/最新版本、任务状态、主操作、Release 链接、说明”分层；
  手机端操作按钮纵向排列并允许自然换行，不能把多个版本源压成一行。

本文面向开发接手和修改，不是用户说明书。用户操作、页面文案和功能边界以 `docs/功能/`
下的对应说明为准；本文只记录接手时需要定位的实现入口、容易遗漏的特殊情况、联动影响和验证入口。

### 当前行为与容易遗漏的特殊情况

- 从其他页面重新进入个人周课表时默认当前学期本周；显式学期/周次链接和学期视图不受影响。
  ResourceStore 内存、浏览器快照、服务器启动缓存和学期接口先后到达时，不能重新应用上次保存的周次/学期，
  也不能覆盖用户进入页面后的手动选择。
- 手机当前周的默认星期使用本机日期，即使当天无课；日期变更、窗口重新聚焦或后台恢复时同步更新
  星期选择、今天标记和课情摘要。异步确认当前学期后须重新校正；手动换日及浏览其他周次不应被抢回。
- 实时高亮同时核对当前学期、当前教学周和实际显示的周次。`TimetableGrid`、`MobileTimetable`、
  缩略/选课紧凑网格及额外日程卡沿调用链传递 `weekNumber`；周视图未确认周次时不高亮。
  `isCourseHappeningNow` 的展示调用携带 `viewMode/weekNumber`，不能仅用课程本身含当前周判断，
  否则每周重复课程会在预览其他周时也高亮；手动日程另核对 `agenda_date`。
  手机网格的 `is-selected-day` 仅表示选日导航，不复用 `is-today` 和今天列背景。
  当前学期的学期总览保留实时高亮，顶部课情摘要不跟随预览周；时间核对不得引发数据请求或抢回选周。
- 手机按日周视图的手势监听在 `MobileTimetable` 外层，空课日也要为课表区域保留足够的
  触摸高度；不能只让有课程卡的部分响应左右滑动。缩略周视图滑动切周、缩略学期视图不切周。
  顶栏摘要只在按钮内处理触摸高亮，展开设置保持单层浮层；周卡片只按周名和日期两行
  决定高度，“本周”位于右上边框并借卡片间隙避免与周名重叠，不得再为角标增加卡片
  顶部内边距或空白行。轨道仅留容纳角标与选中位移的裁剪边距。
  轨道与上方控件保持对齐。
- 父页日期计时器只在本机日期变化时更新，课情摘要、网格和手机课程卡的时间计时器仅在显示分钟变化时
  更新；两者均不触发课表请求或清空已挂载结果。手动切周（含桌面滚轮和手机滑动）关闭当前页面的
  手机选日自动跟随；跨日后只在尚未手动浏览且原本跟随本周时自动换周/换日，重新进入页面才重置此状态。
- 桌面周选择框用原生非被动滚轮监听避免页面同步滚动，按升序周次有边界切换；仅个人课表手机悬浮窗
  的课程信息可点击，按周日到周六及课程结束时间查找下一次课，普通周视图切周和星期、学期视图只切星期、
  缩略周视图只切周、缩略学期视图只收起。其他查询模式的课程信息为静态内容，不显示定位箭头。
  摘要自身的时钟应随时间和页面恢复更新，不能只依赖日期变更。
- 周内顺序为周日到周六；范围判断使用包含式重叠。
- 教学周选项可能包含“（本周）”和日期范围等长文本；中等宽度下操作按钮必须独立成行，选择器文本只能省略，不能覆盖冲突检测或刷新按钮。
- 特殊空闲筛选先限定普通筛选候选，再逐教室扫描并本地核验；继续查找不能重复扫描。
  默认周次只在初始条件尚未填写时设定，跨日或当前周变化不能清除已填写条件和扫描结果。
- 扫描结果与请求条件、游标、已检查教室标识同存于当前页面会话；选中候选教室时暂停扫描，重开筛选
  恢复候选且不运行普通目录预览。续查沿用首次扫描的搜索词、校区及条件，不取课表查看过程中改变的
  页面状态；主动修改筛选条件或切换学期/模式时才废弃旧扫描。
- 无法解析时间的课程不能误判为空闲；结果增量显示，暂停和扫描完成要区分。
- 个人课表优先显示旧快照，刷新失败不能伪装成无课；认证错误不能包装成普通课表错误。
- `backend/core/timetable/api.py` 对个人课表及其周次/校区/节次请求记录端点、查询指纹、
  学校响应指纹及原始安排数量；统一 coordinator 将其关联到同一 `job_id` 并记录提交变化字段。

- 课表业务内容投影由 `backend/core/cache/resources.py::personal_timetable_revision_payload`

  课程状态、教师、时间、地点、性质、考核与详情。只改展示排序不产生内容变化；原字段仍保存在 payload。

  算法不匹配只由 coordinator 标记过期，不能让升级前的可读课表消失。
  变更摘要复用相同内容投影并以当前显示范围为输入，不能在有一门真实变化时混入颜色或 ID 抖动。
- 课表内容签名相同（只变 revision 或顺序）不弹更新窗口；后台刷新先按当前显示的学期、校区、周次
  和视图过滤比较，只有会影响前台课程的差异才在原确认弹窗展示实际增删、地点/时间等变更和相关
  官方未读消息。其他周次或其他校区的变更直接静默合入完整快照，不改变用户正在浏览的范围。
  消息稍后到达只更新弹窗内容，不使 `offerPersonalPayloadUpdate` 变为新回调、不触发课表重读；
  单独消息在课表页面内显示独立的非阻塞通知，不升级为全局弹窗。
  确认/暂缓后只在当前会话记住弹窗展示过的消息，不写官方状态；其他课表模式不使用此弹窗。
- 系统消息两个分页标签独立读取，单个标签失败时保留另一标签；两者都失败只记录资源错误，
  不清空已有缓存。消息列表接口不标记已读，不携带写操作。
- 消息分类由 `frontend/src/utils/systemMessageSummary.js` 统一维护：培养计划和个人课表
  融入各自原有的差异确认弹窗；实验选课、考务管理仍由页面级 `SystemMessageNotice`
  提示，不升级为全局通知。`systemMessagePrompt.js` 按账号和官方 ID 记录当前会话的用户
  确认；官方已读不提示，确认后切页不再反复提示，内容变化的未读消息可重新提示。
  前端确认记录同时写入当前标签页 `sessionStorage`，避免异步页面重新挂载后同一条官方未读消息重复弹出；
  内容指纹变化时仍会重新提示。
  用户确认后由 `POST /api/system-messages/read` 逐条调用提醒/审核消息对应的官方
  `updateReadAndGetMessage.do`，写入走 `require_mutation_auth` 独占认证边界，不自动重试；
  单条失败不阻塞页面，其余消息仍继续同步；官方成功的消息会同步写回本地
  `system-messages` 缓存，避免旧的 `read: false` 快照在切页后再次触发提示。
  消息缓存分类保留近 30 天已读消息，未读消息不因时间过旧自动隐藏；读取失败不改变业务页面状态。

  教务格式的旧值不会发送到课表接口。切页期间的旧请求结果也不能覆盖新页面；FastAPI 422 校验详情需保留
  字段路径和具体原因，不能只显示 Axios 默认英文。
- 周视图星期标题打开准确日期的日程弹窗；手机按日周视图复用 Segmented 星期标题，未选日只选日，
  再点已选日才打开，可重开，不设按钮或快速双击时间限制。捕获阶段仅处理标签转发的 radio 点击，
  在 onChange 更新选日前判断原选日，避免首次选日误开或重复打开；Enter/空格打开当前选日，
  方向键及滑动仍只导航，学期视图仍只选日。空周可添加日程，但未识别日期、
  学期视图和选课嵌入视图不开放。只有个人课表编辑，其他模式查看对象课程，不混入个人日程。

  使旧请求失效。写入携带 revision，冲突返回 409 并重新读取，不盲目重放保存。

  避免切换日程时选填字段串值。更新保留原 ID，删除按 ID 精确移除；取消/保存失败不改变已保存文档，失败可重试。

  编辑/删除始终针对原始事件 ID，不为每次出现复制管理记录。复用 `MobileUX.useIsMobile` 的 md 断点，
  小于 768px 的布局不启用拖动选区（包括电脑窗口及 DevTools 手机比例的 mouse 输入）；
  触摸和笔输入始终保留原生上下滚动；只有桌面宽度的 mouse 输入启用拖动。
  按下时不能由网格父容器捕获指针，否则浏览器会把按钮的点击重定向给父容器，导致点击无效；
  仅桌面鼠标移动超过拖动阈值后捕获，未开始拖动就离开网格时清理状态。
  布局变化时清理进行中的手势和连击状态，保留点击范围起点、已选内容及表单草稿；
  布局断点与 pointerType 共同控制拖动权限，不根据 UA 判断，任何宽度均须支持完整鼠标点击。
  双击同时支持原生 click detail 和触屏同格连续点击，先记录完整选区再按第一次选择的起始周过滤，
  不先将完整选区改为单格；未选格和日期模式不触发隔周，滚动/取消指针清除连击识别。
  切换日期/周次模式或编辑另一条日程必须清除未完成的起点和连击状态，不能影响原有事件数据。
  读取/提交期间禁用管理入口，删除二次确认，官方课程和调休副本不提供手动日程编辑/删除按钮。
- 调休是复制未来某日的原始官方课程到目标日，源日和目标日原课程不变；同源可多目标，目标只允许
  一项复制，撤销仅去掉副本。不复制手动日程或其他副本，不修改官方 payload、缓存、教室占用或选课冲突。
  周视图/个人课情摘要应用日期副本，学期总览保持官方口径；手动日程复用普通移动课程卡和信息层级及
  `--course-color` 配色混合逻辑，使用低饱和蓝灰基色避免视觉脱节，
  以开始时间排序；有节次重叠时显示在正常课程网格中，无法匹配节次时仅在桌面补充区显示，手机端仍进入
  当天课程卡列表，时间栏显示“日程”而不伪造节次。
- `injectTimetableAgenda` 是周视图、日期弹窗和个人课情摘要的统一注入入口，生成课程副本及手动日程，
  `agendaEventMatchesDate` 还会用教学周日历把事件的 `agenda_date` 与当前周/星期做精确核对，
  防止手动日程在同周其他日期或切换周后残留；按周事件在投影阶段展开为所选周次的具体日期。
  不回写官方 payload、ResourceStore 或 IndexedDB；重建先排除已有注入项，避免刷新/重复调用造成重复及连锁复制。
  原课表加载不依赖日程成功，日程失败保留同身份/学期已有数据，不抢回用户正在预览的周次。
  日程弹窗选择面板打开时 Esc 先收起面板，提交期间不能通过 Esc 关闭；调休日期面板使用独立 popup
  样式限制窄屏宽度，不修改其他页面日期选择器。
- 学期生命周期不复用缓存 TTL：仅用当前账号已有、fresh 且 Schema 兼容的官方个人课表记录完整连续的
  周日到周六日期。学期结束停止注入/编辑；新学期索引明确标记 current，且新学期完整日期覆盖今天时，
  下次日程 API 读取/保存才清理结束日期早于新学期起点的旧文档内容。不从用户选中学期或公历月份推断删除。
  无日期、缺周、旧 Schema、过期/缺失缓存、未开始的新学期均不能作为清理证据；后续较短的日期响应不能缩短已确认保留期。
  清理保留无内容的 revision 标记，防止其他窗口旧表单复活数据；旧版本返回 409，已结束学期返回 410。
  `semester_ended`/`semester_end` 为只读响应字段，PUT 只提交 revision/events/moves。
  缓存库读取失败仅缺少清理证据，不能阻断独立日程读取或导致删除；日程文件损坏仍必须反馈错误，不能重置为空。

### 当前实现链路

- 方案管理：工作台内共享 `planSidebarPanel`；目录右侧与自动任务右侧默认显示同一个管理侧栏，
  方案组选取、概览卡、候选编辑和任务操作共用同一状态。点击概览卡进入名称/目标内联表单，高风险
  删除和远端退选仍使用确认弹窗，不维护独立“我的方案”视图。
- 前端模式与课表辅助：`frontend/src/utils/jwxkModes.js`、`frontend/src/utils/jwxkSchedule.js`。
- 两种工作台的预览取消入口共用 `frontend/src/components/SchedulePreviewControls.js`，位于课表标题之后、
  嵌入课表之前；`CourseSelectionPage.css` 负责黏性操作条和窄屏换行，`TimetablePage.css` 只为

### 当前行为与容易遗漏的特殊情况

- 抢选 `02` 与权重 `04` 的人数口径、结果来源和操作语义分开维护。
- “已选人数 0 / 容量 0”按非本轮或不可操作占位记录处理；这是结果判定中的特殊优先级。
- 非零记录即使批次不同，只要官方提供当前可退材料，仍按可操作课程处理。
- 只读请求可恢复并最多重试一次；已发出的写请求不自动重放。不确定的抢选结果继续只读核验。
- 目录、已选结果、自动任务、归档和通知使用同一轮次归属结论。
- 轮次名称或选课类型标识同时包含“人文”“选修”，且带有“选课”“补选”或“课程”等轮次语义时，
  在线课筛选由目录查询契约传入 `online_mode`，在后端分组、分页前执行；课程名称含“在线式”为在线课，
  其余为线下课。前端保留展示层兼容过滤，但不能把它作为唯一数据来源，也不能把该参数发送给学校端。
- 任务页的本地状态轮询只对 `running`/`waiting` 任务开启；草稿、暂停、待核验和已结束任务只在
  进入任务页或手动刷新时读取一次，避免未启动任务产生高频 `/automation/tasks` 请求。
- 方案组管理入口集中在目录和自动任务页面：方案组名称、目标门数、候选、意愿值、实验时间、
  未分组整理和任务绑定仍调用原有保存函数。桌面端使用右侧侧栏；窄屏将同一个侧栏置顶并改为
  单列，不创建抽屉或独立管理区。移除独立方案 Tab 后，旧的 `plan` 内部状态会回落到目录并进入
  侧栏管理态，避免出现空白视图。
- 方案侧栏的组选择、冲突检查、权重整理和删除操作采用统一的主列/操作列网格；冲突检查按钮会
  在侧栏内保留最近一次检查状态，明确区分检查中、无冲突、发现冲突、无可核验时间和失败。自动
  任务创建预览按方案组摘要与候选课程分层，候选课程状态标签在窄屏换行，不依赖横向滚动。
- 抢选异常通知由 `CourseSelectionAutomationService._notify_grab_issue` 按任务、异常类型、候选
  和稳定化原因指纹去重；轮询时间、超时毫秒数等易变文本不能进入新的通知事件。入队前保留 pending
  状态，发送失败才释放，原因或候选阶段变化才允许再次通知。
- 官方退课管理是 JWXK 之外的独立轮次工作台链路：`backend/core/academic/withdrawal.py` 读取
  `cxdqxkxnxq.do`、`cxxsktrw.do`、`cxxqkcbl.do`，`course_selection` router 暴露只读列表和
  明确确认后的单门退课；首页 `OfficialWithdrawalCard` 只负责入口摘要，完整页面为
   `OfficialWithdrawalWorkspacePage`，复用选课工作台课表、课程组/教学班卡片和筛选布局并展示培养计划缺口。页面会从培养计划缓存按课程代码补全缺失类别；缺口点击定位目录，清除筛选同步清除选中状态。单教学班直接显示简要课时、可退状态、返还估算及操作，多教学班才折叠比较；完整安排、时间、阶段扣除和来源放在详情。课程行左侧依次为教师、课时、不可退原因，右侧只放简短状态与操作；缩窄时整组下移，避免长原因挤在按钮间。预览按 `WID` 取当前课程数据，显式按钮聚焦课表，课表顶部或课程按钮取消时用课程行/组引用定位回原处；没有可解析时间不假装预览成功。选课和退课工作台向嵌入课表传入 `initialViewMode="week"` 与 `autoSelectCurrentWeekOnOpen`，紧凑手机课表复用 `MobileTimetable` 的周次横向滑动；普通课表仍由 `TimetablePage` 自己管理默认周。仅当记录当前可退、原权重及阶段扣除权重都有值时，才估算两者差额为预计返还；过期记录不显示旧权重的返还提示。退课确认会提示预计新增缺口和返还估算。首页入口在宽屏分列摘要与定宽按钮、手机整行按钮，刷新按钮位于卡片标题的紧凑图标按钮中；目录与缺口在较窄桌面稳定切成单列，避免导航侧栏展开时大量课程文字反复重排。列表分页必须完整读取，只有
  `XKLY=01` 且时间窗口可确认的记录可写，提交前再次校验学期和 `WID`。认证失效或传输异常
  不重放写请求，成功后只失效个人课表缓存；不能与 JWXK 退课状态混合。

## WebVPN 与认证恢复

### 当前实现链路

- Go直连迁移：`internal/campus/client.go`维护每账号CAS候选Cookie和学校Session；
  `internal/application/accounts.go`组合账号运行上下文、启动恢复与停止；
  `internal/application/api.go`提供登录/状态/bootstrap/退出及同源写入边界。
  `internal/store/secrets.go`保存账号绑定密文，`sessions.go`保存浏览器令牌哈希与撤销代际。
  网络丢失不重放密码表单；只在学校明确拒绝且公钥确实变化时重新取得表单再提交一次。
  未验证的恢复Cookie不当作学校认证成功；停止期间晚到的登录结果不能恢复账号或签发新浏览器会话。
  Go二维码与短信状态机见`internal/campus/webvpn_login.go`，浏览器隔离路由见
  `internal/application/webvpn_login.go`。候选client独立持有Cookie，二维码/短信字段只保留内存；
  HttpOnly随机owner Cookie绑定flow_id，重启、取消、换流程、退出与账号generation变化拒绝旧结果。
  二次认证验证码固定取同目录code?vpn-1，以magic识别图片；短信发送仅含code/method，保留官方
  vpn-12-o2-pass.neu.edu.cn标记。sms_verified后清理表单和验证码，仅只读身份探测，五分钟期限不续延。
  扫码不相信用户填写的账号提示，官方currentUser核验失败不发布运行会话；错误响应不透出学校正文。
  `webvpn_gateway.go`与`webvpn_service.go`仅合并目标账号的网关Cookie，主线路/主Cookie/直连令牌不变。
  子服务密码恢复在网关认证完成后直接ensureService，返回authenticated/not_in_selection_round/
  service_unavailable；扫码始终先核验currentUser账号，不借用提示学号。
  `internal/application/auth_recovery.go`按Runtime绑定共享恢复状态/任务，先VerifySaved再保存密码，
  在公共学校请求槽内执行，5秒指数退避至120秒。恢复发布前同时核对generation和原Runtime，晚到
  结果不能覆盖前台登录或退出；启动只登记未验证运行实例，统一交给该调度链，避免另起认证线程。
  DIRECT_ACCESS_FAILED仅表示密码提交前连接失败，提交后的UPSTREAM_UNAVAILABLE不跨线重放。
  后台短信挑战保存到账号隔离的内存pendingVPN，当前有效浏览器Session可读取/续接原Flow；
  取消/超时改为manual_required，不自动重新发起短信。状态读取只返回本地快照，兼容
  retry_after_seconds/failures字段。恢复后wakeGradeTracking保留activation并提前下一次检查。
  主动低频保活和远程恢复页已接通。主会话核验的网络失败进入等待重试，身份不匹配进入人工恢复，不向学校提交保存的密码；见 `TestRecoveryProbeFailureDoesNotSendSavedPassword`。子服务独立静默恢复、未分类表单新Session专门重试仍待迁移。
  旧版对照入口：`backend/core/auth/client.py` 中 `allow_identity_recovery` 分支先尝试当前子服务会话，有未过期验证码/扫码流程时不重复提交；子服务走 WebVPN 而主教务直连时，以同账号凭据建立目标网关，不替换主会话。直连子服务通过 `_login_direct_service(config)` 使用自己的 CAS 回调。Go 的 `TestVPNServiceRecoveryKeepsPrimarySessionAndMode`、`TestVPNGatewayMergePreservesPrimaryAndDirectServiceState` 和 `TestVPNPasswordServiceRecoveryDoesNotDependOnPrimaryAvailability` 已验证定向密码恢复和网关合并；这些测试没有从子服务只读业务请求自动发起恢复，不作为该触发路径的验收。
  验证见`internal/application/auth_recovery_test.go`、`internal/campus/session_probe_test.go`、`internal/campus/webvpn_login_test.go`、
  `internal/application/webvpn_login_test.go`及原直连/存储测试。

### 当前行为与容易遗漏的特殊情况

- 直连和 WebVPN 共享同一业务会话；可验证线路故障才自动切换，密码错误和普通业务错误不能无限换线。
- Cookie 失效、短时网络失败和暂时不可达优先走 single-flight、超时和退避；只要同账号本地凭据可用，
  JWXK/CXCY 服务级状态探测也会在共享 Session 内自动完成一次账密恢复。直连到 WebVPN 的换线
  只由全局登录器在主身份恢复阶段负责；服务级探测保持用户选择的线路边界。错误凭据、业务异常、
  验证码、短信或二维码才需要人工操作。
- 旧版 Cookie 恢复可能缺少账号元数据，或保留全角/空白形式；恢复前要用本地保存账号补齐并规范化
  当前客户端身份，但不能把不同账号的凭据静默注入现有 Session。
- 已有 WebVPN 会话的 CAS 账密尝试返回未分类登录表单结果且没有稳定错误码时，进程恢复器允许
  同账号凭据在原线路使用干净 Session 再试一次；密码明确拒绝、超时和已有交互挑战不走此分支。
  只有确认新会话成功才替换活动客户端，诊断日志仅包含异常类别与错误代码。
- 只读请求恢复后最多重试一次；写请求不自动重放。恢复失败不能清空页面上下文或缓存，手动退出后不自动恢复。
- JWXK、CXCY 等服务定向恢复保持服务边界；离线模式只读，不触发恢复或写操作。

### 当前行为与容易遗漏的特殊情况

- 登录、访问门、主布局、成绩明细、查询课表（含当日日程）和认证恢复保持静态导入；其他页面按
  学术、选课、导出或独立业务包异步加载。嵌套选课与导出路由必须复用同一注册表 Promise，不能各自
  建立 `React.lazy` 缓存。
- `load` 对并发请求去重并缓存成功模块；导入失败立即清除 pending Promise，`retry` 才能创建新的
  加载过程。预取失败静默，不污染全局错误；真实进入页面时仍按正常错误状态处理。
- 冷启动异步深链接与认证 bootstrap 并行加载目标包。正常在线登录/离线能力确认后才开始按导航顺序空闲预取；
  只读课表恢复态不代表业务身份确认，不预取其他业务包；
  隐藏页面暂停队列，重新可见后继续；Save-Data/2G 远程连接不执行全量预取。本地 desktop/mobile、
  localhost 回环环境不受慢网限制。
- 异步页面只替换内容区，加载中显示同尺寸 Skeleton。chunk 失败自动重试一次；失败后显示联网提示或
  “重试加载/刷新应用”。普通页面渲染异常只进入渲染错误边界，不借刷新掩盖代码错误。
- chunk 失败会读取无缓存 `asset-manifest.json` 比较当前 script 与最新 `main.js`。仅当版本变化且
  `sessionStorage` 尚未记录该目标 main 哈希时自动刷新一次；manifest 不可用、版本相同或已刷新过均不
  自动刷新，避免旧标签页循环白屏。

正式发行流程复用 Go 平台验收工作流，在标签版本的 Windows 和 Debian 验收通过后，将两个 Go 包和 `go-release-manifest.json` 纳入发行附件、总摘要与来源证明。Go 更新器按正式标签和平台读取该清单。

独立分支推送时，若改动全部位于根目录 README、开发文档或功能说明书，GitHub Actions 跳过 Go 平台构建。随 Windows、Linux 成品分发的运行、备份和迁移指南位于部署文档目录，修改这些文件时推送及拉取请求都会触发平台检查。
