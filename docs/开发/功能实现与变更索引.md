# 功能实现与变更索引

## 版本识别与跨平台更新

- 统一版本来源：根目录 `VERSION`；Android 覆盖安装顺序使用 `ANDROID_VERSION_CODE`。
- Release 资产清单：`.github/workflows/release.yml` 生成 `release-manifest.json`，并与
  `SHA256SUMS.txt` 一起发布。
- 后端检查/下载：`backend/core/runtime/updates.py` 与 `backend/app/routers/runtime.py`；
  设置页入口为 `frontend/src/components/VersionUpdateCard.js`。
- Linux 服务自动升级：数据目录 staging 后由 `packaging/linux/neu-jwxt-toolkit-updater.path`
  触发 root-owned helper，最终复用 `install.sh --upgrade` 的配置保留和健康失败回滚。
- Android 客户端/本地版：`packaging/android/shared/.../AppUpdateManager.java`，只访问官方
  GitHub、校验 SHA-256，再通过 FileProvider 拉起系统安装器。
- 客户端版系统设置同时读取手机客户端 Release 和连接服务端的 `/api/runtime/update`；两条链路
  必须由用户分别触发检查/下载，不能在进入设置页或启动客户端时自动检查或下载。服务端更新仍复用
  远端 Linux 的 staging、watcher 和回滚状态。
- 修改版本、发行文件名或安装权限时，需要同时核对发行与 CI、Linux/Android/Windows 部署说明、
  系统设置页面、原生桥和对应测试；不应把更新下载与业务缓存预热或认证恢复混在一起。
- `VersionUpdateCard` 将版本信息按“状态、当前/最新版本、任务状态、主操作、Release 链接、说明”分层；
  手机端操作按钮纵向排列并允许自然换行，不能把多个版本源压成一行。

本文面向开发接手和修改，不是用户说明书。用户操作、页面文案和功能边界以 `docs/功能/`
下的对应说明为准；本文只记录接手时需要定位的实现入口、容易遗漏的特殊情况、联动影响和验证入口。

## GPA 模拟与成绩统计

### 当前实现链路

- 页面与交互：`frontend/src/components/GPACalculator.js`、同目录 CSS。
- 成绩页统计：`frontend/src/pages/ScoresPage.js`、同目录 CSS。
- 绩点策略：共享 GPA policy hook/计算模块及成绩缓存。
- 方案文件：`backend/app/routers/gpa.py`，按账号隔离保存。
- 关联功能：培养计划导入、成绩追踪快照与邮件。

### 当前行为与容易遗漏的特殊情况

- 手动课程名支持直接编辑，失焦或回车保存；只改名称不能重置学分、绩点或元数据。
- 学分必须有效且大于 0，绩点可以为 0；两者都有效后才移出“待输入”。
- 隐藏只存在当前模拟会话，不写入方案文件；隐藏课程不参与当前统计。
- 筛选或隐藏导致统计范围不完整时显示波浪线和说明；完整课程集不显示。
- 成绩明细和 GPA 模拟统一显示四位小数并复用同一绩点策略，包含 2025 级及以后规则。

### 修改时继续检查

绩点策略、成绩缓存和成绩追踪通知。

## 培养计划与系统消息合并

### 当前实现链路

- `frontend/src/pages/AcademicReportPage.js` 订阅 `academic-report` 与 `system-messages`；
  `frontend/src/utils/resourceUpdateSummary.js` 对比当前和新计划快照，
  `frontend/src/utils/systemMessagePrompt.js` 从最新可用消息快照选出本账号的官方未读消息。
- `frontend/src/components/MergedUpdateSummary.js` 在现有的培养计划更新确认弹窗中分区展示
  数据差异与消息内容；不创建新的消息弹窗或额外消息缓存。

### 当前行为与容易遗漏的特殊情况

- 只有计划内容真实变化才提示，revision/排序变化由原逻辑静默应用；仅消息更新不触发
  计划刷新弹窗。官方消息供用户对照，不能断言它一定对应某门变化的课程。
- 消息晚到时更新已有弹窗内容；优先读系统消息资源的 `availableData`，避免已读状态或新
  消息被旧展示快照遮盖。点击“刷新当前显示”或“稍后”沿用原计划快照语义，仅在当前
  会话记住已展示的消息，不执行未经核实的教务消息写入操作。

## 查询课表与教室空闲筛选

### 当前实现链路

- 页面与布局：`frontend/src/pages/TimetablePage.js`、同名 CSS。
- 请求封装：`frontend/src/services/api.js`。
- 后端路由：`backend/app/routers/timetable.py`。
- 教务适配与解析：`backend/core/timetable/`。
- 时间与冲突：`backend/core/scheduling/`。
- 个人首屏：服务器缓存、浏览器快照和课表恢复流程。
- 当日日程：`frontend/src/components/TimetableDayAgenda.js` 和同名 CSS；日期及复制投影为
  `frontend/src/utils/timetableAgenda.js`。持久化接口在课表 router，契约为
  `backend/app/schemas/timetable_agenda.py`，原子存储为 `backend/core/storage/timetable_agenda.py`。
- 教务系统消息：`backend/core/academic/system_messages.py` 只读解析提醒/审核列表，
  `backend/core/cache/resources.py` 注册 `system-messages` 账号缓存，
  `backend/app/routers/system_messages.py` 与 `backend/app/routers/offline.py` 提供在线/离线读取，
  前端由 `frontend/src/utils/systemMessagePrompt.js` 过滤账号级官方未读消息，
  `frontend/src/utils/resourceUpdateSummary.js` 从当前与候选官方课表生成逐课差异；
  有课表差异时在原“课表有更新”确认弹窗内分区合并展示，无差异时在课表页面内显示独立的
  非阻塞通知。

### 当前行为与容易遗漏的特殊情况

- 从其他页面重新进入个人周课表时默认当前学期本周；显式学期/周次链接和学期视图不受影响。
  ResourceStore 内存、浏览器快照、服务器启动缓存和学期接口先后到达时，不能重新应用上次保存的周次/学期，
  也不能覆盖用户进入页面后的手动选择。
- 手机当前周的默认星期使用本机日期，即使当天无课；日期变更、窗口重新聚焦或后台恢复时同步更新
  星期选择、今天标记和课情摘要。异步确认当前学期后须重新校正；手动换日及浏览其他周次不应被抢回。
- 父页日期计时器只在本机日期变化时更新，课情摘要、网格和手机课程卡的时间计时器仅在显示分钟变化时
  更新；两者均不触发课表请求或清空已挂载结果。手动切周（含桌面滚轮和手机滑动）关闭当前页面的
  手机选日自动跟随；跨日后只在尚未手动浏览且原本跟随本周时自动换周/换日，重新进入页面才重置此状态。
- 桌面周选择框用原生非被动滚轮监听避免页面同步滚动，按升序周次有边界切换；仅个人课表手机悬浮窗
  的课程信息可点击，按周日到周六及课程结束时间查找下一次课，普通周视图切周和星期、学期视图只切星期、
  缩略周视图只切周、缩略学期视图只收起。其他查询模式的课程信息为静态内容，不显示定位箭头。
  摘要自身的时钟应随时间和页面恢复更新，不能只依赖日期变更。
- 周内顺序为周日到周六；范围判断使用包含式重叠。
- 教学周选项可能包含“（本周）”和日期范围等长文本；中等宽度下操作按钮必须独立成行，选择器文本只能省略，不能覆盖冲突检测或刷新按钮。
- 特殊空闲筛选先限定普通筛选候选，再逐教室扫描并本地核验；继续查找不能重复扫描。
  默认周次只在初始条件尚未填写时设定，跨日或当前周变化不能清除已填写条件和扫描结果。
- 扫描结果与请求条件、游标、已检查教室标识同存于当前页面会话；选中候选教室时暂停扫描，重开筛选
  恢复候选且不运行普通目录预览。续查沿用首次扫描的搜索词、校区及条件，不取课表查看过程中改变的
  页面状态；主动修改筛选条件或切换学期/模式时才废弃旧扫描。
- 无法解析时间的课程不能误判为空闲；结果增量显示，暂停和扫描完成要区分。
- 个人课表优先显示旧快照，刷新失败不能伪装成无课；认证错误不能包装成普通课表错误。
- 课表内容签名相同（只变 revision 或顺序）不弹更新窗口；后台刷新先按当前显示的学期、校区、周次
  和视图过滤比较，只有会影响前台课程的差异才在原确认弹窗展示实际增删、地点/时间等变更和相关
  官方未读消息。其他周次或其他校区的变更直接静默合入完整快照，不改变用户正在浏览的范围。
  消息稍后到达只更新弹窗内容，不使 `offerPersonalPayloadUpdate` 变为新回调、不触发课表重读；
  单独消息在课表页面内显示独立的非阻塞通知，不升级为全局弹窗。
  确认/暂缓后只在当前会话记住弹窗展示过的消息，不写官方状态；其他课表模式不使用此弹窗。
- 系统消息两个分页标签独立读取，单个标签失败时保留另一标签；两者都失败只记录资源错误，
  不清空已有缓存。消息列表接口不标记已读，不携带写操作。
- 消息分类由 `frontend/src/utils/systemMessageSummary.js` 统一维护：培养计划和个人课表
  融入各自原有的差异确认弹窗；实验选课、考务管理仍由页面级 `SystemMessageNotice`
  提示，不升级为全局通知。`systemMessagePrompt.js` 按账号和官方 ID 记录当前会话的用户
  确认；官方已读不提示，确认后切页不再反复提示，内容变化的未读消息可重新提示。
  前端确认记录同时写入当前标签页 `sessionStorage`，避免异步页面重新挂载后同一条官方未读消息重复弹出；
  内容指纹变化时仍会重新提示。
  用户确认后由 `POST /api/system-messages/read` 逐条调用提醒/审核消息对应的官方
  `updateReadAndGetMessage.do`，写入走 `require_mutation_auth` 独占认证边界，不自动重试；
  单条失败不阻塞页面，其余消息仍继续同步；官方成功的消息会同步写回本地
  `system-messages` 缓存，避免旧的 `read: false` 快照在切页后再次触发提示。
  消息缓存分类保留近 30 天已读消息，未读消息不因时间过旧自动隐藏；读取失败不改变业务页面状态。
- 课表初始化会校验 URL、内存和浏览器快照中的学期标识；空值、`undefined`、`null`、`unknown` 或不符合
  教务格式的旧值不会发送到课表接口。切页期间的旧请求结果也不能覆盖新页面；FastAPI 422 校验详情需保留
  字段路径和具体原因，不能只显示 Axios 默认英文。
- 周视图星期标题打开准确日期的日程弹窗；手机按日周视图复用 Segmented 星期标题，未选日只选日，
  再点已选日才打开，可重开，不设按钮或快速双击时间限制。捕获阶段仅处理标签转发的 radio 点击，
  在 onChange 更新选日前判断原选日，避免首次选日误开或重复打开；Enter/空格打开当前选日，
  方向键及滑动仍只导航，学期视图仍只选日。空周可添加日程，但未识别日期、
  学期视图和选课嵌入视图不开放。只有个人课表编辑，其他模式查看对象课程，不混入个人日程。
- 日程按账号/学期独立持久化，不注册为可重建缓存；加载失败不能以空文档覆盖旧数据，账号/学期切换
  使旧请求失效。写入携带 revision，冲突返回 409 并重新读取，不盲目重放保存。
- 手动日程标题和铅笔按钮均进入同一编辑表单，打开后定位编辑区；表单先重置再带入完整默认值及原始字段，
  避免切换日程时选填字段串值。更新保留原 ID，删除按 ID 精确移除；取消/保存失败不改变已保存文档，失败可重试。
  读取/提交期间禁用管理入口，删除二次确认，官方课程和调休副本不提供手动日程编辑/删除按钮。
- 调休是复制未来某日的原始官方课程到目标日，源日和目标日原课程不变；同源可多目标，目标只允许
  一项复制，撤销仅去掉副本。不复制手动日程或其他副本，不修改官方 payload、缓存、教室占用或选课冲突。
  周视图/个人课情摘要应用日期副本，学期总览保持官方口径；节次外日程另列，不能伪造节次。
- `injectTimetableAgenda` 是周视图、日期弹窗和个人课情摘要的统一注入入口，生成课程副本及手动日程，
  不回写官方 payload、ResourceStore 或 IndexedDB；重建先排除已有注入项，避免刷新/重复调用造成重复及连锁复制。
  原课表加载不依赖日程成功，日程失败保留同身份/学期已有数据，不抢回用户正在预览的周次。
  日程弹窗选择面板打开时 Esc 先收起面板，提交期间不能通过 Esc 关闭；调休日期面板使用独立 popup
  样式限制窄屏宽度，不修改其他页面日期选择器。
- 学期生命周期不复用缓存 TTL：仅用当前账号已有、fresh 且 Schema 兼容的官方个人课表记录完整连续的
  周日到周六日期。学期结束停止注入/编辑；新学期索引明确标记 current，且新学期完整日期覆盖今天时，
  下次日程 API 读取/保存才清理结束日期早于新学期起点的旧文档内容。不从用户选中学期或公历月份推断删除。
  无日期、缺周、旧 Schema、过期/缺失缓存、未开始的新学期均不能作为清理证据；后续较短的日期响应不能缩短已确认保留期。
  清理保留无内容的 revision 标记，防止其他窗口旧表单复活数据；旧版本返回 409，已结束学期返回 410。
  `semester_ended`/`semester_end` 为只读响应字段，PUT 只提交 revision/events/moves。
  缓存库读取失败仅缺少清理证据，不能阻断独立日程读取或导致删除；日程文件损坏仍必须反馈错误，不能重置为空。

## WebVPN 与认证恢复

### 当前实现链路

- 认证客户端：`backend/core/auth/client.py`。
- 会话边界：`backend/core/auth/session_manager.py`。
- 进程保活：`backend/core/auth/keepalive.py`。
- 后端认证路由：`backend/app/routers/auth.py`。
- 前端恢复与请求重试：`frontend/src/services/api.js`、`frontend/src/App.js`。
- 调用方：成绩、课表、选课、成绩追踪、创院服务和后台任务。

### 当前行为与容易遗漏的特殊情况

- 直连和 WebVPN 共享同一业务会话；可验证线路故障才自动切换，密码错误和普通业务错误不能无限换线。
- Cookie 失效、短时网络失败和暂时不可达优先走 single-flight、超时和退避；只要同账号本地凭据可用，
  JWXK/CXCY 服务级状态探测也会在共享 Session 内自动完成一次账密恢复。直连到 WebVPN 的换线
  只由全局登录器在主身份恢复阶段负责；服务级探测保持用户选择的线路边界。错误凭据、业务异常、
  验证码、短信或二维码才需要人工操作。
- 旧版 Cookie 恢复可能缺少账号元数据，或保留全角/空白形式；恢复前要用本地保存账号补齐并规范化
  当前客户端身份，但不能把不同账号的凭据静默注入现有 Session。
- 已有 WebVPN 会话的 CAS 账密尝试返回未分类登录表单结果且没有稳定错误码时，进程恢复器允许
  同账号凭据在原线路使用干净 Session 再试一次；密码明确拒绝、超时和已有交互挑战不走此分支。
  只有确认新会话成功才替换活动客户端，诊断日志仅包含异常类别与错误代码。
- 只读请求恢复后最多重试一次；写请求不自动重放。恢复失败不能清空页面上下文或缓存，手动退出后不自动恢复。
- JWXK、CXCY 等服务定向恢复保持服务边界；离线模式只读，不触发恢复或写操作。

### 当前行为与容易遗漏的特殊情况

- 登录、访问门、主布局、成绩明细、查询课表（含当日日程）和认证恢复保持静态导入；其他页面按
  学术、选课、导出或独立业务包异步加载。嵌套选课与导出路由必须复用同一注册表 Promise，不能各自
  建立 `React.lazy` 缓存。
- `load` 对并发请求去重并缓存成功模块；导入失败立即清除 pending Promise，`retry` 才能创建新的
  加载过程。预取失败静默，不污染全局错误；真实进入页面时仍按正常错误状态处理。
- 冷启动异步深链接与认证 bootstrap 并行加载目标包。正常在线登录/离线能力确认后才开始按导航顺序空闲预取；
  只读课表恢复态不代表业务身份确认，不预取其他业务包；
  隐藏页面暂停队列，重新可见后继续；Save-Data/2G 远程连接不执行全量预取。本地 desktop/mobile、
  localhost 回环环境不受慢网限制。
- 异步页面只替换内容区，加载中显示同尺寸 Skeleton。chunk 失败自动重试一次；失败后显示联网提示或
  “重试加载/刷新应用”。普通页面渲染异常只进入渲染错误边界，不借刷新掩盖代码错误。
- chunk 失败会读取无缓存 `asset-manifest.json` 比较当前 script 与最新 `main.js`。仅当版本变化且
  `sessionStorage` 尚未记录该目标 main 哈希时自动刷新一次；manifest 不可用、版本相同或已刷新过均不
  自动刷新，避免旧标签页循环白屏。
