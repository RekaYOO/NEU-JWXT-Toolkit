# 架构设计

NEU 教务系统工具箱是 React 前端与 FastAPI 后端组成的模块化单体。Windows 桌面版、Linux
服务版和源码开发模式共享同一业务代码，只在运行 profile、资源位置和访问边界上不同。

开始修改前先读[开发接手与变更规范](开发接手与变更规范.md)。本文说明当前结构和关键约束，
不记录历史重构过程。

## 目录与分层

```text
backend/
  app/
    main.py             FastAPI 组合、middleware、路由和 SPA fallback
    dependencies.py     ApplicationServices 组合根与进程级生命周期
    presenters.py       在线/离线共用的 HTTP 展示模型
    routers/            HTTP 参数、权限、状态码和业务编排
    schemas/            Pydantic 请求/响应契约
  core/
    auth/               唯一认证客户端与业务子会话
    cache/              CacheRegistry、SQLite、single-flight 和 revision
    academic/           成绩、培养计划、实验、科研等领域适配
    course_selection/   JWXK、策略模型、归档和后台任务
    timetable/          课表协议适配
    scheduling/         统一时间模型与冲突判断
    storage/            用户文档、配置和兼容迁移
    runtime/            development/desktop/server 配置
frontend/src/
  features/             功能注册和离线可用性
  resources/            共享资源读取、刷新与事件协调
  pages/                页面编排
  components/           可复用业务与移动组件
  services/             API 客户端
  utils/                无副作用的格式化和领域辅助
launchers/               桌面/服务启动入口
packaging/               Nuitka、Linux 安装和发行材料
tests/                   生产运行与发行包集成测试
```

依赖方向为 `router -> core service -> auth/storage/cache`。页面不直接访问学校系统，领域层不
依赖 React 展示结构，持久化层不承担业务决策。

## 进程生命周期

`backend/app/dependencies.py` 创建进程级 `ApplicationServices`，持有：

- 唯一 `NEUAuthClient`；
- `CacheRegistry`、SQLite `CacheStore` 和刷新协调器；
- 成绩追踪与共享邮件 outbox；
- 选课归档、通知和自动任务调度器；
- 领域存储适配器。

FastAPI lifespan 负责一次启动和有界停止。后台线程不能在路由导入时自行创建，也不能为每个
请求复制认证客户端或任务调度器。

## 三种运行 profile

| profile | 用途 | 可写数据 | HTTP 边界 |
|---|---|---|---|
| `development` | 源码和测试 | `<cwd>/data` | 默认回环；开放 OpenAPI |
| `desktop` | Windows 便携版 | `%LOCALAPPDATA%/.../data` | 只监听回环；支持桌面关闭 API |
| `server` | Linux 单用户服务 | `/var/lib/neu-jwxt-toolkit` | 强制回环，外部访问必须经过受信反代与网站密码 |

配置实现位于 `backend/core/runtime/config.py`。冻结资源通过 `resource_path()` 读取，业务数据
通过 runtime/Storage 获取；不能依赖启动时工作目录，也不能写入发行包资源目录。

生产模式由 FastAPI 提供已经构建的前端。缺少 `frontend/build/index.html` 或 `static/` 时 SPA
请求返回明确的 503，API 仍可启动用于诊断。静态根文件使用白名单，嵌套路由统一回退到 SPA。
前端仍保持 CRA 的单一主包，不做路由级拆分。构建阶段为文本静态资源生成 `.br` 和 `.gz`
同名变体，FastAPI 按 `Accept-Encoding` 的质量权重选择响应；带内容哈希的 JS/CSS 使用一年
`immutable` 缓存，`index.html` 与根级 manifest/icon 始终重新验证。该能力内置于应用，反向
代理可以覆盖压缩策略，但 Windows、源码运行和 Linux/1Panel 均不要求增加代理配置。

## 认证和远端会话

整个应用只有一个账号身份和一个主 `requests.Session`。`NEUAuthClient` 负责：

- 直连 CAS 登录、Cookie 恢复和保存账密恢复；
- WebVPN 密码、二维码和短信流程；
- 按服务建立 JWXT、JWXK 等业务子会话；
- 在账号变化时阻止旧数据被新身份继续使用。

远端读取通过共享 session guard 串行保护易冲突的认证状态。只读请求可以在明确的认证失效后
重建业务会话并重试；写请求一旦发出，不因超时、跳转或登录恢复自动重放。详见
[WebVPN 校外访问](../功能/WebVPN校外访问.md)。

WebVPN 二维码、账号密码和短信二次认证共用同一内存候选 Session。认证 API 保留历史
`success`、`status`、`message` 字段，并附带稳定的 `error_code`；前端不得根据中文消息
猜测流程状态。图形验证码由二次认证页面目录的官方 `code?vpn-1&随机数` 端点实时获取，
服务端校验实际图片字节类型后返回 data URL；验证码、短信、Cookie 和完整跳转参数不落盘。

成绩追踪邮件恢复同样使用候选 Session，但由高强度一次性 URL token 单独授权。后台保存账密
已经进入短信挑战时，`GradeTrackingService` 续接该候选 Session，邮件页面直接展示图形和短信
验证；没有保存账密或尚未完成 CAS 登录时，页面才先创建二维码重新登录。未配置可访问的重新
登录地址时只发手动登录通知。恢复成功后通过统一认证装配原子接管 Session、令牌立即失效并
唤醒追踪；服务重启不会伪造已经丢失的内存验证码 Flow。

共享 Session 的内部排队顺序固定为：远端写操作及其核验、前台认证恢复、前台读取、页面后台
刷新、追踪/归档/预热。已经开始的请求不会被中断；连续高优先级读取达到有界次数后允许最早
等待的低优先级读取执行，避免后台状态永久饥饿。此调度只影响排队先后，不改变任务频率、
业务状态机或写操作的“不自动重放”规则。

Linux server 还有一层独立的网站访问密码。它只保护工具箱 HTTP 服务，不代替 NEU 登录。

## 数据读取与缓存

可重建资源通过 `backend/core/cache/` 管理：

```text
页面读取 -> typed adapter -> SQLite 快照
                         -> 过期时提交后台刷新
后台刷新 -> 共享认证会话 -> 规范化 -> 原子替换 -> revision/event
```

页面应先返回本地快照，再展示刷新状态。相同资源的并发刷新由 single-flight 合并；失败保留旧
数据。资源间依赖使用 revision，例如成绩实际变化才使培养计划失效。

应用壳另提供两个附加式、本地只读接口：`GET /api/client/bootstrap` 一次读取运行模式、内存
认证快照、待认证状态、事件游标、头像和课表服务器快照；`GET /api/client/updates` 按频道合并
缓存事件与待认证状态。两者都不访问学校系统、不恢复登录、不获取远端 Session 锁。旧的状态、
缓存事件、头像和课表接口继续保留，新前端遇到旧后端返回 404 时自动回退原接口。

`CacheStore.get_many` 和 `CacheCoordinator.read_many` 用一个短连接批量读取同一首屏的 SQLite
快照。缓存内容提交后再发布事件；相同刷新 job、相同前端请求和相同自动任务状态读取均在各自
边界内合并，不改变公开 API 契约。

收藏、GPA 文件、选课方案/归档/任务、追踪配置/outbox、凭据和日志不是缓存，不能注册进缓存
淘汰策略。详见[缓存与数据一致性](缓存与数据一致性.md)和[数据存储](数据存储.md)。

## 统一时间与冲突模型

课表和选课都把官方安排规范化为学期、星期、周次集合、起止节次、教师、校区和地点。
`backend/core/scheduling/` 是唯一冲突真相源：同学期、同星期、周次相交且节次重叠才冲突。
前端展示可以不同，但不得从时间文本重新猜测。

## 前端能力注册

`frontend/src/features/featureRegistry.js` 是页面名称、路径、图标和离线可用性的稳定注册表。
`App.js` 负责 route element 和认证边界，`MainLayout.js` 从注册表生成导航。新增顶级功能必须同时
登记路由、菜单、离线策略、页面标题和文档。

共享资源由 `frontend/src/resources/ResourceStore.js` 管理；页面订阅状态和 revision，不重复
实现请求缓存。桌面和手机视图共享数据、筛选和操作函数，只改变布局。

账号级 `ClientUpdateScheduler` 合并缓存事件与认证挑战轮询，并通过 `BroadcastChannel` 和
短期租约在同账号的多个标签页中选出一个请求主标签；其他标签接收已确认快照。浏览器不支持
该能力或租约存储失败时退回各标签独立轮询。运行中自动任务仍保留自己的 1 秒进度语义，但
同周期相同批次的请求会复用同一个 Promise。

## 写操作约束

所有远端 mutation 必须：

1. 在后端登记为写操作，不使用通用只读重试。
2. 提交前校验账号、业务上下文和最新操作材料。
3. 前端防重复点击并显示确认。
4. 官方明确成功后立即更新最小本地状态，并在后台失效/刷新依赖资源。
5. 结果未知时进入待核验，不猜测成功也不自动重放。

证明生成、评教、选课、投权、退选、实验选退和科研报名都遵守该边界。

## 测试结构

- `backend/tests/`：领域、路由、缓存、认证、持久化和任务测试。
- `frontend/src/**/*.test.js`：交互、筛选、资源和响应式逻辑。
- `tests/`：生产 SPA、访问网关和发行包约束。
- `.github/workflows/ci.yml`：Linux 上的后端、前端和生产集成验证。
- `.github/workflows/release.yml`：固定版本、Windows/Linux 构建和发行物校验。

运行时性能观测由 `backend/core/runtime/performance.py` 保存为有界进程内统计，只记录阶段名和
耗时。目前覆盖启动、HTTP、SQLite 批量读取和远端排队/占用；不持久化、不开放
新端口或指标接口，也不记录账号、Cookie、验证码和业务数据。

测试中使用匿名夹具和模拟远端响应。真实账号、Cookie、token、个人业务响应以及真实写操作
不得进入测试或版本控制。
