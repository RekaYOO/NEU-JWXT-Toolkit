### 1.1 分层职责

- `backend/core` 负责远端请求、解析和业务规则，不依赖 React 或 FastAPI 表现层。
- `backend/app/schemas` 是稳定的 HTTP 数据契约。
- `backend/app/routers` 负责鉴权、输入校验、错误映射和调用 core，不复制解析逻辑。
- `backend/app/dependencies.py` 组装共享认证客户端、存储、日志和后台追踪服务。
- `frontend/src/services/api.js` 是页面访问后端的统一入口。
- `frontend/src/App.js` 和 `frontend/src/layouts/MainLayout.js` 分别维护路由与导航；
  新功能必须同时检查二者。
- `backend/core/runtime` 和 `launchers` 决定三种运行模式，不能在页面或路由中使用
  当前工作目录推测数据/资源位置。

## 3. 核心设计决策

### 3.1 统一客户端设计

**问题：** 多个Client类造成使用困惑  
**决策：** 通过 `auth.academic` 挂载，统一入口

```python
# 不好的设计
from backend.core.auth import NEUAuthClient
from backend.core.academic import AcademicAPI

auth = NEUAuthClient(...)
auth.login()
ac = AcademicClient(auth)  # 需要额外创建

# 当前设计
from backend.core.auth import NEUAuthClient

auth = NEUAuthClient(...)
auth.login()
auth.academic.get_scores()  # 直接访问
```

### 3.2 延迟加载机制

**原因：** 避免循环导入，只在需要时初始化

```python
# NEUAuthClient.__init__
self._academic = None  # 延迟初始化

@property
def academic(self):
    if self._academic is None:
        from backend.core.academic.api import AcademicAPI
        self._academic = AcademicAPI(self)
    return self._academic
```

### 3.3 使用系统绩点

**问题：** 手动计算可能与系统不一致  
**决策：** 直接使用教务系统返回的 `JD` 字段

```python
# 系统返回的数据
{
    "XSZCJ": "85",    # 成绩
    "JD": "3.5",      # 系统计算的绩点 <-- 使用这个
    "XF": "3.0"       # 学分
}

# 计算公式
GPA = Σ(JD × XF) / Σ(XF)
```

### 3.4 本地数据存储

**问题：** 页面、追踪、离线和后台刷新若各自保存文件，会出现多个真相源和竞态。
**决策：** 可重建业务数据统一进入 SQLite `cache.db`；用户文档、配置、凭据、可靠
outbox、收藏和日志按各自生命周期独立存储。

**设计要点：**

- `CacheRegistry` 声明资源 Schema、revision、时效、依赖和写后失效；
- `CacheStore` 使用 WAL、短连接和事务，是缓存唯一真相源；
- `CacheCoordinator` 提供 single-flight、失败退避、身份 epoch 隔离和两个托管工作线程；
- `AuthSessionManager` 串行保护共享教务 Session；缓存读取不占用远端锁；
- `scores.csv` 等旧文件仅在一个兼容周期内惰性迁移，不再写入；
- 默认数据目录由运行模式决定，且可被 `NEU_JWXT_DATA_DIR` 覆盖。

```python
# 页面读取 typed adapter，缓存过期时提交后台任务
entry, stale = read_cache(account, "scores")
if stale:
    submit_refresh(account, "scores", force=False, reason="page_swr")
```

完整协议见[缓存与数据一致性](缓存与数据一致性.md)和
[数据存储](数据存储.md)。

### 3.5 运行模式与访问边界

项目同时支持 `development / desktop / server`：

- `development` 保持仓库本地数据和开发调试能力。
- `desktop` 是只允许本机访问的 Windows 单实例服务，可从页面明确退出。
- `server` 是 Linux systemd 服务，只监听回环地址，由可信反向代理提供 HTTPS；进入
  NEU 登录前必须先通过独立网站访问密码。

生产模式关闭 Swagger/OpenAPI 和开放 CORS。服务器网站密码、个人数据 API、离线 API
和成绩追踪恢复路径的边界见[开发接手与变更规范](开发接手与变更规范.md)。

### 3.6 离线与缓存联动

离线模式不建立另一套业务数据，只读共享的成绩、培养计划与科研训练资源。成绩页、登录预热和
成绩追踪提交同一个 `scores` job；成绩 revision 真正变化后，事件订阅者生成通知并让
培养计划依赖失效、异步刷新。修改任一数据模型或刷新规则时，应同时检查成绩页、
培养计划、GPA 模拟、成绩追踪和离线返回。

## 4. 数据流

### 4.1 登录流程

```
用户调用 auth.login()
    │
    ▼
GET https://pass.neu.edu.cn/tpass/login
    │
    ▼
提取隐藏字段 (lt, execution)
    │
    ▼
RSA加密 (username + password)
    │
    ▼
POST https://pass.neu.edu.cn/tpass/login
    │
    ▼
跟随重定向到 jwxt.neu.edu.cn
    │
    ▼
设置 _logged_in = True
```

### 4.2 成绩缓存与刷新流程

```
页面/登录预热/追踪/手动刷新
    │
    ▼
CacheCoordinator single-flight
    │
    ▼
AuthSessionManager 共享 Session 互斥
    │
    ▼
AcademicAPI 获取所有学期成绩与系统总 GPA
    │
    ▼
canonicalize + revision + diff
    │
    ▼
CacheStore 原子提交；未变化只更新 last_checked_at
    │
    ▼
释放事务与 Session 锁后发布 CacheEvent
```

## 5. 类设计

### 5.1 NEUAuthClient

**职责：** CAS认证 + HTTP会话管理 + 子模块挂载

```python
class NEUAuthClient:
    # 核心属性
    username: str
    password: str
    timeout: int
    cookie_file: Optional[str]   # Cookie 持久化文件路径
    network_mode: str            # direct 或 webvpn
    active_mode: str             # 当前生效的访问方式
    _session: requests.Session
    _logged_in: bool
    _academic: AcademicAPI           # 延迟初始化
    _academic_report: AcademicReportAPI  # 延迟初始化
    _evaluation: EvaluationAPI       # 延迟初始化
    
    # 核心方法
    login(target) -> bool
    ensure_login() -> bool       # 自动恢复登录（Session/Cookie/密码）
    request(method, url, **kwargs) -> Response
    get(url, **kwargs) -> Response
    post(url, **kwargs) -> Response
    get_user_info() -> Dict      # 获取用户信息（含头像）
    get_avatar(token) -> bytes   # 获取头像图片
    clear_cookies() -> None      # 清除持久化的 Cookie
    
    # 属性
    @property
    academic -> AcademicAPI
    @property
    academic_report -> AcademicReportAPI
    @property
    evaluation -> EvaluationAPI
    @property
    is_logged_in -> bool
```

### 5.2 AcademicAPI

**职责：** 成绩数据获取 + 绩点计算

```python
class AcademicAPI:
    # 配置
    TERMS_URL: str
    SCORES_URL: str
    GPA_URL: str
    HEADERS: dict
    
    # 初始化
    _client: NEUAuthClient  # 反向引用
    
    # 方法
    get_terms() -> List[Dict]
    get_scores(term="") -> List[CourseScore]
    get_overall_gpa() -> float
    calculate_gpa(scores) -> float
    get_scores_by_term() -> List[TermScores]
```

### 5.3 数据模型

```python
@dataclass
class CourseScore:
    name: str                    # KCM 课程名称
    code: str                    # KCH 课程号
    score: str                   # XSZCJ 成绩（原始字符串，可能是"85"或"优良中合格"）
    gpa: float                   # JD 绩点（系统返回）
    credit: float                # XF 学分
    term: str                    # XNXQDM 学期代码
    term_display: str            # XNXQDM_DISPLAY 学期显示名
    course_type: str             # KCXZDM_DISPLAY 课程性质（必修/选修）
    course_category: str         # KCLBDM_DISPLAY 课程类别
    exam_type: str               # KSLXDM_DISPLAY 考核方式（考试/考查）
    is_passed: bool              # SFJG_DISPLAY 是否及格
    exam_status: str = ""        # CXCKDM_DISPLAY 初修/重修
    general_category: str = ""   # XGXKLBDM_DISPLAY 通识选修类别
    course_nature: str = ""      # KCXZDM 课程性质代码
    raw_data: Dict = field(default_factory=dict)  # 原始完整数据
    
    def get_score_value() -> float  # 获取用于排序/计算的数值成绩

@dataclass
class TermScores:
    term_code: str
    term_name: str
    courses: List[CourseScore]
    
    @property
    def total_credits -> float
    
    @property
    def gpa -> float  # 使用系统绩点计算
```

## 6. 扩展点

### 6.1 添加新模块

参考 `backend.core.academic` 的模式：

1. 在 `backend/core/` 下创建新包目录 `xxx/`
2. 实现 `api.py`，接收 `NEUAuthClient` 作为参数
3. 在 `NEUAuthClient` 添加 property 挂载点

```python
# backend/core/xxx/api.py
class XxxAPI:
    def __init__(self, auth_client):
        self._client = auth_client

# backend/core/auth/client.py
@property
def xxx(self):
    if self._xxx is None:
        from backend.core.xxx.api import XxxAPI
        self._xxx = XxxAPI(self)
    return self._xxx
```

### 6.2 添加新接口

在 `AcademicAPI` 中添加方法，遵循模式：

```python
def new_method(self, param: str) -> ReturnType:
    # 1. 构建请求
    resp = self._client.post(
        self.NEW_URL,
        data={"param": param},
        headers=self.HEADERS
    )
    
    # 2. 解析响应
    data = resp.json()
    if data.get("code") != "0":
        return default_value
    
    # 3. 提取数据
    rows = data["datas"]["xxx"]["rows"]
    
    # 4. 转换模型
    return [Model(r) for r in rows]
```

## 8. 编码规范

### 8.1 命名

- 类名: `PascalCase` (e.g., `AcademicAPI`)
- 方法/属性: `snake_case` (e.g., `get_scores`)
- 常量: `UPPER_CASE` (e.g., `TERMS_URL`)
- 私有属性: `_leading_underscore` (e.g., `_client`)

### 8.2 类型注解

所有公共方法必须添加类型注解：

```python
def get_scores(self, term: str = "") -> List[CourseScore]:
    ...
```

### 8.3 文档字符串

类和方法必须包含文档字符串：

```python
def calculate_gpa(self, scores: List[CourseScore]) -> float:
    """
    计算GPA
    
    公式: Σ(绩点×学分)/Σ学分
    
    Args:
        scores: 成绩列表
        
    Returns:
        GPA值
    """
```

## 9. 测试策略

### 9.1 单元测试

- `backend/tests/` 覆盖数据模型、解析、业务规则、认证流程和 Router 行为。
- 外部响应使用最小化、匿名化夹具；至少包含正常、空数据、缺字段和结构变化。
- 修复回归问题时先增加能复现问题的测试，再验证修复。

### 9.2 集成测试

- `tests/` 覆盖生产静态资源挂载、运行模式、访问网关和发行边界。
- 前端生产构建完成后再运行依赖 `frontend/build` 的测试。
- 界面需求还需浏览器验证，构建成功不能代替交互、手机布局和无障碍验收。

### 9.3 测试账号

真实账号只用于本地人工端到端验证，不写入源文件、测试、文档、命令历史或 CI。测试
数量和 GPA 不能固定为某个学生的结果。学校接口变化无法自动验证时，在交接说明中明确
记录已使用的匿名化响应范围和未验证项。

## 认证模块 (backend.core.auth)

### NEUAuthClient

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|

- `_session`: requests.Session 实例
