# 前端设计规范

本规范用于 NEU 教务系统工具箱的界面设计与实现。目标是在不改变业务行为的前提下，让信息密集型教务工具保持清晰、稳定、易扫描，并在桌面与移动设备上都可完成核心操作。

## 1. 设计原则

1. **任务优先**：首屏直接呈现当前业务，不使用营销式大标题或装饰性版块。
2. **信息分层**：应用导航、页面上下文、操作区、数据区四层明确；不使用卡片嵌套表达普通页面分区。
3. **一致胜于新奇**：相同语义使用相同颜色、间距、控件和反馈方式。
4. **状态可见**：加载、空数据、错误、禁用、刷新中和提交中必须有明确状态，异步操作不可只依赖颜色反馈。
5. **按场景适配且能力等价**：移动端不是缩小后的桌面端。根据移动用户“没有电脑、需要快速获取或操作”的场景重新安排默认内容、信息密度与交互方式；所有合法能力必须通过适合触屏的入口可达。
6. **克制表达**：颜色用于品牌、状态和操作优先级；阴影只表示浮层或轻微层级，不作为常规分区手段。
7. **自适应组合而非机械折叠**：多设备适配应重新组合信息和操作。不要因为手机空间小就
   给每一段内容增加折叠、卡片或彩色标签；短而重要的信息直接显示，只有明显次级且
   较长的内容才适合按需展开。

## 2. 设计令牌

令牌定义在 `frontend/src/App.css`，Ant Design 映射定义在 `frontend/src/App.js`。业务样式优先引用 CSS 变量，不直接复制色值。

| 语义 | 令牌 | 用途 |
|---|---|---|
| 品牌色 | `--color-brand` | 主按钮、链接、主要信息 |
| 强品牌色 | `--color-brand-strong` | 悬停或高对比品牌元素 |
| 强调色 | `--color-accent` | 少量品牌识别，不用于大面积背景 |
| 成功 | `--color-success` | 已完成、通过、成功反馈 |
| 警告 | `--color-warning` | 待处理、容量临界、风险提示 |
| 危险 | `--color-danger` | 失败、冲突、不可逆操作 |
| 正文 | `--color-ink` | 标题和正文 |
| 次要文字 | `--color-muted` | 标签、辅助信息 |
| 画布 | `--color-canvas` | 应用背景 |
| 表面 | `--color-surface` | 卡片、表格、浮层 |
| 边界 | `--color-line` | 主要分隔线 |
| 导航底色 | `--color-nav` | 浅色侧栏和移动导航 |

界面字体统一使用 `--font-sans`。不得单独引入未随项目加载的字体名称，也不得使用 `450 / 550 / 650` 等可能触发浏览器合成的字重；正文、强调和标题分别使用 `400 / 600 / 700`。

配色采用中性灰画布、白色表面和标准蓝主色。蓝色只表示主要操作、选中态与信息；绿色只表示成功，橙色只表示提醒，红色只表示错误或危险。成绩、状态等标签必须使用统一的浅底深字状态色，不得再新增青色、紫色等近似语义颜色。

间距采用 4px 基准：`4 / 8 / 12 / 16 / 20 / 24 / 32`。页面主间距使用 24px，移动端使用 12-16px。圆角限制为 `4 / 6 / 8px`；业务卡片不得使用更大的胶囊式圆角。

## 3. 页面框架

- 桌面端侧栏宽 240px，折叠后 80px；侧栏固定，内容区独立滚动。
- 移动端不保留窄侧栏，使用左侧抽屉导航。
- 顶栏高 72px，移动端 64px；顶栏只承载导航开关、当前页名和用户菜单。
- 内容最大宽度为 1440px，居中显示。培养计划等桌面分栏页仍遵守该宽度，内部左侧导航
  限制在稳定的最小/最大宽度，右侧数据区自适应取得其余空间。页面不再套一层白色大卡片。
- 页面标题由主框架统一展示；业务页只在需要独立上下文或操作时增加局部标题栏。

## 4. 组件规则

### 按钮

- 一个操作组最多一个主按钮。
- 手机端同级的 2-3 个按钮使用等宽网格或明确的主次比例，不允许自然换行后形成
  “上一行两个、下一行一个”的残缺布局。超过 3 个操作时保留主操作，并把语义相关的
  次要操作合并到“导入”“更多”等菜单；所有能力仍须在两次操作内可达。
- 破坏性操作使用危险样式，并在不可逆时二次确认。
- 仅图标按钮必须有 `aria-label` 或 Tooltip。
- 按钮文案使用动宾结构，例如“刷新数据”“导出 ICS”。进行中状态保留原按钮宽度。

### 卡片与统计

- 卡片只用于独立、可重复的信息单元，或明确边界的工具。
- 页面章节优先使用留白与分隔线，不把卡片放进卡片。
- 手机端的同组统计优先合并成一个摘要表面，用细分隔线组织，不为每个数字创建不同
  颜色和独立阴影。状态标签只保留真正影响决策的状态，不把普通元数据全部标签化。
- 同组统计卡高度一致，数字使用等宽数字特性；状态色只用于关键数值或图标。
- 卡片标题 15px，页面上下文标题 17-22px，避免面板内使用展示型大字。

### 表格

- 数据表默认支持横向滚动，关键列固定在左侧需谨慎使用。
- 表头 13px、半粗体；数字右对齐，操作列固定宽度。
- 桌面表头保持单行；字段过多时优先利用可用工作区宽度，再使用横向滚动，不把短标题
  挤成两行。单位已由表头或上下文表达时，数字单元格不重复显示单位。
- 筛选、排序、列设置与分页行为遵循 `前端开发.md`。
- 空状态、加载状态与错误状态不得共用同一文案。
- 桌面端可以使用横向滚动承载完整字段，但横向滚动不是手机端信息密集页面的默认解决方案。
- 手机端应优先将表格转换成任务卡片、摘要列表或主从详情。每个条目只直接展示完成当前任务所需的字段，其余字段放入详情、抽屉或“更多”操作。

### 表单与反馈

- 表单标签靠近输入项，必填校验在提交前后都应明确。
- 成功使用轻量消息；需要用户处理的问题使用 Alert；复杂或危险确认使用 Modal。
- 状态不能只用红绿区分，必须同时有文字、图标或形状差异。
- 加载超过 300ms 时显示加载反馈；提交期间禁用重复提交。

## 5. 手机端需求工程

### 5.1 使用场景

手机端首先服务以下场景：

1. 临时没有电脑，需要快速确认成绩、考试时间、课程状态等结果。
2. 在移动途中单手操作，注意力和连续操作时间有限。
3. 屏幕窄而长，横向比较能力弱，但适合纵向扫描少量高价值条目。
4. 网络可能不稳定，需要尽快看到本地数据、缓存结果和明确状态。

设计前必须先回答“用户此刻最想得到的答案是什么”，再决定字段与组件。不得以桌面表格已有字段为理由，将所有信息原样搬到手机端。

### 5.2 信息优先级

移动端信息分为三级：

| 层级 | 定义 | 呈现方式 |
|---|---|---|
| 核心信息 | 用户打开页面后立即需要的答案 | 首屏直接展示，使用醒目但克制的数值、状态或时间 |
| 决策信息 | 帮助判断下一步的信息 | 卡片次级区域、简洁标签或三项以内的摘要 |
| 管理信息 | 课程代码、完整类别路径、列配置、历史字段等低频信息 | 详情页、抽屉或“更多”菜单 |

默认视图可以与桌面端不同，但必须满足：

- 默认结果能直接回答页面的主要问题。
- 隐藏的是低频信息，不是关键状态或必要操作。
- 用户可以通过不超过两次操作进入“全部”或详细视图。
- 桌面端存在的合法筛选、详情、导入、导出、保存和写操作必须有手机入口；不能以低频
  或屏幕较窄为由删除能力。
- 切换视图后保留明确的筛选状态，并提供空状态说明。

### 5.3 页面默认策略

#### 成绩

- 默认展示最近学期，而不是全部历史成绩。
- 单条课程优先展示课程名、成绩、是否通过；绩点和学分作为决策信息。
- 课程代码、课程类别、考核方式和列设置属于管理信息，不常驻首屏。
- 提供“最近 / 未通过 / 全部”等直接对应用户目的的快捷视图。

#### 培养计划

- 默认展示待完成课程，已选课程优先于普通未修课程，必修课程优先于选修课程。
- 单条课程优先展示课程名、状态、学分、性质和计划学期。
- 类别树不得占据手机首屏，应通过“选择类别”抽屉按需打开。
- 统计区只保留“待完成、已选课程、还差学分”等能指导行动的信息。
- 提供“待完成 / 已选 / 全部”快捷视图；完整类别路径和课程代码按需查看。

其他信息密集页面参照同一方法确定默认策略，不直接复制上述字段组合。

### 5.4 窄长屏布局

- 以宽度决定主要断点，支持最小 320px；不得仅针对某一种手机型号写固定尺寸。
- `md` 以下优先使用纵向信息流。卡片内部一般不超过 3-4 个并列字段，320px 下应能继续降为两列或单列。
- 默认分页每页建议 10 条，避免一次渲染过长列表；分页使用简洁模式并居中。
- 页面首屏顺序为：页面上下文、核心摘要、任务视图切换、结果列表、次要信息。
- 工具栏允许换行，但主操作应保持可见；低频操作可收进菜单或抽屉。
- 导航和辅助抽屉宽度不超过视口的 90%；承载完整详情或长流程表单的移动抽屉可以使用
  全宽。弹层需保留可见关闭入口，并避免产生页面横向滚动。
- 短筛选、少量选项和确认信息使用内容自适应的底部弹层：高度由实际内容决定，只设置
  视口上限，不能固定占据大部分屏幕留下空白。长筛选、文件列表和表单超过上限后只让
  正文滚动，标题与底部操作保持可见。
- 手机弹窗同样遵循“内容高度优先、视口高度兜底”。纵向重排桌面列表时必须清除遗留的
  `flex-grow`、固定高度和桌面外边距，避免单条记录把操作按钮推到屏幕之外。
- 不依赖悬停展示手机端必要信息；桌面悬浮面板在触屏上必须有点击、展开或独立入口。
- 使用 `100vh` 时应考虑移动浏览器地址栏变化。长列表页面优先使用自然文档流，不锁定整页高度。

### 5.5 移动端交互

- 交互文案使用用户目标，而不是实现术语，例如“未通过”“待完成”“选择类别”，避免“筛选字段”“配置列”等桌面管理语言。
- 高频切换可使用 Segmented；选项通常不超过 3 个，必须有明确默认值。
- 不把“可折叠”当作节省空间的默认答案。三四项简短条件、资格或统计应直接组成紧凑
  摘要；长说明、层级树和长表单才进入抽屉或展开区。
- 点击卡片可进入详情时，整张卡片应有一致反馈；卡片内部存在独立按钮时避免点击冲突。
- 响应式工具栏、筛选抽屉、详情抽屉和底部操作栏优先复用
  `frontend/src/components/mobile/MobileUX.js`，不在每页重新定义交互语义。
- 固定底部操作区必须为正文预留空间，并使用 `env(safe-area-inset-bottom)`；虚拟键盘
  打开时长表单仍需能滚动到当前输入项和提交入口。
- 含输入框的移动弹层应跟随 `window.visualViewport` 的实际可见高度；键盘弹出时缩小
  弹层上限并把当前输入项滚入可见区域，不能让键盘覆盖关闭入口、正文滚动区或提交按钮。
- 切换类别或视图后回到第一页；翻页后将用户带回结果区或页面顶部。
- 空结果不是错误，应说明当前条件下没有需要关注的内容。
- 刷新、加载和离线数据状态应简短明确，不挤占核心信息区域。

## 6. 响应式与可访问性

- 支持宽度从 320px 开始，断点以 Ant Design 的 `sm / md / lg / xl` 为准。
- 触控目标建议不小于 40x40px；紧凑表格中的次要操作可例外，但必须保持可点击间距。
- 所有交互元素必须可键盘聚焦，焦点环不可移除。
- 文本与背景保持足够对比；次要文字不能浅到影响阅读。
- 尊重 `prefers-reduced-motion`，减少动画时关闭位移和过渡动画。
- 动态状态使用 `aria-live`，图标按钮提供可读名称，页面地标使用 `main / nav / header`。

## 7. 实现与验收

新增或修改页面时检查：

- [ ] 使用现有令牌和 Ant Design 主题，不增加近似色或新圆角值
- [ ] 主要任务在首屏可见，操作优先级明确
- [ ] 手机端默认内容来自用户目的，而不是桌面字段的机械缩减
- [ ] 核心、决策和管理信息已经分级，低频信息可在两次操作内访问
- [ ] 同级按钮在窄屏下等宽或按主次稳定排布，没有孤立换行和大片无意义空白
- [ ] 没有为了缩短首屏而给短信息机械增加折叠、卡片、标签或颜色
- [ ] 已按[移动端能力矩阵](移动端能力矩阵.md)逐项核对，不存在只能在桌面端完成的合法能力
- [ ] 信息密集表格在手机端已评估卡片、摘要列表或详情模式，不默认依赖横向滚动
- [ ] 快捷视图有明确默认值、选中状态、分页复位和空状态
- [ ] 加载、空、错误、成功和禁用状态齐全
- [ ] 320×800、375×812、430×932、768px 和 1440px 宽度无重叠、横向溢出或不可达操作
- [ ] 表格可滚动，按钮组可换行，长文本不撑破容器
- [ ] 手机端首屏先出现结果和核心操作，不被类别树、长说明或完整统计占据
- [ ] 抽屉、弹窗、分页和卡片在触屏下具有足够点击区域
- [ ] 短弹层没有固定大高度或无意义空白；长弹层正文可滚动且标题、关闭和提交始终可见
- [ ] 输入框聚焦和虚拟键盘弹出后，当前字段及底部操作仍可到达
- [ ] 键盘可访问，图标按钮有名称，颜色不是唯一状态线索
- [ ] `npm run build` 通过，并完成关键流程的浏览器检查
