# 前端设计规范

本规范用于 NEU 教务系统工具箱的界面设计与实现。目标是在不改变业务行为的前提下，让信息密集型教务工具保持清晰、稳定、易扫描，并在桌面与移动设备上都可完成核心操作。

## 1. 设计原则

1. **任务优先**：首屏直接呈现当前业务，不使用营销式大标题或装饰性版块。
2. **信息分层**：应用导航、页面上下文、操作区、数据区四层明确；不使用卡片嵌套表达普通页面分区。
3. **一致胜于新奇**：相同语义使用相同颜色、间距、控件和反馈方式。
4. **状态可见**：加载、空数据、错误、禁用、刷新中和提交中必须有明确状态，异步操作不可只依赖颜色反馈。
5. **渐进适配**：移动端保留完整功能。导航改为抽屉，表格允许横向滚动，操作组允许换行，不隐藏关键操作。
6. **克制表达**：颜色用于品牌、状态和操作优先级；阴影只表示浮层或轻微层级，不作为常规分区手段。

## 2. 设计令牌

令牌定义在 `frontend/src/App.css`，Ant Design 映射定义在 `frontend/src/App.js`。业务样式优先引用 CSS 变量，不直接复制色值。

| 语义 | 令牌 | 用途 |
|---|---|---|
| 品牌色 | `--color-brand` | 主按钮、链接、主要信息 |
| 强品牌色 | `--color-brand-strong` | 悬停或高对比品牌元素 |
| 强调色 | `--color-accent` | 少量品牌识别，不用于大面积背景 |
| 成功 | `--color-success` | 已完成、通过、成功反馈 |
| 警告 | `--color-warning` | 待处理、容量临界、风险提示 |
| 危险 | `--color-danger` | 失败、冲突、不可逆操作 |
| 正文 | `--color-ink` | 标题和正文 |
| 次要文字 | `--color-muted` | 标签、辅助信息 |
| 画布 | `--color-canvas` | 应用背景 |
| 表面 | `--color-surface` | 卡片、表格、浮层 |
| 边界 | `--color-line` | 主要分隔线 |
| 导航底色 | `--color-nav` | 浅色侧栏和移动导航 |

界面字体统一使用 `--font-sans`。不得单独引入未随项目加载的字体名称，也不得使用 `450 / 550 / 650` 等可能触发浏览器合成的字重；正文、强调和标题分别使用 `400 / 600 / 700`。

配色采用中性灰画布、白色表面和标准蓝主色。蓝色只表示主要操作、选中态与信息；绿色只表示成功，橙色只表示提醒，红色只表示错误或危险。成绩、状态等标签必须使用统一的浅底深字状态色，不得再新增青色、紫色等近似语义颜色。

间距采用 4px 基准：`4 / 8 / 12 / 16 / 20 / 24 / 32`。页面主间距使用 24px，移动端使用 12-16px。圆角限制为 `4 / 6 / 8px`；业务卡片不得使用更大的胶囊式圆角。

## 3. 页面框架

- 桌面端侧栏宽 240px，折叠后 80px；侧栏固定，内容区独立滚动。
- 移动端不保留窄侧栏，使用左侧抽屉导航。
- 顶栏高 72px，移动端 64px；顶栏只承载导航开关、当前页名和用户菜单。
- 内容最大宽度为 1440px，居中显示。页面不再套一层白色大卡片。
- 页面标题由主框架统一展示；业务页只在需要独立上下文或操作时增加局部标题栏。

## 4. 组件规则

### 按钮

- 一个操作组最多一个主按钮。
- 破坏性操作使用危险样式，并在不可逆时二次确认。
- 仅图标按钮必须有 `aria-label` 或 Tooltip。
- 按钮文案使用动宾结构，例如“刷新数据”“导出 ICS”。进行中状态保留原按钮宽度。

### 卡片与统计

- 卡片只用于独立、可重复的信息单元，或明确边界的工具。
- 页面章节优先使用留白与分隔线，不把卡片放进卡片。
- 同组统计卡高度一致，数字使用等宽数字特性；状态色只用于关键数值或图标。
- 卡片标题 15px，页面上下文标题 17-22px，避免面板内使用展示型大字。

### 表格

- 数据表默认支持横向滚动，关键列固定在左侧需谨慎使用。
- 表头 13px、半粗体；数字右对齐，操作列固定宽度。
- 筛选、排序、列设置与分页行为遵循 `前端开发.md`。
- 空状态、加载状态与错误状态不得共用同一文案。
- 手机端不强行压缩列宽；保留横向滚动和清晰触控目标。

### 表单与反馈

- 表单标签靠近输入项，必填校验在提交前后都应明确。
- 成功使用轻量消息；需要用户处理的问题使用 Alert；复杂或危险确认使用 Modal。
- 状态不能只用红绿区分，必须同时有文字、图标或形状差异。
- 加载超过 300ms 时显示加载反馈；提交期间禁用重复提交。

## 5. 响应式与可访问性

- 支持宽度从 320px 开始，断点以 Ant Design 的 `sm / md / lg / xl` 为准。
- 触控目标建议不小于 40x40px；紧凑表格中的次要操作可例外，但必须保持可点击间距。
- 所有交互元素必须可键盘聚焦，焦点环不可移除。
- 文本与背景保持足够对比；次要文字不能浅到影响阅读。
- 尊重 `prefers-reduced-motion`，减少动画时关闭位移和过渡动画。
- 动态状态使用 `aria-live`，图标按钮提供可读名称，页面地标使用 `main / nav / header`。

## 6. 实现与验收

新增或修改页面时检查：

- [ ] 使用现有令牌和 Ant Design 主题，不增加近似色或新圆角值
- [ ] 主要任务在首屏可见，操作优先级明确
- [ ] 加载、空、错误、成功和禁用状态齐全
- [ ] 375px、768px、1440px 三种宽度无重叠或不可达操作
- [ ] 表格可滚动，按钮组可换行，长文本不撑破容器
- [ ] 键盘可访问，图标按钮有名称，颜色不是唯一状态线索
- [ ] `npm run build` 通过，并完成关键流程的浏览器检查
