# 课程大纲

## 能力边界

课程大纲是独立的只读领域模块，入口为“课程大纲”。列表、详情分段和历史附件均实时读取
教务系统 `kccx` 应用，不进入 `cache.db`、LocalStorage、GPA 文件或离线数据。页面关闭后，
完整大纲只保留在浏览器内存中。

系统仅允许持久化课程代码对应的以下最小元数据：考核方式、成绩分制、大纲版本、培养计划
课程指纹、同步状态和时间。禁止保存课程简介、教材、目标、教学安排、考核正文、附件内容等。

## 官方请求与公共 API

后端 `backend/core/course_outline/` 统一适配官方列表、查询模型、初始化、基本信息、教材、
课程目标、教学与达成、成绩评定、考核矩阵、质量改进、编制信息和历史附件请求。响应解析兼容
顶层 `rows` 与 `datas.<action>.rows`，单个分段失败只影响该分段。

开课单位、课程层次和课程级别直接读取教务系统页面使用的三个 `jwapp/code` 字典接口，不再从
页面模型中猜测字典。详情接口在领域层完成语义化：只返回中文标签、正文、教学安排、达成标准、
考核矩阵和编制信息等展示结构，`WID`、`BBWID` 以及各类关系键不会进入前端通用渲染。

公共 API：

- `GET /api/course-outlines/search-schema`
- `POST /api/course-outlines/search`
- `POST /api/course-outlines/detail/overview`
- `POST /api/course-outlines/detail/sections`
- `POST /api/course-outlines/attachments/download`
- `GET /api/course-outlines/metadata/plan`
- `POST /api/course-outlines/metadata/read`（按课程代码读取当前账号的本地元数据，供成绩等页面复用）
- `POST /api/course-outlines/metadata/sync`
- `GET /api/course-outlines/metadata/sync/status`
- `POST /api/course-outlines/metadata/sync/cancel`

搜索和详情响应使用 `Cache-Control: no-store`。课程代码只从 POST 请求体接收，并经过字符、
长度和批量数量校验。附件令牌经过白名单校验后由后端转发，不保存附件副本。

## 页面行为

独立页面默认服务端分页显示全部课程。课程代码和名称合并为一个主搜索框；进一步筛选提供开课
单位、课程层次、课程级别，以及带明确常用区间的学分和学时选项，不显示含义不明的裸“最小/
最大”输入。搜索延迟 300ms，新的搜索会取消旧请求。详情抽屉先显示概览，再依次加载教学、
考核和编制分组；每组可独立失败和重试，关闭抽屉不会替换列表状态。

详情目录位于抽屉内容顶部并吸附显示，不占用正文横向空间。概览按“考核方式/成绩分制/课程性质、
核心属性、课程简介、教材”组织；其余内容按信息卡、教学安排和考核矩阵分别渲染，不直接遍历远端
对象键名。

“下载大纲”在浏览器端补齐所有分段并生成自包含 HTML。远端文本全部转义，文件可离线打开、
打印或另存为 PDF，历史附件二进制不嵌入文件。

## 培养计划与 GPA

培养计划默认显示“考核方式”和“成绩分制”，因此首次进入页面即读取缓存并按需启动配对同步；
用户仍可在列设置中关闭，关闭两列只停止本页监听，不取消账号共享队列。同步失败不阻塞培养计划，
可在列设置中重试失败项。课程名和移动详情可直接打开大纲抽屉。

GPA 培养计划导入显示两项元数据与大纲入口。导入后两项值复制进模拟课程快照，保存和重新打开
仍可使用；完整大纲不写入 GPA 文件。GPA 总表默认显示成绩分制，自定义课程显示“未设置”。

成绩页列设置提供默认隐藏的“成绩分制”。用户首次开启后，先复用培养计划已经补全的账号级元数据，
再只对成绩中仍缺失的课程代码启动同一套后台补全，并将最小元数据写入
`course-outline-metadata` 缓存；课程不在当前培养计划中也能读取。同步和缓存失败不阻塞成绩加载，
完整大纲仍不会被保存。

培养计划与成绩页通过同一个前端元数据协调 Hook 接入缓存：页面进入时先做一次 cache-only 读取，
已有值不等待后台任务状态；缺失或后端标记 `needs_sync` 的课程提交一次后台 single-flight 同步。
状态每 5 秒串行检查，批次结束后一次合并缓存；结束后仍接收全局 `neu-cache-event`，以观察其他
页面的后续补全。提交碰到已有共享批次时，等待结束后重新核对本页缺失项，不能把复用状态当作接单。
请求连续失败三次，或任务连续两分钟无进展且复查仍未恢复，停止本页加载并保留已有值与可重试状态；
不取消账号共享任务。禁止页面短周期反复全量读取元数据。

后台补全只请求初始化和基本信息，不再读取教材、简介等正文。基本信息失败或响应结构异常属于
同步失败，不能保存为“无大纲”；合法空列表才允许负缓存。元数据 Schema 2 对旧条目保留显示并
触发重新核验，成功条目遵循 Registry 时效，负缓存按最近成功检查时间最多复用 7 天。

## 开发验收

`tools/check_course_outline_metadata.cjs` 使用已有生产构建和匿名模拟接口，检查
320/375/430/768/1440px 下的缓存先显、仅提交缺失课程、终态合并、加载结束及页面边界。
从仓库根目录运行 `node tools/check_course_outline_metadata.cjs`；需要已有 Playwright 与 Edge，
可用 `PLAYWRIGHT_MODULE` 指定现有模块路径。脚本自行启动临时静态服务并在结束时关闭，
不启动真实后端、不登录或访问学校系统，截图保存在系统临时目录。
