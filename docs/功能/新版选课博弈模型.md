# 新版选课博弈模型

## 文档状态

本文先固化选课机制、经验规律和下一版模型假设，再讨论计算方法。当前代码仍是
`course-selection-contest-v1`：它使用参考项目改进后的连续指数竞争函数和整数动态
规划。本章提出的“容量分型 + 隐含中选线”模型是下一版设计稿，**尚未写入代码**。

这样区分是必要的：在没有新版真实接口、历史投权和最终录取结果时，不能因为公式已经
写出，就把经验假设描述成已经验证的事实。

## 经验假设的核心用途

本文中的容量分型、超额比例和 90–105 现象，首要用途不是把推荐结果直接硬编码成
`if/else`，而是构成候选数学模型的**行为验收集**。

模型可以采用连续竞争函数、隐含中选线分布、均衡近似或其他方法，但必须在控制其余
变量后自然体现这些经验现象。若一个模型出现以下行为，即使推导形式完整，也应判为
不合格：

- 人数未超过容量时仍建议为该课程投入大量竞争权重。
- 小班课从轻度拥挤变成双倍容量后，所需权重反而下降。
- 大班课只超额 20–30 人时，直接把 90–105 当作唯一有效区间。
- 大班课达到 1.5 倍或 2 倍容量后，仍认为 20–50 权重具有很高中选率。
- 相同输入只改变课程排列顺序，推荐结果就发生变化。

经验验收只能约束模型应呈现的方向、门槛和相对关系，不能证明模型给出的具体百分比
准确。模型通过行为验收后，仍需使用真实历史结果校准和回测。

## 当前建模采用的制度设定

以下设定用于当前研究，但新版真实接口尚未核验，不能全部视为学校正式规则：

- `[用户确认]` 每名学生本轮总权重默认 105，最低有效投权为 5，权重按整数分配。
- `[用户经验]` 学生倾向于把本轮全部权重投入喜欢的课程；权重能否跨轮保留仍待接口确认。
- `[用户经验]` 终局人数未超过容量时不需要竞争，只需投入最低权重 5。
- `[继承参考背景]` 超容量后按投权排序录取前 `C` 人；真实排序和特殊名额规则待确认。
- `[待接口确认]` 截止前可以调整投权，当前人数是过程快照而不是最终人数。
- `[待接口确认]` 同权重排序未知，不能假定一定随机或一定失败。

目标用户希望在总预算约束下，提高所喜欢课程的总中选价值。课程偏好采用相对效用
`u_j` 表示；如果用户没有区分优先级，则所有喜欢课程的效用相同。

## 可观察量与不可观察量

对课程 `j`，当前可以合理期待新版接口提供：

- `C_j`：课程容量。
- `N_j^raw`：接口当前快照中的有效选课人数。
- `target_included`：目标用户是否已经计入 `N_j^raw`。
- `A_j^now = N_j^raw - I(target_included)`：规范化后的当前匿名对手数。
- 快照时间和选课截止时间。

后续验证还使用以下变量：

- `tau_j`：快照距离截止时间；终局时为 0。
- `N_j^final = A_j^final + 1`：包含目标用户后的终局有效总人数，只能在截止后观察。
- `N_j^low/base/high = A_j^low/base/high + 1`：包含目标用户后的三种预测终局总人数。
- `E=max(N-C,0)`、`r=N/C`：行为验收统一使用上述“已包含目标用户”的 `N` 计算。
- `T_j`：该课程终局最后一名中选者的权重，即隐含中选线。
- `b`：被验证学生对该课程的投权。
- `Y`：最终是否中选，取 0 或 1。

模型看不到：

- 其他学生分别投了多少权重。
- 其他学生的课程偏好、替代课程和剩余预算。
- 同权重时的真实排序规则。
- 当前人数到截止人数之间的稳定变化规律。

因此，聚合人数不能唯一推出真实中选概率。下一版计划估计“达到中选线所需权重”的
范围，再把范围转换为模型内中选率；当前 `contest-v1` 尚未估计 `T`，仍由 `rho` 直接
输出未校准指数代理率。后续有历史数据后，应直接校准中选线分布，而不是继续叠加不可
验证的行为假设。

## 经验假设

以下假设来自实际选课经验，属于个案归纳，不是学校规则或已验证结论。它们作为下一版
模型的首批“预注册假设”：先固定分界和预期方向，再使用真实数据证伪，避免看到结果后
反复调整区间以迎合样本。

本节若不带上标地写 `N/E/r`，一律指终局有效人数 `N^final`，或截止前模型正在评估的
某个预测终局情景 `N^low/base/high`，不指接口原始人数 `N^raw`。行为验收使用终局数据；
在线推荐使用预测终局情景。

### H1：容量内只投最低权重

只有终局 `N_j^final` 不超过 `C_j`，或截止前的悲观预测 `N_j^high` 仍不超过 `C_j`，
该课程才归类为“无需竞争”：

```text
recommended_bid = 5
model_success_rate = 1
```

在完整预算必须用完的情况下，多余权重应放到确实需要竞争的课程；只有所有目标课程都
无需竞争时，才把无法产生边际收益的剩余权重集中放置并明确标记为冗余权重。

### H2：容量类型会改变竞争行为

相同的 `r=N/C` 不一定代表相同难度。小班课和大班课的参与者数量、平票密度和学生
分配预算的方式不同，因此不能只使用一个全局连续函数。

行为验收预先固定以下容量分型，候选模型不一定必须在内部使用离散分支：

| 类型 | 容量 | 模型解释 |
|---|---:|---|
| 小班课 | 30–60 | 容易出现人数快速达到 1.5 倍乃至 2 倍容量；拥挤后权重竞争明显增强 |
| 过渡课 | 61–99 | 暂无足够经验，参数在小班课和大班课之间插值，不单独宣称规律 |
| 大班课 | ≥100 | 绝对超额 20–30 人时仍存在较宽投权博弈空间；严重拥挤时中选线会靠近预算上限 |

容量低于 30 的特殊课程、容量为动态值的课程以及分专业保留名额课程暂不套用上述
先验，应标记为“规则未知”。

### H3：小班课主要看需求容量比

小班课容量只有 30–60 人，绝对人数较小，终局 `r=N/C` 对竞争强度的解释力可能更强。
行为验收按下列终局区间划分场景：

| 需求容量比 | 状态 | 固化假设 |
|---:|---|---|
| `r <= 1` | 无需竞争 | 投 5 |
| `1 < r < 1.25` | 轻度竞争 | 中选线开始高于最低权重，但仍有分散投权空间 |
| `1.25 <= r < 1.5` | 中度竞争 | 需要明显增加投权，低权重方案风险上升 |
| `1.5 <= r < 2` | 高度竞争 | 更倾向把预算集中到少数高效用课程 |
| `r >= 2` | 极端竞争 | 已达到至少双倍容量；高权重成为主要策略，但不预先断言必须达到 90 |

最后一条特意与大班课区分：目前经验只说明小班课双倍容量时倾向更高权重，还不足以
断言其真实中选线必然与大班课一样落在 90–105。

### H4：大班课同时看绝对超额和比例超额

大班课中，终局超额 20–30 人和超额半个容量不是同一种状态。例如容量 150、终局人数
175，
虽然已经超出 25 人，但 `r≈1.17`，仍有较大的权重博弈空间；不能直接判为必须满权。

行为验收按下列场景分组：

| 条件 | 状态 | 固化假设 |
|---|---|---|
| `N <= C` | 无需竞争 | 投 5 |
| `0 < E <= 30` 且 `r < 1.5` | 可博弈 | 中低到中高权重都可能有意义，不能硬编码成 90+ |
| `E > 30` 且 `r < 1.5` | 强竞争 | 中选线继续上升，但仍需根据容量和快照阶段估计 |
| `r >= 1.5` | 极端竞争 | 低于 90 的权重视为中选希望很低，主要可行区间为 90–105 |
| `r >= 2` | 超极端竞争 | 即使 90–105 也不能承诺中选，只能视为争夺极少数高权名额 |

“超出半个容量”在本文中明确指 `N >= 1.5C`；“达到双倍容量”指 `N >= 2C`，避免把
“超出两倍容量”和“人数达到两倍容量”混为一谈。

### H5：严重拥挤存在门槛效应

大班课终局达到 `r>=1.5` 后，不宜继续用一条从 5 到 105 平滑上升的普通指数曲线。经验
假设是：中选线分布会显著向 90–105 集中，89 与 90 附近可能产生比普通一步更大的
策略差异。

该假设可以通过“隐含中选线”表达并验证，而不是直接写成“投 90 必中”：

```text
T_j = 课程 j 截止时最后一名中选者的权重
success(b) = P(T_j <= b)
```

对于严重拥挤的大班课，行为验收要求候选模型把 `T_j` 的主要质量推向 `[90,105]`。
这应当是模型结合容量、人数和预算后产生的结果，而不是在输出层看到 `r>=1.5` 就直接
返回 90。没有历史数据时只能报告低、中、高三个中选线情景，不能伪造个位数精度。

### H6：课程之间通过总预算耦合

每个学生只有 105 权重。一名学生若对某门课投入 90–105，就几乎放弃了同时竞争多门
热门课的能力。因此模型不能逐门独立给出“建议满权”后再简单相加，而应在统一预算下
同时求解所有目标课程。

这也是保留整数动态规划的理由：课程动作只能是 `0` 或不低于 5 的整数，且所有动作
总和必须等于 105。

## 标准行为验收场景

经验假设最终要落成模型测试，而不是只作为说明文字。验收分成“单课成功曲线”和
“完整预算组合”两层。

### 单课曲线验收

单课测试固定预算 105、最低投权 5、终局人数口径和相同的用户效用，只改变容量与终局
人数。候选模型至少满足：

| 场景 | 输入示例 | 必须体现的行为 |
|---|---|---|
| 容量内 | `C=150, N=140` | 投 5 的模型中选率为 1；继续加权对该课没有边际收益 |
| 容量边界 | `C=150, N=150` | `N` 已含目标用户，仍属于容量内，投 5 的模型中选率为 1 |
| 刚超容量 | `C=150, N=151` | 立即进入竞争状态，不得再次把目标用户加 1 |
| 小班轻度竞争 | `C=40, N=48` | 中选线高于 5，但仍保留分散预算的可能 |
| 小班双倍容量 | `C=40, N=80` | 中选线严格高于小班轻度竞争，低权重成功率明显下降 |
| 大班少量超额 | `C=150, N=175` | 20–30 人超额仍存在内部博弈区间，模型不能直接退化成“只有 90+ 有效” |
| 大班半容量超额 | `C=150, N=225` | 低于 90 的中选希望应很低，主要边际收益进入 90–105 |
| 大班双倍容量 | `C=150, N=300` | 90–105 也只能表示仍有争夺可能，不能输出必中特征 |

这里的 `N` 是包含目标用户后的终局有效人数。模型输出的具体概率仍待校准；验收先检查
单调性、相对强弱、门槛位置和是否出现不合理的 0/1 饱和。

### 完整预算组合验收

只放一门目标课程会产生伪测试：因为 105 必须全部用完，无论课程是否拥挤，优化器都
可能把 105 全投给它。因此组合验收固定一个标准偏好组合：

| 课程 | 容量与终局人数 | 相对效用 |
|---|---|---:|
| 被测目标课 | 按上表逐场景替换 | 10 |
| 固定替代课 A | `C=100, N=125` | 8 |
| 固定替代课 B | `C=50, N=65` | 6 |

完整市场中的其他背景课程、年级人数和平均参与门数保持不变，只替换被测目标课的
`C/N`。候选模型及整数优化器应满足：

- 容量内目标课只保留 5，其余预算转向替代课。
- 小班双倍容量时，目标课建议权重高于同一小班的轻度竞争场景。
- 大班只超额 25 人时，不应无条件把目标课推到 90–105。
- 大班达到 1.5 倍容量且目标课效用最高时，建议权重应进入或接近 90–105。
- 如果把目标课效用从 10 降到替代课以下，模型允许放弃极端拥挤目标课；“极端拥挤”
  不能覆盖用户偏好和预算机会成本。

上述断言属于模型验收目标，不要求模型内部使用相同的分段 `if/else`。实现时应测试候选
公式能否自然产生这些行为，并同时记录不符合预期的反例；不能在求解结果生成后再强制
把权重改成期望区间。

## 假设的证伪条件

经验模型不能只列支持案例。每条核心假设都预先给出反例和所需证据：

| 假设 | 可证伪命题 | 反例条件 | 所需证据 | 当前状态 |
|---|---|---|---|---|
| H-CAP 容量分型 | 容量在比例或绝对超额之外仍提供解释力 | `r+log(C)+tau` 不优于 `r+tau`，且 `E+log(C)+tau` 不优于 `E+tau` | 跨容量档的课程轮次 | 待验证 |
| H-RATIO 比例效应 | 小班课终局 `r=N/C` 能解释中选线上升 | ratio-only 在留出集不优于 excess-only，或 `r` 与 `T` 不单调 | 小班课终局人数和中选线 | 待验证 |
| H-EXCESS 绝对超额 | 大班课的绝对超额模型提供独立预测价值 | excess-only 或 `E+log(C)+tau` 不优于 ratio-only | 不同容量与超额组合的课程轮次 | 待验证 |
| H-HIGHBID 高权门槛 | 大班课终局 `r>=1.5` 时，`T` 的主要质量集中在 90–105 | 同条件下大量课程的真实 `T<90` | 终局中选线或带投权结果的区间删失数据 | 待验证 |
| H-TIME 时间效应 | 当前人数到终局人数的关系随 `tau` 改变 | 不同 `tau` 下的终局预测误差无显著差异 | 同一课程轮次的多时间点快照 | 待验证 |

其中“主要质量集中在 90–105”不能只凭一两个案例确认。获得样本后，需要预先规定确认
标准，例如报告 `T in [90,105]` 的课程轮次比例及置信区间；在样本量不足前一直保持
“待验证”。

当前实现只使用 `rho` 进入指数竞争尺度，没有独立的容量档、绝对超额或时间项。除
“是否超过容量”的分支外，相同 `rho` 的 30 人课和 300 人课当前会得到相同成功率
曲线；代码也没有把 90–105 编码成门槛。动态规划偶尔给出 90–105，不能当作经验假设
已经被模型验证。

## 下一版模型结构

下一版不直接从人数生成一个看似精确的百分比，而采用四阶段流程。

### 1. 预测截止人数

先由接口人数和 `target_included` 得到当前匿名对手数 `A_j^now`，再根据快照距离截止的
时间、历史变化速度和全市场人数变化，预测匿名对手：

```text
A_j^low <= A_j^base <= A_j^high
N_j^scenario = A_j^scenario + 1
```

真实接口尚未提供时间序列时，三者只是敏感性情景。行为验收和成功曲线只使用规范化后
已经包含目标用户的 `N_j^scenario`，不得再次加 1；这避免目标用户在乐观情景中消失，
也避免在容量边界被重复计数。

### 2. 识别竞争区间

使用预测终局人数计算 `E=N-C` 和 `r=N/C`，为每门课生成可解释的行为标签：

```text
SAFE / LIGHT / MODERATE / HEAVY / EXTREME
```

标签用于解释和验收，不要求数学核心采用离散分支。候选模型可以连续使用 `C/r/E/tau`
及其交互，但页面将来仍应展示解释，例如“容量 150，预测终局超额 25 人，属于大班课
可博弈场景”，而不是只展示一个无法解释的成功率。

### 3. 构造隐含中选线分布

每个竞争区间对应中选线的低位、基准和高位估计：

```text
T_j^low <= T_j^base <= T_j^high
```

目前只固化两个行为验收端点，不要求实现直接把它们写成返回值：

- `SAFE`：悲观预测终局人数仍不超容量时，中选线应为 5。
- 大班课 `EXTREME`：候选模型应自然把中选线主要质量推向 90–105。

小班课和大班课非极端区间的具体中选线数值暂不硬编码。它们需要由真实历史快照、
截止投权和录取结果校准；在此之前可以使用宽区间，宁可降低置信度，也不制造虚假的
个位数精度。

如果必须在无历史数据阶段形成连续曲线，可在 `[T_low,T_high]` 上使用分段线性或
Logistic 累积分布，并强制满足：

- 投权增加，中选率不下降。
- 人数增加，中选率不提高。
- 容量增加，中选率不降低。
- 大班课从可博弈区进入 `r>=1.5` 时，中选线出现向 90–105 的门槛跃迁。
- 终局或悲观预测终局 `N<=C` 时，投 5 的中选率固定为 1。

### 4. 在统一预算下优化

目标课程 `j` 的效用为 `u_j`，合法投权为：

```text
b_j in {0} union {5, 6, ..., 105}
sum(b_j) = 105
```

在每门课的中选线分布确定后，整数动态规划分别求解：

- 稳健方案：最大化高位中选线情景下的总效用。
- 均衡方案：综合低位、基准和高位情景。
- 进取方案：允许承担高位中选线风险，优先争取高效用课程。

所有方案都必须同时返回未投课程、冗余权重、触发的经验规则和不同人数情景下的结果，
不能只输出一个权重数字。

## 待验证参数

下面这些内容尚未由经验充分确定，不能在下一次实现时擅自写死：

- 小班课四个竞争区间各自对应的中选线范围。
- 大班课“超额 20–30 人”时，中选线随容量 100、150、200 是否不同。
- `r=1.5` 的门槛是否应随课程类型移动，以及是否存在 1.4–1.6 的过渡带。
- 小班课达到双倍容量时，90–105 是否同样是主要可行区间。
- 当前人数是否包含仅报名但未投入有效权重的学生。
- 截止前撤回、换课和新增人数的典型速度。
- 同权重的真实处理规则。

获得真实数据后，应按“容量类型 × 需求容量比 × 绝对超额人数 × 距截止时间”分桶，统计
最终中选线，而不是只拟合整体准确率。至少应报告：

- 中选线中位数和 10%/90% 分位数。
- 各投权区间的实际中选频率。
- 对人数和容量的单调性违例。
- 稳健、均衡、进取方案的历史回测效用。

样本单位必须是“课程轮次”。同一课程轮次的多个快照是时间序列，不能当作多个独立
终局样本。如果接口看不到完整 `T`，仍可利用区间删失证据：

- 投权 `b` 成功，说明 `T` 通常不高于 `b`，同权情况需单独标记。
- 投权 `b` 失败，说明 `T` 通常不低于 `b`，同样需要考虑平票规则。

模型比较必须使用跨课程或跨学期留出，至少比较校准误差（Brier score 或 log loss）、
课程排序质量和中选线区间覆盖率，不能只判断推荐结果是否“看起来符合经验”。应同时
保留反例和无效结论。

真实学号、姓名、Cookie、个人完整投权和原始接口响应不得进入仓库。测试和文档只使用
匿名聚合、充分脱敏或合成数据。

## 当前实现与下一版的差异

| 边界 | 内容 |
|---|---|
| 当前已实现 | 完整市场 `mu`、`rho` 指数代理、三个人数情景、整数动态规划、无状态 API |
| 待验证后实现 | 容量分型、绝对超额、时间维度、90–105 门槛和隐含中选线分布 |
| 暂不承诺 | 真实中选概率、真实终局中选线、学校平票规则和自动提交投权 |

当前 `course-selection-contest-v1` 已实现：

- 完整市场输入、默认 105/5/1 制度参数。
- 参考项目改进后的连续指数竞争函数。
- 乐观、基准、悲观人数情景。
- 稳健、均衡、进取三套整数动态规划方案。
- 无状态 API、输入规模限制、禁止响应缓存和无远端写入边界。

当前实现**尚未实现**：

- 小班课、过渡课和大班课容量分型。
- 大班课 `r>=1.5` 时 90–105 的中选线门槛。
- 基于绝对超额 20–30 人的可博弈区。
- 隐含中选线分布和基于历史数据的校准。

在这些假设得到进一步确认前，代码保持不变；不能修改文档中的“当前实现”描述来冒充
功能已经完成。

## API 与数据边界

当前 API 为：

```text
POST /api/course-selection/optimize
```

请求必须携带完整课程市场、目标课程和相对效用。接口完全无状态，不写缓存、数据库或
本地方案文件，不调用 `NEUAuthClient`，也不发出任何教务请求。未来新版接口通过
`CourseSelectionProvider` 标准化数据，模型层仍保持纯计算。

课程池、个人优先级和完整请求体不得写入日志；响应使用 `Cache-Control: no-store`。
当前模型内中选率仍是未校准代理，`market_confidence` 为
`uncalibrated_reference_proxy`。
