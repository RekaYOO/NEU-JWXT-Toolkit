# 成绩追踪

成绩追踪会复用工具箱现有的教务登录和成绩查询能力，按设定间隔获取成绩、与上一份快照比较，并在新增课程成绩或已有成绩被修改时发送邮件。它不维护第二套学号、密码或 WebVPN 登录流程。

追踪没有独立的“直连/WebVPN”开关，而是严格复用当前登录客户端：

- 校内直连账密登录、CAS Cookie 恢复后，追踪继续使用直连请求。
- WebVPN 账密及短信验证完成后，追踪继续使用同一个 WebVPN Session。
- 页面二维码登录完成后，追踪继续使用同一个 WebVPN Session。
- 页面二维码或短信流程尚未完成时，追踪不会清除或覆盖该流程；若后台检查发现必须由用户交互，
  会按“重新登录地址”配置发送恢复链接或手动登录通知。
- 后台已用保存账密进入短信挑战时，一次性恢复页会直接续接该 Session，不再要求重复扫码。
- 没有保存账密、尚未完成第一步 CAS 登录时，一次性恢复页先提供微信扫码重新登录；若学校继续
  要求二次认证，再在同一页面填写图形验证码和短信验证码。

## 配置方法

1. 登录工具箱，在导航中进入“成绩追踪”。
2. 设置每日检查时段和检查间隔；新配置默认每 30 分钟检查一次。
3. 填写 SMTP 服务器、端口、安全方式、用户名、密码或授权码，以及发件和接收地址。
4. 可在保存配置后发送测试邮件，单独验证 SMTP 设置。
5. 页面顶部开关会立即开启或关闭追踪，无需再次点击“保存配置”；开启时使用已经保存的
   配置，同步当前成绩，并自动发送一封初始邮件。
6. “立即检查”用于主动刷新，开启时的初始同步不需要再手动触发。

启用时必须填写 SMTP 服务器、发件地址和接收地址。填写 SMTP 用户名时也必须提供密码或授权码。密码输入框留空并保存时会保留已经存储的密码。
检查间隔不得短于五分钟。一次性恢复页面令牌在登录成功前有效；其中单次二维码和短信 Flow
仍按统一认证服务的短时有效期执行，过期后可在同一页面重新开始。

建议使用邮箱提供的 SMTP 授权码，不要直接使用邮箱主密码。配置页面和 API 都不会回传已保存的密码。

## 通知规则

- 每次从关闭切换为开启，都会立即安排一次初始同步并发送当前成绩邮件；即使成绩 revision
  与上次关闭前相同，也会为这次开启生成一封新的初始邮件。重复提交“已开启”状态不会重发。
- 初始同步不受每日检查时段限制；如果教务登录已失效，会先进入既有的登录恢复流程，恢复后
  再发送初始成绩邮件。
- 后续出现新课程成绩，或成绩、绩点、学分、课程名称发生变化时发送更新邮件。
- 首次建立基线和首次同步邮件不查询分项成绩。后续新增课程，或既有课程的最终成绩/绩点
  变化时，通知发送前按课程串行查询分项；其他字段变化、删除课程和仅总 GPA 变化不查详情。
- 分项名称和数量完全按教务响应动态展示。查询无数据时邮件注明暂无分项，查询失败也不阻断
  总成绩通知；有效分项同时写入与总成绩分离的单科缓存。
- 正常成绩变化通知按 revision 去重；用户明确关闭后再次开启产生的初始邮件不受该去重限制。
- 邮件临时发送失败时进入本地待发送队列，由后台继续重试；本次开启的初始邮件意图会保留到
  SMTP 实际发送成功或用户主动关闭追踪，不会因保存配置、退出登录或切换账号而误判为完成。
- 配置“重新登录地址”后，邮件会发送形如 `/grade-tracking/recovery/<随机令牌>` 的一次性页面，而不是普通站点首页。Linux 服务建议填写反向代理后的 HTTPS 独立子域名。
- 邮件生成时不会创建新的微信扫码二维码，也不会开始轮询。若后台保存账密恢复已经进入短信
  挑战，页面直接显示该 Session 的实时图形验证码；否则收件人打开页面后才创建二维码重新登录。
- 用户手动填写图形验证码并点击“获取验证码”后才发送短信，再提交短信验证码完成登录。后台
  不会自动识别图形验证码或自动发送短信。
- 单次二维码或短信 Flow 超时后，一次性网页链接仍然有效，可以在原页面重新开始；只有成功建立教务会话后，网页令牌才立即失效。
- 一次性网页令牌可访问必要的恢复接口，不要求先输入 Linux 站点访问密码；其他业务接口仍受访问密码保护。服务器访问日志会隐藏令牌路径。
- 未配置重新登录地址时，不再向邮件嵌入无法继续短信认证的二维码。系统只发送一次“登录已失效”
  通知，提醒用户重新进入工具箱手动登录；同一次失效期间不会按每个检查周期重复发送。
- 手动登录或一次性页面恢复成功后会清除本次失效通知标记，立即唤醒成绩追踪；以后再次失效时才发送新通知。
- 配置重新登录地址的邮件会根据当前状态说明“直接完成短信验证”或“先重新扫码登录”，并提醒链接不可转发。

## 不同运行方式

| 运行方式 | 追踪持续条件 |
|---|---|
| 源码开发 | `start_all.py` 对应的后端进程保持运行 |
| Windows 本地版 | 本地服务保持运行；关闭浏览器不影响，从托盘或页面点击“退出程序”会停止追踪 |
| Linux 服务版 | systemd 服务正常运行；关闭客户端页面不影响 |

追踪不会绕过东北大学的登录有效期。WebVPN 或教务会话过期后，需要用户重新打开工具箱并完成登录，下一轮检查会自动恢复。

## 本地文件与安全

成绩追踪文件跟随当前运行模式的数据目录：

- `grade_tracking_config.json`：检查和 SMTP 配置
- `grade_tracking_snapshot.json`：最近一次成绩快照
- `grade_tracking_state.json`：检查时间、状态和错误
- `grade_tracking_outbox.json`：尚未成功发送的通知

Linux 下目录和文件由服务用户持有，并使用 `0700/0600` 权限。Windows 下文件位于当前用户的本地应用数据目录。以上文件以及源码模式的 `data/` 都不得提交到 Git。

清理普通业务数据时会保留追踪配置，但快照、状态和待发送通知会被删除。删除快照后，下一次检查会被视为首次同步；如果本次开启的初始邮件尚未发送成功，其待发送意图也会保留，并在重新登录后根据新账号的当前成绩重建邮件，避免发送旧账号内容。

## API

```text
GET  /api/grade-tracking/config
PUT  /api/grade-tracking/config
PATCH /api/grade-tracking/enabled
GET  /api/grade-tracking/status
POST /api/grade-tracking/check
POST /api/grade-tracking/test-email
GET  /api/grade-tracking/recovery/{token}/status
POST /api/grade-tracking/recovery/{token}/start
GET  /api/grade-tracking/recovery/{token}/poll
POST /api/grade-tracking/recovery/{token}/captcha/refresh
POST /api/grade-tracking/recovery/{token}/sms/send
POST /api/grade-tracking/recovery/{token}/sms/verify
POST /api/grade-tracking/recovery/{token}/cancel
```

`PUT /config` 只保存检查策略和 SMTP 配置；为兼容旧页面而接收到的 `enabled` 和
`notify_initial` 字段会被忽略。开关状态只能通过 `PATCH /enabled` 修改，避免配置保存
覆盖另一个页面或请求刚完成的开关操作。

Linux server 模式下，配置、状态、检查和测试邮件接口与其他业务接口一样受网站访问密码保护。
全部 `recovery` 接口以高强度随机令牌自身作为授权，只能操作该令牌绑定的内存候选 Session；
验证码、Cookie、二维码 UUID 和完整回调地址均不持久化。SMTP 密码只允许写入，不会通过配置接口返回。
