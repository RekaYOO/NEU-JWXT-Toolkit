# 成绩追踪

成绩追踪会复用工具箱现有的教务登录和成绩查询能力，按设定间隔获取成绩、与上一份快照比较，并在新增课程成绩或已有成绩被修改时发送邮件。它不维护第二套学号、密码或 WebVPN 登录流程。

追踪没有独立的“直连/WebVPN”开关，而是严格复用当前登录客户端：

- 校内直连账密登录、CAS Cookie 恢复后，追踪继续使用直连请求。
- WebVPN 账密及短信验证完成后，追踪继续使用同一个 WebVPN Session。
- 页面二维码登录完成后，追踪继续使用同一个 WebVPN Session。
- 页面二维码或短信流程尚未完成时，追踪不会清除或覆盖该流程，也不会同时发送邮件二维码。
- 没有可恢复会话且未配置站点登录地址时，邮件一次性链接会新建 WebVPN 微信扫码会话；确认成功后写回全局认证客户端。

## 配置方法

1. 登录工具箱，在导航中进入“成绩追踪”。
2. 设置每日检查时段和检查间隔；新配置默认每 30 分钟检查一次。
3. 填写 SMTP 服务器、端口、安全方式、用户名、密码或授权码，以及发件和接收地址。
4. 保存配置后发送测试邮件。
5. 页面顶部开关会立即开启或关闭追踪，无需再次点击“保存配置”；开启时使用已经保存的配置。
6. 可点击“立即检查”建立初始快照，不必等待下一轮调度。

启用时必须填写 SMTP 服务器、发件地址和接收地址。填写 SMTP 用户名时也必须提供密码或授权码。密码输入框留空并保存时会保留已经存储的密码。
检查间隔不得短于五分钟，与一次性微信扫码认证链接的最长有效期一致。

建议使用邮箱提供的 SMTP 授权码，不要直接使用邮箱主密码。配置页面和 API 都不会回传已保存的密码。

## 通知规则

- 首次成功检查建立基线；开启“首次同步后发送通知”时会发送确认邮件。
- 后续出现新课程成绩，或成绩、绩点、学分、课程名称发生变化时发送更新邮件。
- 首次建立基线和首次同步邮件不查询分项成绩。后续新增课程，或既有课程的最终成绩/绩点
  变化时，通知发送前按课程串行查询分项；其他字段变化、删除课程和仅总 GPA 变化不查详情。
- 分项名称和数量完全按教务响应动态展示。查询无数据时邮件注明暂无分项，查询失败也不阻断
  总成绩通知；有效分项同时写入与总成绩分离的单科缓存。
- 同一份成绩快照不会重复通知。
- 邮件临时发送失败时进入本地待发送队列，由后台继续重试。
- 配置“重新登录地址”后，邮件会发送形如 `/grade-tracking/recovery/<随机令牌>` 的一次性页面，而不是普通站点首页。Linux 服务建议填写反向代理后的 HTTPS 独立子域名。
- 邮件生成时不会创建微信扫码二维码，也不会开始轮询。收件人打开一次性页面后，服务器才创建二维码并开始最长五分钟的状态轮询。
- 单次二维码超时后，一次性网页链接仍然有效，可以在原页面重新生成二维码；只有成功建立教务会话后，网页令牌才立即失效。
- 一次性网页令牌可访问必要的恢复接口，不要求先输入 Linux 站点访问密码；其他业务接口仍受访问密码保护。服务器访问日志会隐藏令牌路径。
- 未配置重新登录地址时，每个检查周期会创建一个独立的微信扫码认证链接并发送邮件。后台只轮询五分钟；确认成功后继续本轮成绩查询。
- 五分钟内未确认时，本次认证链接立即作废，不会进入邮件重试队列。程序等到下一次既定检查周期，再生成和发送新的链接。
- 一次性认证邮件会明确提示有效期以及超时后需要等待下一轮邮件，旧邮件中的链接不能重复使用。

## 不同运行方式

| 运行方式 | 追踪持续条件 |
|---|---|
| 源码开发 | `start_all.py` 对应的后端进程保持运行 |
| Windows 本地版 | 本地服务保持运行；关闭浏览器不影响，点击“退出本地服务”会停止追踪 |
| Linux 服务版 | systemd 服务正常运行；关闭客户端页面不影响 |

追踪不会绕过东北大学的登录有效期。WebVPN 或教务会话过期后，需要用户重新打开工具箱并完成登录，下一轮检查会自动恢复。

## 本地文件与安全

成绩追踪文件跟随当前运行模式的数据目录：

- `grade_tracking_config.json`：检查和 SMTP 配置
- `grade_tracking_snapshot.json`：最近一次成绩快照
- `grade_tracking_state.json`：检查时间、状态和错误
- `grade_tracking_outbox.json`：尚未成功发送的通知

Linux 下目录和文件由服务用户持有，并使用 `0700/0600` 权限。Windows 下文件位于当前用户的本地应用数据目录。以上文件以及源码模式的 `data/` 都不得提交到 Git。

清理普通业务数据时会保留追踪配置，但快照、状态和待发送通知会被删除。删除快照后，下一次检查会被视为首次同步。

## API

```text
GET  /api/grade-tracking/config
PUT  /api/grade-tracking/config
PATCH /api/grade-tracking/enabled
GET  /api/grade-tracking/status
POST /api/grade-tracking/check
POST /api/grade-tracking/test-email
GET  /api/grade-tracking/recovery/{token}/status
POST /api/grade-tracking/recovery/{token}/start
GET  /api/grade-tracking/recovery/{token}/poll
```

Linux server 模式下，配置、状态、检查和测试邮件接口与其他业务接口一样受网站访问密码保护。三个 `recovery` 接口以高强度随机令牌自身作为授权，只开放二维码恢复所需能力。SMTP 密码只允许写入，不会通过配置接口返回。
