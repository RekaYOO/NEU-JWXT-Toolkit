# 成绩明细

成绩明细页汇总当前账号全部学期成绩，并把筛选、统计、分项成绩和 GPA 模拟放在同一条
数据链路中。页面对应 `/scores`，在线和离线展示复用同一响应模型。

## 页面操作

- 按课程名称、代码、学期、课程性质、考核方式、成绩分制、状态、成绩、绩点和学分筛选。
- 点击列标题排序；“列设置”保存当前浏览器的显示列和顺序。
- “列设置”旁的“绩点计算”可选“2024级及以前”“2025级及以后”，手机端同样可达。
  默认按学号前四位选择，2025 及以后使用新策略；手动设置按账号保存在后端，支持恢复年级默认。
- 顶部总学分、课程数和平均绩点随当前筛选结果变化。平均绩点按有效课程的
  `绩点 × 学分 / 学分合计` 计算，不冒充官方总绩点。
- 点击课程成绩或绩点打开详情。页面只读取该课程已有的分项缓存，不因打开详情临时访问
  教务系统；没有缓存时可触发总成绩刷新，由后端继续补全。
- 点击“GPA 模拟”把当前真实成绩载入模拟器。详细规则见
  [GPA 模拟器](GPA模拟器.md)。

手机端使用课程卡和“筛选与排序”抽屉，但筛选字段、统计口径、分项详情和 GPA 入口与桌面
端一致。

## 本地优先和刷新

页面使用共享资源 `scores`：

1. 打开时先读取当前账号的完整本地快照。
2. 缓存过期或用户刷新时，通过后台任务读取官方成绩。
3. 只有语义内容变化才更新 revision，并让依赖成绩的培养计划失效。
4. 后台失败时保留旧快照，并显示数据时间和错误状态。

刷新不是无条件阻塞重载。多个页面同时请求同一资源时由缓存协调器合并为一次远端刷新。
离线模式只读取缓存，不启动远端任务。

分项成绩使用独立的 `score-details` 资源，按课程代码与学期保存。后端每次成功取得总成绩后
检查课程详情缓存，只为缺失、空白或与当前总成绩不一致的课程排队补全；已有有效缓存不会重复
访问教务系统。补全任务低优先级逐科执行，不阻塞总成绩返回，失败遵守退避并保留旧详情。
登录恢复且总成绩缓存仍新鲜时也会检查缺项，因此前端只负责读取缓存和触发“刷新成绩”。

## 数据口径

本地平均绩点、筛选后的平均绩点、学期 GPA、GPA 模拟和成绩追踪通知的本地计算共用策略：

- 旧策略：所有有效非负绩点、正学分课程计入，包括 0 绩点。
- 新策略：在旧策略基础上，排除培养计划“通识类 → 通识选修类”全部后代课程，以及“两级制”
  课程；从分子 `Σ(绩点×学分)` 和分母 `Σ学分` 同时排除。
- 分类来自培养计划树，分制来自单科大纲缓存，不把普通选修或通识必修误当通识选修。
- 只改变本地绩点计算与贡献值，不隐藏课程、不更改总学分/通过状态、不覆盖教务返回的官方 GPA。
- 新策略的分类/分制尚未缓存时会提示结果暂供参考；后端通过现有共享缓存任务补全，
  读取设置本身不联网。离线使用同一保存值，只读不可修改。回到页面时重新读取后端设置。

后端 `backend/core/academic/api.py` 负责官方字段解析；HTTP 展示模型由
`backend/app/presenters.py` 统一生成。前端不应重新推断成绩是否通过或自行重算官方总绩点。

默认可见列为课程名称、成绩、绩点、学分、学期、课程性质、考核方式和状态。课程代码及
其他字段可以在列设置中开启。新增默认列不会覆盖已有用户的浏览器设置。

## API

| 接口 | 用途 |
|---|---|
| `GET /api/scores/cache` | 只读当前成绩缓存 |
| `GET /api/scores` | 兼容的在线成绩读取 |
| `POST /api/scores/refresh` | 提交共享资源刷新任务 |
| `GET /api/cache/jobs/{job_id}` | 查询后台刷新状态 |
| `GET /api/scores/details/cache` | 读取单科分项缓存 |
| `POST /api/scores/details/query` | 兼容旧客户端的单科刷新入口；当前页面不调用 |
| `GET /api/columns/default` | 默认列定义 |
| `GET /api/gpa-policy` | 缓存只读的当前策略、默认值及分类/分制依据 |
| `PUT /api/gpa-policy` | 保存账号策略；`mode=null` 恢复年级默认 |
| `GET /api/offline/gpa-policy` | 未登录时只读本地账号策略 |

## 边界

- 本地数据用于快速查看，最终成绩以官方系统为准。
- 分项成绩是否可见由官方当前状态决定；没有返回不表示课程没有考核组成。
- 分项自动补全受详情接口的节流和熔断保护；教务异常不会阻塞已有总成绩或清除旧分项缓存。
- 页面筛选不会修改缓存，也不会影响成绩追踪的完整快照比较。
- 真实成绩更新时，已打开的 GPA 模拟器只自动协调未修改课程；用户已编辑项需要确认处理。
