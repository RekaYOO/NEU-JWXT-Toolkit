# 查询课表

查询课表页对应 `/timetable`，把官方 `kbapp` 的“我的课表、班级课表、教师课表、教室课表”
合并到一个界面。四种模式使用同一会议时间模型和冲突引擎。

## 使用方式

1. 默认进入“我的课表”。页面识别官方当前学期和教学周；假期或当前周无课时会检查紧邻
   下一学期，用户仍可手动选择学期。
2. 班级、教师和教室模式先搜索目标，再选择校区和筛选条件。
3. 在周课表与学期课表之间切换。周课表按周日到周六展示。
4. 点击课程查看完整名称、教师/班级、周次、节次、地点和类型。
5. 非个人课表可与“我的课表”比较冲突。

桌面端使用节次轴与七天课表；同一时段多门课程以可切换的堆叠卡片展示，不把课程折成
“另 N 项”而隐藏主要信息。

### 手机端视图

手机端保留两种互补的阅读方式，二者使用同一份课表数据、周次和课程详情：

- 默认视图按星期显示纵向课程卡，地点后直接显示教师姓名。周课表左右滑动时每次切换一天；
  周六向后滑到周日时同步进入下一教学周，反向操作同理。
- “使用缩略视图”在一屏宽度内显示周日到周六七列。课程块只显示课程名和完整教室地点，
  不显示教师、课程性质、考核方式或课程类型；点击课程仍打开同一完整详情。
- 周课表缩略视图左右滑动时每次切换一个教学周。学期课表缩略视图展示全学期安排，
  不响应隐藏的周次切换手势。
- 周课表首次完成可用数据渲染后定位到“第 N 周”选择栏；后台核验、切换星期或课程数量变化
  不再次强制滚动。学期课表首次定位到星期选择栏。

页面顶部的课情摘要默认收起设置区：正在上课时显示“当前”，当天稍后有课时显示“下节”，
当天课程结束后显示明日第一节及开课时间，今明两天均无后续课程时显示“今明两天课程结束”。
展开后显示对应课程的时间、地点和教师，并提供“打开时默认课表”“使用缩略视图”和
“周课表 / 学期课表”设置；两个开关统一放在各自行右侧。

## 时间和冲突口径

每个课次规范化为学期、星期、周次集合、起止节次、教师、校区和地点。冲突必须同时满足：

- 同一学期；
- 同一星期；
- 周次集合相交；
- 节次范围重叠；
- 不是同一课程自身的重复记录。

时间未知不会被当作“无冲突”。跨校区是独立提示，不等同于时间冲突，也不会把课程名称
标红。分段课程按每个课次分别参与判断，详情同时展示双方完整安排和实际重叠周次。

统一规则位于 `backend/core/scheduling/`；课表页、选课工作台和方案预览必须复用该领域，
不能各自用显示文本猜测冲突。

### 节次时间解析

课表节次接口有时只返回“第一节至第十二节”而不返回具体时间。前端在
`frontend/src/utils/timetableSections.js` 内置版本化作息 `neu-campus-schedule-v1`：

| 节次 | 南湖 / 东校区 / 网络区 | 浑南校区 |
|---|---|---|
| 第 1 节 | 08:00–08:45 | 08:30–09:15 |
| 第 2 节 | 08:55–09:40 | 09:25–10:10 |
| 第 3 节 | 10:00–10:45 | 10:30–11:15 |
| 第 4 节 | 10:55–11:40 | 11:25–12:10 |
| 第 5 节 | 14:00–14:45 | 14:00–14:45 |
| 第 6 节 | 14:55–15:40 | 14:55–15:40 |
| 第 7 节 | 16:00–16:45 | 16:00–16:45 |
| 第 8 节 | 16:55–17:40 | 16:55–17:40 |
| 第 9 节 | 18:30–19:15 | 18:30–19:15 |
| 第 10 节 | 19:25–20:10 | 19:25–20:10 |
| 第 11 节 | 20:20–21:05 | 20:20–21:05 |
| 第 12 节 | 21:15–22:00 | 21:15–22:00 |

每个起止时间字段独立按以下顺序补全：

1. 官方节次接口返回的明确时间；
2. 当前课次携带的官方起止时间，仅在 45 分钟小节、课间间隔、上午/下午/晚间边界和课程
   结束时间能互相验证，且同校区同节次不存在矛盾样本时采用；
3. 上表内置校区作息；
4. 校区仍无法识别时保留为空并显示“待定”，不猜测为南湖或浑南。

名称识别支持“南湖/南湖校区”“浑南/浑南校区”“东校区”“网络区/网络校区”；当前课表与
JWXK 已确认的 `00=南湖校区`、`01=浑南校区`仅作为名称缺失时的辅助映射，未知代码不推断。
“全部校区”下，时间完全相同的校区合并为一条时间轴；浑南与其他校区上午时间同时出现时，
桌面显示完整校区名，手机缩略轴显示“浑/南/东/网”等短标签。下午和晚间相同时间仍合并显示。

内置时间只补全显示轴，不写回服务器缓存或 IndexedDB，不参与冲突判断、选课预检和远端操作；
将来官方返回不同时间时会按上述优先级自然覆盖内置值。浏览器旧快照中的空节次也能直接补全。

### 共享七日网格

桌面课表、手机七日缩略课表和选课工作台共用同一七日网格与课程定位算法，仅调整信息密度。
桌面端同一时段课程使用可切换的堆叠卡片，手机缩略视图则使用横向并排车道，确保触屏窄视口下
每门课程始终有可见、可点击的入口；缩略课程块完整换行显示教室地点，并按内容扩展所占节次行。
手机默认的按日课程卡片仍作为独立的移动阅读方式保留。
“全部校区”同时出现不同作息时，节次轴分别标出校区时间，不选择其中一个作为所有课程的时间。

共享范围包括节次偏移、课程跨度、星期列、重叠/冲突状态、当前课程高亮、详情点击和无障碍名称。
展示策略只决定字段、密度、行高和重叠布局：桌面普通模式显示完整信息并使用课程簇；手机缩略
模式只显示课程名与地点并使用并排车道；选课紧凑模式只显示课程名和选择状态。地点完整显示所需
高度按 320px 窄屏和实际并排车道数估算，只扩展课程覆盖的节次，不统一放大全部行。

## 我的课表缓存

`personal-timetable` 是账号级共享资源：

- 当前学期和紧邻下一学期按 `term:<学期>` 保存，默认时效五分钟；
- 页面先显示本地快照，再按时效后台更新；
- 学期末无课周可以预热下一学期；
- 历史学期、班级、教师和教室课表按需实时查询，不写入个人课表缓存；
- 后台失败保留旧快照，并显示数据时间。

### 浏览器首屏缓存

在服务端缓存之外，在线登录后前端会把当前/下一学期的官方个人课表快照写入专用
IndexedDB。打开页面时按“React 内存 → 浏览器快照 → 服务器 `cache.db` → 官方刷新”的顺序
渐进显示；只要已有快照就不会重新显示整页骨架。浏览器快照只保存规范化的官方课表，不保存
选课方案叠加、临时预览或冲突结果，并按账号命名空间隔离。跨标签页通过 `BroadcastChannel`
通知读取新 revision。

服务器提供 `GET /api/timetable/bootstrap`（只读缓存，不等待教务系统）和
`POST /api/timetable/sync`（只提交后台刷新任务）。后台结果到达后先比较规范化课表内容：仅缓存时间或
revision 变化时只更新状态，课程内容变化时由用户确认是否应用。应用时保留当前学期、校区、
周次、滚动位置和详情状态；刷新失败继续使用旧快照。系统设置中的“清除本机课表缓存”只
删除浏览器 IndexedDB，不影响服务器缓存。显式离线模式的能力范围不因此扩大。

### 认证恢复与首屏

打开 `/timetable` 时，如果浏览器存在最近一次在线认证账号对应的课表快照，应用会先进入
“课表恢复态”：立即显示本机课表，同时在后台并行确认网站访问权限、教务登录和服务器缓存。
恢复态只允许查看课表，不能执行刷新、选课、退课、投权或其他需要远端身份的操作；切换到其他
页面时回到登录门禁，不挂载依赖在线身份的成绩、头像、培养计划等资源。认证成功且账号一致后
自动升级为正常在线态，并按服务器缓存、官方同步结果逐步核验；认证失败会明确显示简短登录失效
提示及重登入口，而不是泛化为课表服务错误。桌面端提示位于查询控件下方的标准系统提示区，手机端
仍放在课表内容下方，不占用移动端首屏和日期选择栏聚焦区域；两端都不会清空已经显示的快照。
浏览器只保存不可逆的账号命名空间标识，不保存密码、Cookie 或 Token；
主动退出后快照仍可保留，但手动退出标记会阻止未重新登录时的课表恢复态展示。

官方课表可能包含预选/投权尚未形成最终结果的课程。后端保留可识别的官方状态，前端用蓝色
状态区分待结果课程；已确认课程使用普通已选样式。状态无法确认时不根据颜色或权重值猜测。

## API

| 接口 | 用途 |
|---|---|
| `GET /api/timetable/terms` | 学期、当前周和校区上下文 |
| `GET /api/timetable/personal` | 我的课表，本地优先 |
| `GET /api/timetable/bootstrap` | 只读服务器课表缓存启动索引，不建立远端会话 |
| `POST /api/timetable/sync` | 提交课表学期索引及当前/下一学期的后台同步任务 |
| `POST /api/timetable/context` | 指定模式的上下文与筛选字典 |
| `POST /api/timetable/targets/search` | 搜索班级、教师或教室 |
| `POST /api/timetable/schedule` | 查询指定目标课表 |
| `POST /api/schedule/conflicts/check` | 批量冲突检查 |

领域适配位于 `backend/core/timetable/api.py`，路由位于
`backend/app/routers/timetable.py`，页面位于 `frontend/src/pages/TimetablePage.js`。

## 边界与测试

- 班级、教师和教室结果以官方实时数据为准，不保证离线可用。
- 缺少可靠周次、节次或地点时显示待确认，不把整段官方安排复制为每个课次地点。
- 课表颜色仅表达状态，不参与冲突计算。
- 自动测试覆盖周次解析、同周/错周冲突、跨校区、缓存、四类模式、四套校区作息、时间覆盖
  优先级、全部校区时间合并、手机并排车道、长地点完整显示和移动端入口；见
  `backend/tests/test_timetable.py`、`backend/tests/test_scheduling.py` 和
  `frontend/src/pages/TimetablePage.test.js`、`frontend/src/utils/timetableSections.test.js`。
