# Android 安装与运行

> 当前状态：两个 APK 已构建并通过 API 35 模拟器功能门禁，仍待真机和正式签名发行验收。
> 以下流程不代表 GitHub Release 已经提供正式 APK；调试包仅用于测试。

目标是在同一个 GitHub Release 提供两个 Android 7.0（API 24）及以上可安装包，正式包仅支持
`arm64-v8a`：

| 安装包 | 包名 | 用途 |
|---|---|---|
| `android-client-arm64.apk` | `io.github.rekayoo.neujwxt.client` | 内置前端，连接自己部署的 Linux 服务端 |
| `android-local-arm64.apk` | `io.github.rekayoo.neujwxt.local` | 内置前端、Python 3.13 和完整 FastAPI 后端，数据留在手机内部存储 |

两个 APK 使用项目维护者保管的同一套固定自签名密钥，不接入应用商店。Android 要求 APK
必须签名后才能安装；这里的自签名用于确认后续覆盖安装来自同一密钥，不等于应用商店审核。
首次安装时允许系统的“安装未知应用”权限即可，不需要关闭系统安全扫描。下载后应先按
[发行与 CI/CD](../开发/发行与CI.md)校验 SHA-256 和 GitHub artifact attestation。

## 客户端版

首次启动输入 Linux 服务端的 HTTPS 根地址，例如 `https://jwxt.example.com`。地址必须使用
系统信任的证书，不能包含用户名、密码、查询串、片段或子路径；HTTP 和自签名证书会被拒绝。
首次保存或重新检测地址时会检查 `/api/health` 的移动 API 版本。之后启动直接打开 APK 内置页面，
服务端离线不阻止页面加载。静态 JS、CSS 和图片不从
服务端下载，只有相对 `/api/*` 请求由 OkHttp 发往已配置主机。

启动等待页、访问密码页和教务登录页均提供“服务端设置”，不需要先登录旧服务端。
登录后的系统设置也可以更换或重新检测地址、清除加密保存的访问密码 Cookie。
客户端拒绝 API 重定向，Cookie 按 HTTPS origin（含端口）隔离，检测候选服务端时不带 Cookie。
切换服务端会取消旧请求、清理页面会话并重载；IndexedDB 课表/头像缓存按服务端地址分区保留，
不会把另一服务端的离线数据展示在当前服务端中。

## 本地版

本地版不需要配置服务端。应用在随机回环端口启动 FastAPI，并为本次进程生成高强度令牌；
包括健康检查在内的所有本地 API 都必须携带该令牌。应用不申请外部存储权限，并关闭 Android
云备份；业务数据位于应用内部目录，卸载应用会删除这些数据。

本地版复用网页端的认证、教务网络、缓存协调器和页面取数逻辑，不维护第二套业务缓存。
原生桥到本机 FastAPI 的回环请求明确绕过系统 HTTP 代理；Python 到学校的请求仍由共享
`NEUAuthClient` 处理直连和 WebVPN。持久化 Cookie、凭据、`cache.db` 与用户文档都位于内部
数据目录，不放入可被系统淘汰的 Android 临时缓存目录；完整大纲仍是进入页面自动实时查询，
只有考核方式、成绩分制等最小元数据允许保存。

共享后端在直连首次网络失败后返回 WebVPN 建议，不再整轮重试登录直至超过前端期限；
登录表单的网络失败不当作公钥错误重复提交。网站和桌面模式同步采用这项修复。

本地版不显示 SMTP、远程恢复地址或恢复链接。成绩变化、选课结果和任务异常使用独立 Android
通知频道；锁屏只显示概括，点击后进入相应页面。Android 13 及以上必须允许通知才能开启成绩
追踪或自动选课。任一自动任务启用时会显示常驻运行通知，全部关闭后退出前台运行状态。
手机重启后会恢复已启用任务；若系统阻止自动启动，会提示点击恢复。用户手动“强行停止”应用后，
应用遵守 Android 限制，不尝试自行绕过。

Python 运行时和本地 API 令牌属于应用进程。前台服务结束后，同一进程中的页面仍可使用本地后端；
再次启用自动任务时复用该运行时和令牌，不会生成一个无法访问已有后端的新令牌。
通知 outbox 在系统确认展示后才调用业务完成回调；回调失败保留通知以便重试。
写盘失败不会提前修改内存队列，通知入队、删除和确认均可重试。页面资源在后台线程解压，
服务重新创建时重新检查后端健康状态，不仅依赖上次启动留下的地址。

## 下载与安全边界

WebView 只加载 APK 内部页面，不允许远程子资源、子框架、混合内容或文件系统导航；
外部 HTTP/HTTPS 链接交给系统浏览器。原生网络桥拒绝绝对 URL、路径穿越和伪造的 Cookie、
Host、本地会话令牌等特权请求头，服务端 `Set-Cookie` 不返回 JavaScript。
原生请求的连接、读取、写入和总超时统一采用 Axios 传入的有界期限，普通请求仍为 30 秒；
不能额外保留更短的套接字默认超时，否则学校的直连失败提示或登录成功结果可能被提前丢弃。
仅在尚未发送请求的连接建立阶段允许尝试备用地址。非 GET/HEAD 请求体使用 one-shot，
一旦开始发送就不可自动重放，包括响应丢失、`408` 或 `503 + Retry-After: 0` 情况。
GET/HEAD 仍允许在空闲连接失效时重新连接，不把这一行为扩展为业务写操作重试。
不可重放请求每次使用新的、不保留空闲连接的连接池，避免登录页初始化留下的连接在健康检查后
恰好关闭，造成首次点击报网络错误。GET/HEAD 继续复用连接；新连接仍使用相同的证书校验、
CookieJar、代理设置和原生令牌，不通过重发登录或放宽安全规则来恢复连接。
独立连接池在完整读取并关闭响应后才回收，避免 HTTP/2 提前回收引发响应读取失败；
响应清理后只回调一次，HTTPS 回归覆盖连续 100 次新连接请求。

ICS、日志、证明文件、证书 ZIP 直接流式写入私有临时文件，再由系统文件选择器保存。
课程大纲 HTML 等页面生成文件按 64 KiB 分块传输，文件复制不占用界面线程。
头像等需要在页面展示的二进制响应不会被错误替换为空文件占位对象。

## 更新

调试包的包名附加 `.debug`，使用 Runner 调试签名，与未来正式版数据不共享。
不同 Runner 的调试密钥可能不同；不能承诺调试包之间覆盖安装，也不能把卸载重装当作数据迁移。

从后续 Release 下载同一包名的 APK 并直接安装即可覆盖更新，`ANDROID_VERSION_CODE` 保证新版
可识别。固定签名密钥丢失后无法覆盖安装已有应用，因此正式工作流在任一签名 Secret 缺失时
直接失败，不会临时生成新密钥。客户端版和本地版包名不同，可以同时安装，数据互不共享。
