# 快速开始

本文用于从源码运行和参与开发。普通用户应优先使用
[Windows 便携版](部署/Windows本地安装.md)或
[Linux 轻量服务发行版](部署/Linux轻量服务.md)。

## 环境要求

- Python 3.11
- Node.js 20 与 npm
- Git

源码启动使用 `requirements.txt` 和 `frontend/package-lock.json`；发行与 CI 安装
`requirements-build.lock`，它先引用 `requirements.lock` 固定运行依赖，再增加构建与测试工具。

## 一键启动

先安装前端依赖，再在仓库根目录执行：

```bash
cd frontend
npm ci
cd ..
python start_all.py
```

首次运行会创建 `.venv`、安装 `requirements.txt` 中的 Python 依赖，并构建生产前端；
`start_all.py` 不会代替 npm 安装前端依赖。默认模式由 FastAPI
在 `http://localhost:8000` 同时提供页面和 API。前端先构建到 staging 目录，只有
`index.html` 和静态资源完整时才替换旧构建，失败不会清空上一版可用页面。

常用参数：

```bash
python start_all.py --build             # 强制重建前端
python start_all.py --port 8080         # 修改单端口模式端口
python start_all.py --dev               # 后端 8000 + React 开发服务器 3000
python start_all.py --dev -b 8001 -f 3001
```

两种模式均可使用 `Ctrl+C` 停止。脚本启动的子进程会随主进程退出。

## 手动启动

手动启动适合定位依赖、构建或热重载问题。

### 后端

Windows PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m backend.app.main
```

Linux/macOS：

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
./.venv/bin/python -m backend.app.main
```

`development` profile 默认把可写数据放在仓库根目录的 `data/`。API 文档仅在开发 profile
开放，地址为 `http://localhost:8000/docs`。

### 前端

```bash
cd frontend
npm ci
npm start             # Windows
npm run start:unix    # Linux/macOS
```

开发服务器通过 `frontend/package.json` 的 proxy 把 API 请求转发到
`http://localhost:8000`。生产构建使用同源 API：

```bash
npm run build
```

## 首次使用

1. 打开页面，选择校内直连或 WebVPN。
2. 完成账号密码、二维码或短信流程；具体支持范围见
   [WebVPN 校外访问](功能/WebVPN校外访问.md)。
3. 登录后从侧栏进入功能。页面会按各资源的缓存策略先显示本地数据，再决定是否后台刷新。
4. 登录页只有在当前账号存在允许离线读取的缓存时才提供离线入口。

“记住密码”会把恢复登录所需凭据保存在应用数据目录。Cookie、凭据、日志和缓存均为敏感
信息，不应复制到共享目录或提交到仓库。

## 数据目录

| 运行 profile | 默认数据目录 |
|---|---|
| 源码开发 `development` | `<仓库>/data` |
| Windows 发行版 `desktop` | `%LOCALAPPDATA%\NEU-JWXT-Toolkit\data` |
| Linux 发行版 `server` | `/var/lib/neu-jwxt-toolkit` |

环境变量 `NEU_JWXT_DATA_DIR` 可以覆盖默认位置。数据分类、文件权限和清理边界见
[数据存储](开发/数据存储.md)。

## 验证改动

后端：

```bash
python -m pytest backend/tests
python -m compileall -q backend launchers
```

前端：

```bash
cd frontend
npm ci
npm test
npm run build
```

生产运行、访问网关和发行包还需执行根目录集成测试：

```bash
python -m pytest tests
```

完整影响面和验证顺序见[开发接手与变更规范](开发/开发接手与变更规范.md)，发行包构建见
[发行与 CI/CD](开发/发行与CI.md)。

## 常见问题

- 页面返回“前端静态资源不完整”：执行 `python start_all.py --build`。
- 3000 端口页面无法调用 API：确认后端正在 8000 端口运行，或使用 `-b` 配合代理配置。
- 校外登录失败：不要反复快速重试，按 [WebVPN 校外访问](功能/WebVPN校外访问.md)核对流程。
- 本地数据没有立即更新：先区分页面正在展示缓存还是远端结果，参见
  [缓存与数据一致性](开发/缓存与数据一致性.md)。
