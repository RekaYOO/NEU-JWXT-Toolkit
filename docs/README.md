## 文档维护规则

- 用户操作以 `frontend/src/features/featureRegistry.js`、页面组件和实际路由为证据。
- API、认证、缓存和持久化规则以对应 schema、router、core 模块及测试为证据。
- `docs/功能/` 下的功能文档描述当前可用行为，面向用户阅读，不混入实现链路、测试清单或开发影响矩阵。
- `docs/开发/功能实现与变更索引.md` 集中记录功能实现链路、容易遗漏的特殊情况、跨层影响面、更新要求和验证入口。
- 功能文档不保存聊天过程、个人工作记录、临时方案或未实现愿望；当前用户可见的特殊行为仍应在功能说明书中写清楚。
- 实现发生变化时，用户可见变化更新对应功能文档；实现入口、联动影响或验证方式变化更新开发索引；两者都变化时分别同步。
- 开发规范负责说明“按什么类型判断影响、先看哪些文档、修改后更新什么”；功能文档负责用户操作，开发索引负责实现与变更。
- 这些内容用于帮助修改时覆盖完整影响面，不用于冻结设计；需求或接口事实变化时，应同步更新实现、测试和相关说明。
- 所有仓库内链接使用相对路径。真实账号、Cookie、token、业务响应和个人数据不得进入文档。
